# 影剧工坊 2.0 · 落地验收单（2026-11-02 周一用）

> 小南备料 · 2026-11-01
> 验收口径：**B —— 帧格视界的人自己操作，做出一条能用的成片**（凡哥 2026-10-29 定）
> 一句话原则：**小李在旁只答不问、不动手**。要靠小李点才算过，这条就算没过。

---

## 一、谁来操作（开场先定，别临场找）
- 帧格视界出 **1–2 人**，用他们自己的账号登录
- 小李只做两件事：站在旁边被问、出问题记下来
- 凡哥只在最后问三句（见第四节），不插手操作

## 二、走哪条链路（只走一条，别贪多）
**登录 → 新建项目 → 选/传素材 → 生成镜头（生图→生视频）→ 剧本生成 → 拼成片 → 导出**

> 走一条完整的就够判。多走几条价值不大，还容易在现场翻车。

## 三、看三样（就这三样，别加）
1. **能不能自己点完**：全程不喊小李过来接手
2. **成片能不能用**：画面不畸形、不违法；音画对得上；时长对了；能导出来能播
3. **要多久**：一条成片从开工到导出，实际耗时多少（记具体数字，别记"还行"）

## 四、判定（当场给结论，不拖）
| 情况 | 结论 |
|---|---|
| 三样全过 | **B 达成** —— 2.0 落地成立，可以对外说"帧格视界能自己出片了" |
| 前两样过、第三条慢 | **C 可用** —— 能出片但效率不够，本月记"落地"，下月定优化目标 |
| 需要小李动手才出得来 | **没过** —— 当场记卡在第几步，当天给下一轮日期 |
| 生成质量不行（画面/音画错） | **没过** —— 见第六节，直接走换 API 这条路，别现场调参 |

## 五、不过的时候怎么收场（不许说"尽快"）
当场只问三句，记成三行字：
1. 卡在第几步？
2. 是谁的问题（产品/配置/机器/素材/人不会用）？
3. 下一轮哪天能看到，具体到日？

## 六、现场必须预备的（今天先跟小李对一遍）
- [ ] 在哪台机器、哪个地址、谁的账号（提前登好，别现场等验证码）
- [ ] 网络：公司 Wi-Fi 还是热点，够不够传素材
- [ ] 演示素材提前传好（原片/参考图/剧本），别现场等上传
- [ ] 生图这一环：**凡哥 10-29 已授权换外部 API** —— 如果现场出现"幻觉/不听指令"，当场记下来，直接说"换 API，报预算"，不在现场调参
- [ ] 整条链路提前录一段屏做兜底：现场真崩了，先放录屏，再看什么时候补
