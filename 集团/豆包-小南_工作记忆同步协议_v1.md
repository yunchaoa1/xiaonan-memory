# 豆包 ↔ 小南 · 工作记忆同步协议 v1

> 用途：把飞书豆包的工作记忆同步给小南（Hermes），并让小南回执，避免两边各记一套。
> 定稿：2026-09-15 · 小南　口径：凡哥

## 一、怎么用（两种方式，推荐方式 A）

**方式 A · 文件直连（推荐，已建好）**
豆包能读本地文件 → 双方共用一个文件：
`D:\Hermes\xiaonan-memory\集团\豆包工作记忆.md`（分 A/B/C 三区）
- 豆包：开工前读 **A 区**（凡哥确认过的最新口径）；有新情况**追加到 B 区**（带日期）；不动 A/C 区
- 小南：开工先读 **B 区** → 把凡哥确认过的并入总控台 → 在 B 区标 `→ 已并入`，结论补进 A 区
- 好处：不用复制粘贴；两边永远看同一份口径；`xiaonan-memory` 走 git，公司/家里两个小南也同步

**方式 B · 复制粘贴（备选）**



1. 凡哥把下面「给豆包的指令」整段粘给豆包（一次即可）。
2. 以后豆包每次回复，末尾都会带一段**《工作记忆同步块》** → 凡哥**整段复制发给小南**。
3. 小南并入总控台后回一张**《小南回执》** → 凡哥可粘回豆包，让它知道已同步（省得它重复问）。

## 二、给豆包的指令（整段复制粘贴）

【以后请固定这么做 · 工作记忆同步】

从现在开始，每次你回复我，都在最后附上一段《工作记忆同步块》，格式严格照下面来，不要改结构、不要加评论：

【工作记忆同步块 v1】
同步时间：YYYY-MM-DD
── 项目状态 ──
· 项目名｜状态（未开始 / 进行中 / 卡住 / 已完成）｜一句话进度｜最近更新日期
── 本轮新增或变更 ──
· [新增/变更] ……
── 已确认决定（只写我明确确认过的）──
· 决定内容（确认人：凡哥｜日期：YYYY-MM-DD）
── 待确认（需要我或技术侧定的）──
· 问题：…… ｜可选答案：A / B
── 卡点与下一步 ──
· 卡点：…… ｜影响：…… ｜下一步：…… ｜期望完成日期：YYYY-MM-DD
── 名词表（新出现的人名 / 项目名 / 术语）──
· 名词 ＝ 解释

三条要求：
1. 只写事实和已确认的决定，不要写你的推测；不确定的放进「待确认」。
2. 每个条目都要带日期。
3. 本轮没有变化就写「本轮无变化」，不要编内容。

## 三、小南收到后怎么处理（规则）

| 豆包块里的字段 | 小南怎么处理 |
|---|---|
| 项目状态 | 更新树形总控台 `dashboard-tree.html`（改 DATA）与 `DASHBOARD.md` |
| 本轮新增或变更 | 只并入**凡哥确认过**的部分；判断为"豆包推测"的一律进「待确认」 |
| 已确认决定 | 按凡哥口径固化进总控台（并标注确认日期） |
| 待确认 | 整理成问题清单问凡哥（普通聊天问，不用提问卡） |
| 卡点与下一步 | 进月度任务台账 + 给 CEO 的一周进展 |
| 名词表 | 并入总控台术语，避免两边叫法不一致 |

**三条铁律**：
1. **总控台只认凡哥确认过的口径** —— 豆包的推测不得直接写进真相源（防止把总控台搞乱）。
2. 每条都带**来源与日期**（豆包 / 凡哥 / 小南，YYYY-MM-DD）。
3. 两边叫法不一致时，**以凡哥口径为准**，并在总控台记一条"口径统一"。

待凡哥确认：……（哪几项还不能入）
与既有口径冲突：……（如有，说明以哪个为准）
