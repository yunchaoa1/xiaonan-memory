# 网关部署步骤（小南执行清单）

> 前置：凡哥给来 **公网 IP + root 密码**。
> 依据：官方 docker-compose.yml（github.com/QuantumNous/new-api）+ 官方文档《渠道管理》《用户管理》《API 令牌》。

---

## 阶段 0 · 上机前准备

- [ ] 确认服务器系统为 Ubuntu 22.04
- [ ] 确认能 SSH 通：`ssh root@<IP>`
- [ ] 把 `deploy/` 整个目录传上去：`scp -r deploy root@<IP>:/opt/company-ai-gateway`

## 阶段 1 · 装 Docker + 起网关

```bash
cd /opt/company-ai-gateway
bash bootstrap.sh
```

脚本会：装 Docker → 生成随机 PG/Redis/Session 密码并写回 compose → 拉起容器 → 等待就绪 → 打印访问地址。

- [ ] 验证：`docker compose ps` 三个容器都 Up
- [ ] 验证：`curl -s http://localhost:3000/api/status` 返回 success

## 阶段 2 · 放行 3000 端口

在**云厂商控制台**（不是服务器里）操作：

- 腾讯云轻量：轻量应用服务器 → 实例 → **防火墙** → 添加规则 → TCP **3000**
- 阿里云轻量：轻量应用服务器 → 实例 → **防火墙** → 添加规则 → TCP **3000**

- [ ] 验证：本机浏览器打开 `http://<公网IP>:3000` 能看到登录页

## 阶段 3 · 首次登录 + 改密码

1. 用 `root` / `123456` 登录
2. ⚠️ **第一件事改管理员密码**（官方 README 明确警告：默认密码必须改）
3. 给系统改个名字（如"公司AI网关"）

## 阶段 4 · 添加 DeepSeek 渠道

依据官方《渠道管理》文档：

1. 左侧导航 **渠道**（或直开 `/console/channel`）
2. 右上角 **添加渠道**
3. 弹窗里：
   - 服务商类型：**DeepSeek**
   - 渠道名称：`DeepSeek-官方`
   - **API Key**：填公司 DeepSeek 账号的 key
   - **模型**：勾选或点「填入默认模型」
4. 高级配置（按需）：
   - **Base URL**：官方直连可留空（默认 `https://api.deepseek.com`）
   - 优先级 / 权重：单渠道填默认
   - **自动禁用**：建议开启（连续失败自动摘除）
5. 提交保存
6. 点该渠道右侧的 **测试**，确认返回成功、响应时间正常

- [ ] 渠道测试通过

> 💡 如果之后一个渠道想放多把 key：用官方**多 Key 模式**（编辑渠道 → 多 Key 管理 → 添加 Key → 轮询模式），一把失败自动跳过。
> 我们 4 人共用一个公司账号，暂时用不上。

## 阶段 5 · 建 4 个用户 + 令牌 + 额度

依据官方《用户管理》文档：

1. 左侧导航 **用户**（或 `/console/user`）
2. 为 4 个人各建一个账号（用户名建议用真名拼音，方便对账）
3. 每个用户可设置：
   - **配额余额**：给一个初始额度（比如每人 50 元等值配额）
   - **分组**：默认组
   - **状态**：启用
4. 令牌（`/console/api-token`）：
   - 每个用户登录自己的账号，建自己的令牌；或管理员代建后分发
   - 令牌名建议 `-<人名>`，方便以后在日志里筛人

- [ ] 4 个账号建好
- [ ] 4 把令牌生成，一一登记（谁是哪把，记在 `04-成员登记表.md`）

## 阶段 6 · 端到端验收（必须实测，不靠猜）

```bash
# 用某个成员的虚拟 key 打网关，而不是打官方
curl http://<公网IP>:3000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-<虚拟key>" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"你好"}]}'
```

- [ ] 返回正常回复
- [ ] 到网关后台 **日志**（`/console/log`）能看到这次调用：谁的令牌、用了多少 token、扣了多少配额
- [ ] 故意填错 key → 报错正常（没漏放）

## 阶段 7 · 交给成员

- [ ] 写 `03-成员接入配置.md`（每人一页纸，见该文件）
- [ ] 逐个成员：改 base_url + 换 key → 当场跑一次 → 确认后台看得见

## 阶段 8 · 加固（建议，可后补）

- [ ] SSH 改密钥登录、关密码登录
- [ ] 3000 端口来源限制到公司出口 IP
- [ ] 配 Nginx + HTTPS（避免 key 明文过网）
- [ ] 备份任务：`tar czf newapi-backup-$(date +%F).tar.gz data/ docker-compose.yml`

## 已知坑（写在前头）

| 坑 | 说明 |
|----|------|
| 3000 打不开 | 90% 是云控制台防火墙没放行，不是网关没起 |
| compose 里密码变成 `__PG_PASS__` | 说明 `bootstrap.sh` 没跑成功，重新跑（已有真密码时会跳过生成） |
| 默认密码没改 | 官方明确警告，公网暴露就是裸奔，必须改 |
| 换了 IP / 重装 | 网关地址变了，4 个人的 Agent 配置要同步改 |
