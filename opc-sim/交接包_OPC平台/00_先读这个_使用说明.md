# OPC 节点 Skill 交接说明（先读这个）

> 这份说明是给搭建 OPC 平台的同事看的。简单讲清楚：**这套东西是什么、里面有什么、怎么用、有哪些规矩**。

---

## 一、这套东西是什么

OPC 是一个"给客户一键生成短剧/短片"的平台。客户的完整链路是：

```
客户一个想法
   ↓
① 写作节点（生成小说/故事）
   ↓
② 改剧本节点（小说 → 标准剧本）
   ↓
③ 资产提取节点（从剧本提取人物/场景/道具清单）
   ↓
④ 主体资产生成节点（画人物定妆照/场景图/道具图）
   ↓
⑤ 分镜节点（剧本 → 分镜卡：每镜拍什么/谁说话/镜头怎么动）
   ↓
⑥ 故事板节点（每镜生成参考图）
   ↓
⑦ 生视频节点（分镜+参考图 → 视频片段）
   ↓
拼接成片
```

**Skill = 给 AI Agent 看的"工艺说明书"**，不是给人读的技术文档。
每个节点配一份 Skill，Agent 读了就会按照固定工艺干活。

**关键认知：**
- Skill 内容 = 长期实测 + 反复纠错沉淀出来的规则（怎么拆镜、怎么画人、怎么翻译提示词……全在里面）
- Agent 不需要人教，读了 Skill 就能按节点干活
- 你搭建 OPC 平台时，把 Skill 作为"每个节点的执行规则"接入你的 Agent 即可

## 三、怎么用

### 第一步：装进你的 Agent
把这 10 个 Skill 文件夹放进 Agent 的 skills 目录（和你在 OPC 里内置 Agent 的方式一致），Agent 就能读到。

### 第二步：按链路跑
每个节点跑法都一样：**喂上游产物 → Agent 按对应 Skill 的规则干活 → 吐唯一产物 → 传给下一节点**。
每个 Skill 文件开头都写了：输入格式、输出格式、必须遵守的规则。

### 第三步：验收
- 文本产物（小说/剧本/分镜）：可以用 `opc-output-inspection` 的方法检查（证据链，不凭感觉）
- 图片产物：**人工看图验收**（人物像不像/场景对不对）
- 视频产物：看效果 + 听声音

## 四、最重要的规矩（血泪沉淀，务必遵守）

这些是无数次实测纠错换来的，违反任何一条都会在产物上翻车：

1. **节点 = 黑盒**：每个节点只做"生成"这一件事。**禁止节点内部自检、自查、重试、筛优选优**。写完直接交付。
2. **检查永远在节点外面**（验收层/平台层做），不在 Skill 里。
3. **节点只读正式上游 + 自己的 Skill**：不接受聊天补充、不接受场外解释、不联网查资料。
4. **一个想法只生成一次**（One-Shot）：不重跑、不修图、不比稿。不满意 = 改 Skill 规则 → 重跑 → 验收，不是手动改图。
5. **发现问题先改 Skill 再重跑**：产物不对 → 一定是规则没写对 → 去 Skill 里找原因改掉。禁止手工补救产物。
6. **写作启动前客户必须选画风**（style_id），没选就返回"请先选择画风"，系统不默认。
7. **画风一旦验收就锁死**：人物长相、服装、场景风格全链路一致，不漂移。
8. **台词与剧本语义一致**：可以改语气词，不能改意思、不能自创。
9. **宫格数 = 切镜数**：一镜内没切机位就一张图；有切镜就按切镜数给关键帧格数。
10. **局部修改是平台的事**：客户想改某一段 → 平台定位影响范围 → 产出新版本 → 交给对应节点按新规则重跑。节点自己不处理"修改请求"。

## 六、怎么迭代（重要工作方式）

1. 拿一个测试剧本全链路跑一遍
2. 产物不对 → **去对应 Skill 找规则漏洞，改掉，重跑**
3. 验收通过 → 规则就固化在 Skill 里，以后永远按这个规则生成
4. Skill 是活的：每发现一个新坑，就补一条规则进去（这就是这套东西越来越准的原因）
