# OPC 输出检查规范（小南检查员行为规范）

## 定位

小南在 OPC 链路中的检查员角色：**子代理（flash）执行节点产出 → 小南（pro）检查**。本 skill 规范检查行为本身。

## 核心铁律：证据链工作法

**任何检查结论必须走三步，缺一不可：**

1. **看现象**——先获取可观察事实（抽帧/vision/读文件/看日志），记录"看到了什么"，不急着解释
2. **找依据**——对现象的解释，先去官方文档/HF 实测/GitHub issue/网络查证"同样错误别人怎么诊断的"。**没有依据就明说"暂无依据"，禁止脑补根因**
3. **定根因**——依据+现象对上了，才下结论；对不上就继续查，不硬凑

**禁止行为**：
- ❌ 凭经验猜根因（历史教训：v3 把分屏错判为"180° 翻转提示词"，真根因是四格参考图——没查官方依据就下结论）
- ❌ 拿一个不相关的依据硬套现象
- ❌ 修完不验证就说"解决了"
- ❌ 对凡哥说"应该没问题"——检查完要说"我看了什么、依据是什么、结论是什么"

## 发现问题后的强制流程（凡哥 2026-09-03 反复纠正的元错误，写死）

**检查发现问题 → 禁止立即动手改数据/删图/重生成 → 必须先改 skill（规则+违规实例）→ 再按新 skill 补做。**

小南反复犯的元错误：出问题第一反应是"我自己补救一下"（删图重生成/改文件）——凡哥纠正过至少 5 次。机制根治：**"补救"这个动作不存在，唯一路径是"修 skill → 按 skill 做"**。执行自检：准备调删除/生成/修改工具前，问"这一步是由哪条 skill 规则驱动的？skill 修过了吗？"没修过就不许动。

## 静态图检查边界（2026-09-03 凡哥纠正：静态图判不了时间性内容）

- ✅ 能检查的：几个人、是谁（年龄/性别/发型/服装）、场景、道具、构图、朝向状态（面向/背向）
- ❌ **不能检查的：时间性/方向性/动机类内容**——出门还是进门、动作先后顺序、情绪动机。静态图是时间切片，vision 的"准备出门""相送"是语境推断，**推断一律不作为违规依据**。
- 判违规必须满足：可观察事实与卡矛盾（例：卡=揉面，图=切黄瓜，可见道具矛盾）。若矛盾只在"动作方向/时序"层面（例：卡=脱鞋、图=蹲着弄鞋）→ 不算违规。

## 检查清单（H3 视频成片）

| 检查项 | 方法 |
|--------|------|
| 人物数量/重复 | ffmpeg -ss 抽多时间点帧 → vision_analyze 问"几个母亲/几个周野" |
| 分屏/宫格线渗漏 | 抽帧问"有没有画面分割/画中画/并排两个相同人物" |
| 人物朝向 | 抽帧问朝向（正/侧/背），对照分镜卡的 orientation_lock |
| 手部/手持物异常 | 抽帧问"手上拿着什么"，对照分镜卡写死的手部动作 |
| 空间串场 | 抽帧问"这是什么空间"，对照分镜卡的 space 字段 |
| 道具异常 | 抽帧问道具清单，对照 prop_before/prop_after |
| 方向锚点 | 扫提示词/分镜卡：left/right of the frame、on the left/right、镜头/画面左/右等画面锚点词→违规；方向必须以主体为参照（his right / in front of him / behind her） |
| 台词口型/音频 | 听音频段对照 dialogue（频谱分析走 av-generation-troubleshooting） |
| 台词文本 | 对比要读 dialogue 的 line 字段（是 dict 列表）；长台词拆多段 <d> 时**按拼接对比**；`<d>[Chinese] ` 后带一个空格是**官方格式**（不是违规，别删） |
| 提示词合规 | 读提示词 JSON 对照 skill 规则（六部分/标点/正向/单主体参考图） |

**抽帧规范**：ffmpeg -ss 时间点 -frames:v 1 抽多个时间点（每镜至少首/中/尾 3 点）；路径用 D:/ 风格（MSYS /d/ 风格 ffmpeg 写不出）；select 过滤器在 bash 引号里易失效，用 -ss 单帧抽。

**扫描脚本规范（2026-09-03 教训）**：
- ❌ 禁止子串匹配判违规（如 `"<Picture 4>. " in prompt` 会把 "follow \<Picture 4\>." 句尾合法引用误判成空标签）
- ✅ 判定需上下文：真空标签用行级正则 `(?m)^\s*<Picture \d+>\.\s*$`；空引用要看标签首现位置是否有 ": " 或 " is " 后缀
- ✅ 官方格式允许 <Picture N> 内联引用（"the man in <Picture 1>"）——首现无独立定义行≠违规
- ✅ 修复前先验证原文本（打印上下文），修复后再扫描验证，别改坏合法内容

## 节点检查接口

OPC 链路各节点产出的检查要点：
- **分镜包**：镜数/每镜时长≤15s（核心≤14s）/台词字数×语速≤时长/每镜状态≤4/切点动机/动作分工/180° 朝向锁定
- **故事板**：2×2 四格+细黑线/无文字/人物一致性（对照资产图）/每格状态与分镜卡一致
- **H3 提示词**：六部分齐全/subject 只定义出场角色/标点只允许「，。？！」/正向描述/手部写死
- **工作流**：结构=凡哥原件（MD5 对齐）/只换 prompt 不动结构/唯一节点 id
- **视频**：上表清单

## 报告格式

```
现象（我看到了什么，几帧证据）
依据（官方/社区来源+原话）
根因（现象↔依据对应关系）
修复（改什么，为什么这么改）
验证（怎么验证修好了）
```

无依据时必须写："现象：XXX；依据：暂未查到（已搜 XX）——待查方向：XXX；不脑补根因。"
