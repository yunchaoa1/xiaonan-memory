## 4. 节点输入检查

每个测试任务必须显式提供：

- `source_manifest`：文件路径、版本、验收状态、SHA-256；
- `asset_spec`：资产ID、类型、状态ID、上游可见事实、必须保持项、允许变化项、明确未知项；
- `runtime_model_id`：受控配置提供的实际模型ID，不从聊天称呼推断；
- `endpoint_mode`：生成或编辑端点；
- `reference_images[]`：引用ID、版本、SHA-256、来源、用途、顺序；没有已批准参考图时必须显式为空；
- `output_request`：尺寸、质量、背景、格式和压缩等，按实际模型校验；
- `prompt_schema_version`、`node_run_id`。

任何未登记路径、未核验哈希、未声明参考图或未来源化的提示词事实都触发阻断。

## 5. 自动检查

自动检查必须至少覆盖：

| 检查 | 通过条件 |
|---|---|
| 输入来源 | 仅固定输入或已登记批准输入，路径和SHA一致 |
| 资产字段 | ID、类型、版本、状态、来源和未知项非空 |
| 状态枚举 | 只使用 Skill 规定的状态值 |
| ID/版本 | ID稳定、版本显式、旧版本不被覆盖 |
| 模型配置 | 实际model_id可用，端点和参数符合运行时schema |
| 参考图 | 每张图有来源、版本、哈希、用途和顺序，禁止清单外图片 |
| 提示词溯源 | 每个可见事实都能映射到上游字段或锁定规则 |
| 输出文件 | 可解码，格式、MIME、尺寸、alpha和声明一致 |
| 输出哈希 | 实际输出SHA-256与记录一致 |
| QC与锁定 | 未通过QC或仍待人工复核不得LOCKED |
| 唯一成品 | 下游只收到一个正式锁定版本 |
| 场外输入 | `closed_input=true`，实际输入集合与声明集合一致 |

## 6. 人工复核

机器通过后仍须逐资产复核：

1. 身份是否与上游定义一致，关键识别锚点是否漂移；
2. 可见人物、服装、姿态、环境事实是否超出上游；
3. 场景空间核心、轴线、位置和拓扑是否自洽；
4. 道具类别、部件、数量、结构和绑定关系是否正确；
5. 上游明确未知的信息是否仍保持未知，是否出现模型脑补；
6. 状态版本是否只改变声明允许变化的内容；
7. 人物、场景、道具和能力是否发生职责污染。

没有实际图片时，人工复核结果只能记为 `PENDING`，不能写成 PASS。

## 7. 评分量表

每项0—4分：

- `4`：完全符合，证据充分，无修订；
- `3`：基本符合，有轻微可修订问题，不触发硬门禁；
- `2`：部分符合，存在明显问题，需要定向返工；
- `1`：严重偏离，主要约束未实现；
- `0`：缺失、无法判断、来源非法或与上游冲突。

评分维度：

| 维度 | 目标 |
|---|---|
| 输入与来源 | 版本、哈希、审批状态和来源完整 |
| 节点职责 | 只做主体资产编译/生成，不越权改剧情或分镜 |
| 可见事实 | 只呈现有来源事实 |
| 身份/状态 | 母版与状态版本边界清楚 |
| 场景/道具结构 | 独立绑定且无拓扑/结构污染 |
| 模型与参数 | 实际模型和参数经过运行时校验 |
| 输出追溯 | 元数据、文件、哈希、QC和锁定记录完整 |
| 封闭边界 | 无聊天、网络、场外或未登记输入 |

文档测试建议总分门槛：每项至少3分、无硬失败；实际图片测试还需所有人工复核项至少3分，且不得有0分关键项。

## 8. 硬失败、返工和复测

以下任一项直接 FAIL：

- 任何非法场外输入；
- 未知项被静默补成确定事实；
- 来源文件、版本或SHA不一致；
- 王二、金纹少年、未来年轻人或占位场景被错误判为可锁版；
- 铁链写入金纹少年人物底板，或火柴写入未来年轻人身份；
- 模型ID/端点/参数未经校验或静默降级；
- 输出无法解码、元数据不符或哈希不符；
- 未完成人工复核即锁定；
- 生成成功但缺少来源、QC或锁定记录。

返工只能修改已声明的生成变量、参数或提示词组织方式，不能添加剧情、角色、场景或道具事实。返工后必须使用相同固定输入重新运行全部自动检查，并重新进行独立人工复核。
