# 图书蒸馏 · 四步蒸书法

把一本书蒸成**可执行的方法论技能**（不是摘要、不是概念词条库）。

## 何时加载
- 凡哥说"蒸馏这本书""把《X》蒸成 skill"
- 凡哥发来一段蒸馏提示词（多为四步法：类型判定→提取→结构化→适用边界）
- 已有 raw 原文，要产出可复用技能

## 铁律
1. **蒸的是"能执行的方法"，不是"读书笔记"** —— 每条都必须落到"遇到什么情况，做什么动作"
2. **忠于原书，不编造** —— 凡哥铁律。作者没说的原理不替他说，只在"我的分析"层明确标注是推断
3. **边蒸边标出处** —— 事后补不回来
4. **不把书的铺垫章节当技巧** —— 信念/励志章节是心法层，单独归一类，别混进操作流程

## 第一步 · 类型判定（先判定，再动手）

| 类型 | 特征 | 提取目标 |
|---|---|---|
| **工具书** | 有步骤、流程、公式、清单 | 方法论：可执行步骤/流程/原则 |
| **非工具书** | 讲思考方式、决策逻辑 | 思维框架：作者的思考方式/分析框架 |
| **混合型**（最常见） | 主干是方法，外层是心法 | 以主干定结构，心法作为「底层机制」章节 |

判定结果要**明确写出来**给凡哥看，别闷头蒸。

## 第二步 · 提取

逐章过一遍，**每章产出一张方法论卡**：
- 本章解决什么问题（症状）
- 可执行的动作/步骤/公式（能抄下来直接用的）
- 作者原话金句（**保留原文**，那是证据）
- 出处（第几章/第几节）

## 第三步 · 结构化（统一成三件套）

标准 skill 形态：
```
输入（用户遇到的问题/症状）
  → 处理流程（按书的方法分步走，每步一个动作）
    → 输出（得到什么答案 / 什么行动方案）
```

**必须额外有「分诊表」**：症状 → 走哪条流程。这是把书用起来的关键——
没有分诊表，用户描述完问题还得自己猜该用哪招。

**技巧类内容单独归「工具箱」**，每条格式：公式 → 例子（用原书例子）→ 出处 → 翻车条件。

## 第四步 · 适用边界（写厚，不许一段打发）

必须回答：
- 在什么场景下有效
- **什么场景下会翻车**（要具体，不能写"看情况"）
- 需要什么前提条件
- 作者自己承认的局限
- 与用户现实处境的差距（如：书里的时代/文化背景 vs 现在）

## 必须补的三样（凡哥 2026-09 确认的加厚要求）
1. **出处标注** —— 每条方法论标原书章节，可溯源
2. **反例** —— 说清什么时候这条会失效、甚至反噬
3. **边界写厚** —— 边界比方法值钱

## 执行流程

1. **素材核查** —— 原文在不在？几章？多少字？已有哪些编译产物可复用？
2. **全文读入** —— 多章合并成单文件再 `read_file` 分批读（read_file 有 2000 行 / 100K 字符上限）
3. **逐章提方法论卡** —— 第二步
4. **合并去重** —— 跨章重复的概念只留一处，其余用「见流程X」引用
5. **组织成 skill 结构** —— 第三步 + 第四步
6. **查重划界** —— 搜现有技能，判断是否打架：重叠的部分**合并**，或**划清触发边界**
7. **双产物**：
   - 技能（`skill_manage` 装进 `D:\Hermes\skills\`）→ 给我自己用
   - 成品文档（`.md` + `.docx` → `D:\Documents\我的文档\蒸馏\`）→ 给凡哥看/存档
8. **回流** —— 更新 `DASHBOARD.md` + git 提交 + 跑技能健康检查
9. **验证** —— `skill_view` 能正常加载 + health_check 无异常

## 坑

- **技能重名/重叠**：动手前先 `search_files` 全库搜关键词，别蒸出第二个打架的技能
- **docx 生成**：用 python-docx，注意中文字体（默认字体中文会乱），标题层级要映射
- **技能描述一行定生死**：description 限 60 字符内、**中文触发词放最前**，否则以后不会自动加载
- **一本厚书别想一遍读完再蒸**：分章读、分章蒸，中间产物落盘，防上下文被挤爆
- **别把"金句"当"方法"**：金句是证据和感染力，方法是动作清单，两者分开写
- **样例先行**（书很厚时）：可先蒸 1 章给凡哥验风格，再全蒸——但凡哥说"直接蒸"就直蒸

## 已验证案例
- 《人性的弱点》→ `carnegie-human-relations`（management 类）
- 《迷上我》28 章 → `mishangwo-attraction-system`（relationships 类），结构 = 分诊表 + 四流程 + 工具箱 + 边界
