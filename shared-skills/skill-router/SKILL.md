# 技能总调度 · Skill Router

凡哥的模糊需求 → 拆解维度 → 逐项加载专项技能 → 全齐了才动笔。

## ⚡ 派活三步（2026-11-23）

最后要交到凡哥手上的东西，走三步：

**第一步：派一个写的。**
把活写成任务书给子代理，写明干什么、什么约束、写到哪个路径。收它的产出路径和自检结果。

**说「派了」就必须同一轮真的调 `delegate_task`。** 只在回复里写「派个人去出图」而没真的调用工具，等于没派——凡哥会当场问「你又没有派活」。说要派就当场调。

**长驻进程由主代理起，不由子代理起。** 子代理被停或超时的时候，它 `terminal(background=true)` 起的进程会跟着一起被杀（结果里会写 `Child left N background process(es) running that were TERMINATED with it`）。ComfyUI 这类要活过一轮的服务，主代理自己起、自己盯；子代理只负责提交和看结果。

**任务书必须带三件停止条件**，缺一件它就不知道什么时候收手：① **目标达成的判据**（文件存在、大于多少、带音轨这类可数的）② **重试上限**（写「最多重来 1 次」，不是写「如果卡了就重试」——没上限它会一直重来）③ **达成就停**。实证：跑片任务书只写了「如果卡超过 20 分钟就减时长重试」，既没写上限也没写完成即停，子代理空转 45 分钟把同一段跑了三遍，白烧电、白磨卡。

**第二步：派一个查的。**
另开一个子代理，第一句告诉它「你只挑毛病，不许改任何文件」。把稿件路径给它，收它的问题清单。清单上还有问题 → 回第一步让写的改 → 再走第二步复查；清单空了 → 往下走。

**第三步：交。**
把产物路径、这次改了什么、查的人挑出了几条问题又怎么解决的，一并告诉凡哥。

为什么走这三步：自己写、自己看，六轮返工、7 处否定词漏网都是这么来的。

## ⚡ 开工第零步：照技能的目录走，不许跳步（2026-11-23 修正）

**规范依据**：Anthropic Agent Skills 渐进式披露——`SKILL.md` 是目录（<500 行），`references/` 按需读，`scripts/` 跑不读。**不是全读，也不是凭感觉挑。**

**病根（2026-11-23 实证）**：`forest-laoli-h3` 选对了、`SKILL.md` 也读了，但第 12 条写着"情绪落成四区肌肉，详见 `acting-facs.md`"——**读到指令没执行下一步**。结果 `checklist.md`（62 项）、`gates.md`（P0/P1）、表演层三件套全部跳过，成片"脸不动、一个调到底"。

**规矩四条：**

1. **`SKILL.md` 必读全文**，读完把里面**每一条指向 `references/xxx.md` 的铁律列出来**——这些就是必读清单，按它读，不按自己判断挑。

2. **技能自带的执行清单必过**：有 `checklist.md` / `gates.md` / `scripts/` 的，**逐项打勾**。这是官方设计的执行关，不是参考资料。

3. **机检的盲区要人眼补**：`checklist` 里机检列标 `—` 的（表演层、视线、标点落身体），**机器抓"缺席"抓不到，必须逐条人眼看**。别拿"机检全绿"当验收。

4. **全库体检**（看哪些技能参考多却无机检，属高危）：
   ```bash
   python D:\Hermes\scripts\skill_full.py --audit
   python D:\Hermes\scripts\skill_full.py <技能名>        # 只列清单，不读正文
   ```

**判据一句话**：**不是"我读了多少"，是"技能让我做的，我做了几步"。**

## 🛑 分镜铁律（2026-12-19 第二次修正 · 违反即返工）

**凡哥说"做成分镜/做成视频/出片/拍出来/要能看/要喂 H3"——第一件事，不是打开 sd-storyboard-engine，是打开 `forest-laoli-h3`。**

```
唯一入口：forest-laoli-h3（H3 专用全流程，六阶段一条链）
  G0 锁 → ① 剧本 → ② 资产 → ③ 分镜 → ④ H3 编译 → ⑤ 词根清洗+h3_lint 机检 → ⑥ 交付
```

**为什么钉死（2026-12-19《偏心》全废实录）**：skill-router 顶部原写"① sd-storyboard-engine → ② h3-storyboard → ③ h3-video-prompt"，被当成铁律执行，导致：
- **台词全抽成 mp3、提示词里一句台词不写** → H3 只能自己编语音（编出英文），口型跟着英文走
- 正确做法是 `She says: <d>[Chinese] 台词</d>` 写进正文，**H3 自己生成中文语音、自己带口型**
- 情绪写成"紧张/委屈"结论词 → 铁律 12 禁；要写四区肌肉（眉/眼/口/颌可见动作）
- 只喂场景图、没做氛围层 → 铁律 21 三层分工（外形锁图、空间锁位、**氛围写到死**）
- 一镜塞 3–4 段 → 官方上限最多 2 切；对话段应"固定机位 + 换嘴切镜"
- 白跑 6 颗 + 17 张资产图作废

**根因不是忘，是路牌错**：2026-11-22 写这段时凭返工印象写，没跑 `find_skill.py` 检索、没核对技能列表。`forest-laoli-h3` 从 11-18 就装在 `D:\Hermes\skills\creative\forest-laoli-h3\`，描述第一句就写着"H3 专用短剧全流程"。

**⛔ 附加硬规矩（防再次选错）**：
1. 凡涉及 H3/视频/成片，**先跑** `python D:\Hermes\scripts\find_skill.py h3`，把命中的技能**描述第一句**读一遍再选。
2. **不许按技能名字猜用途**（`sd-storyboard-engine` 像分镜、`forest-laoli-h3` 像人格壳——实际判断反了）。
3. 凡"上次跑通过"的活，**先找上次的提交脚本和提示词原文**（`D:\Hermes\cache\seg0*.txt` 这类），照它复制，不许重新发明。
4. `sd-storyboard-engine` / `h3-video-prompt` 降级为**参考资料**，不再是必经链；只有凡哥明确要"纯文字分镜表"时才用第一个。**`h3-storyboard` 已于 2026-11-22 归档**（与 forest-laoli-h3 同为 H3 分镜、功能重复，凡哥定"只留一个"），归档路径 `D:\Hermes\skills-archive\creative\h3-storyboard`，要翻回来跑 `python D:\Hermes\skills\software-development\skill-library-maintenance\scripts\restore_skills.py h3-storyboard`。
