# 商品事实核查：拿硬事实的四个顺序

> 场景：用户拿一个商品来问"这个值不值 / 能不能干这件事 / 是不是智商税"，
> 而详情页可能被拦、成分表可能查不到。这份是**取证顺序**，不是产品推荐。

---

## ① 批号先行（最快、最硬，不用查配方）

中国化妆品批号直接决定它**法规上能不能做某件事**：

| 批号形态 | 类别 | 法规上允许 |
|---|---|---|
| `国妆特字G…` / `国妆特进字…` | 特殊化妆品 | 防晒、祛斑美白、染发、烫发、防脱发 —— **只有这类能加防晒剂** |
| `国妆网备字…` / `<省简称>G妆网备字…`（如 `京G妆网备字`） | 普通化妆品 | **不得添加防晒剂**，不得宣称美白祛斑/防脱 |
| `国妆备进字…` | 进口普通化妆品 | 同上，不能防晒 |

**用法**：任何保湿乳 / 面霜 / 身体乳，只要是普通备案，**不用看成分表就能断定它没有防晒能力**。
反过来，商家把"含维E""滋润修护"讲成"能防晒/抗光老"时，批号就是反证。

实测实例（2026-11-11）：大宝维生素E乳 `京G妆网备字2022000741` → 普通化妆品 → **必然不防晒**。
用户当时的真实处境：只在早上涂一次这瓶乳、**零防晒**，而所在地紫外线全年强、晒后先红再脱皮。

## ② 商品页被拦 → 读「跳转后的 URL」，不要读正文

抖音 / 淘宝 / 闲鱼 / 美团的分享短链（`v.douyin.com/xxx`、`m.tb.cn/xxx`）跳过去后，
**被拦的通常只是 HTML 正文**，而 resolved URL 的 query 里常带整页的结构化 JSON。

实测（2026-11-11，`v.douyin.com/2Z0E5e0T5tg/`）：

- 页面正文：53 字「检测到当前环境存在安全风险，请进入抖音查看商品详情」→ 抓正文必失败
- `page.url` 跳到 `haohuo.jinritemai.com/ecommerce/trade/detail/...`
- 其中 `goods_detail` 参数是 **URL-encoded JSON**，含 `title / sales / min_price / max_price`

```python
from urllib.parse import urlparse, parse_qs
import json
q = parse_qs(urlparse(page.url).query)
for k, v in q.items():
    try:
        print(k, json.loads(v[0]))
    except Exception:
        pass
```

命令行等价（拿 resolved URL）：
```bash
curl -sI -L -o /dev/null -w '%{url_effective}' "<短链>"
```

⚠️ **边界**：这样拿到的是**元数据**（标题 / 价格 / 销量 / 店铺），拿不到正文（成分表、参数表、详情文案）。
元数据不能冒充正文 —— 正文要不到就请用户截图。

## ③ 成分表：请用户拍瓶身背面

法规要求所有化妆品**必须标全成分**，瓶身标签比任何成分查询站都权威。
网上查不到时（商品页被拦、搜索被商品列表页淹没），直接请用户拍**瓶身背面成分表那一栏**，
比继续搜十次强。

> 2026-11-11 实测教训：搜「大宝维生素E乳 成分表」两轮，返回全是京东/淘宝商品列表页、
> 乱码站和无关文章；同一产品还有「经典款 / 增强版」两个配方（增强版含玻尿酸+人参），
> **版本不同成分就不同**，所以"查到个大概"比"查不到"更危险。

## ④ 官方备案核验

国家药监局「化妆品监管 APP」（`nmpa.gov.cn` 互动页有入口）可查备案号、备案成分、
生产企业。批号和成分对不上 = 假货或改配方。

---

## 三条判断纪律

1. **标题 ≠ 成分**。电商标题是关键词堆砌，出现"防晒""美白"只说明想被搜到，不说明有资格。
2. **"含 XX 成分" ≠ 起效浓度**。看排位（靠后的基本是概念添加）和浓度，不看有没有。
3. **价位决定功能上限**。9.9 元的乳液，成本结构决定了它做不了抗老、做不了防晒——
   不是厂家不想做，是这个价做不出来。说"它只有保湿一个功能"是有依据的，不是贬低。
