# 把仓库/技能副本交给别人之前：完整性核查（2026-11-19 实测）

> 场景：凡哥说「把这个 skill 发给小李 / 发给团队」。
> **「下载成功 N 个文件」≠「完整原版」。** 本文是交付前的核查动作与已踩的坑。

---

## 一、为什么会出问题（本次实证）

装 `forest-laoli-h3` 时用的是一个手写的 `get_forest.py`，里面有一个**硬编码的 `FILES` 列表**（21 条）。
脚本报「成功 21 / 失败 0」—— 看起来完美，其实：

| 项 | 实际情况 |
|---|---|
| 脚本下载的 | 21 个文件（SKILL.md + 20 本 references + h3_lint.py） |
| GitHub 仓库实际有 | **59 个文件** |
| 缺了什么 | `scripts/tests/` 下 **29 个测试用例** + `run_tests.py` + `check_docs.py` + `CHANGELOG.md` + `README.md` + `README.en.md` + `LICENSE` + `.gitignore` |
| 多出什么 | `case01_test.md` —— **仓库里根本没有**，是当初为了试机检脚本自己弄的，混在技能目录里 |

**根因：下载脚本的 FILES 列表是我手写的，不是从仓库读的。**
手写列表 = 只能拿到我以为需要的部分；仓库里还有什么，脚本永远不会告诉我。

## 二、核查四步（交付前必须走完）

### 第 1 步：拿仓库真实文件清单

```python
import urllib.request, json
op = urllib.request.build_opener(urllib.request.ProxyHandler(
    {'https': 'http://127.0.0.1:7897', 'http': 'http://127.0.0.1:7897'}))
d = json.load(op.open(
    f'https://api.github.com/repos/{owner}/{repo}/git/trees/main?recursive=1', timeout=60))
paths = [t['path'] for t in d['tree'] if t['type'] == 'blob']
print(len(paths), '个文件')
```

**注意分支名**：可能是 `main` 也可能 `master`，猜错会拿到 `404 Not Found`（14 字节）。

### 第 2 步：本地清单 vs 仓库清单，双向对账

- **只在本地的** → 多半是你自己加的临时文件，交付前剔掉
- **只在仓库的** → 缺件，要么补下，要么**明确告诉凡哥缺了什么、为什么没放**

```python
local = {相对路径 for 本地递归遍历}
repo  = {相对路径 for 仓库清单}
print('仅本地(多余):', sorted(local - repo))
print('仅仓库(缺失):', sorted(repo - local))
```

### 第 3 步：共有文件逐字节比对（不是比大小、不是比名字）

```bash
# 全量弱对比：文件名 + 大小相同才算过
for f in $(cd 本地目录 && find . -type f | sed 's|^\./||'); do
  curl -sL --max-time 90 "$RAW_BASE/$f" -o "/tmp/chk/$f"
  cmp -s "/tmp/chk/$f" "本地目录/$f" && echo "SAME $f" || echo "DIFF $f"
done
```

`cmp` 比 `sha256sum` 更好用——它直接回答「一样吗」，不用肉眼对哈希串。

### 第 4 步：交付前剔掉自己的临时文件

把第 2 步列出的「仅本地」文件删掉再打包。**混一个进去，别人拿到的就不是原版了，而他又没能力分辨。**

## 三、四个已经踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **raw URL 少一层子目录 → 静默 404** | 四个不同文件算出来的 sha256 **完全一样** | 那全是 14 字节的 `404: Not Found`。**哈希相同就是假成功信号**，先 `cat` 一眼内容。仓库文件常在 `<repo名>/` 子目录下，raw 路径要带：`/main/<repo名>/SKILL.md` |
| **镜像站不代理 API** | `https://ghfast.top/https://api.github.com/...` 返回 `Invalid input.` | `ghfast.top` 只代理 `raw.githubusercontent.com` 和 releases 下载。**API 要走代理直连**：`-x http://127.0.0.1:7897` 或 python 的 `ProxyHandler` |
| **代理没开** | `curl: (7) Failed to connect` | 先问一句「代理开没开」，别急着改脚本。（2026-11-19：凡哥中途说「刚才我没打开代理，你现在再试」→ 一开就通了） |
| **"文件数对上了"就当验完** | 21 个文件都在，以为没问题 | 数量对上只说明列表里的都下到了，**说明不了列表本身是全的**。必须走第 1、2 步 |

## 四、给凡哥的话术（他一定会问「这是原版吗」）

他问这句时**要的是证据，不是保证**。按这个顺序说，三句话：

1. **共有文件全部逐字节一致** —— 「22 个文件逐个跟 GitHub 比对过，0 个有差异」
2. **缺了什么，说清楚** —— 「作者仓库还有 29 个测试用例和 CHANGELOG/README，你说测试用例不用下，所以没放」
3. **多了什么、处理了没有** —— 「原来目录里有个 case01_test.md 是我自己试脚本弄的，不在仓库里，打包时剔掉了」

**别说「这就是原版」四个字**——不完全对。准确说法是「这 22 个文件跟 GitHub 上的一字不差，但不是仓库全部内容」。

## 五、顺带：这个技能能干什么、不能干什么（评估结论也要一起给）

凡哥拿到技能发给别人后，常接着问「这个技能做 X 怎么样」。**能力边界要在评估时就查清，别等他问。**

本次（forest-laoli-h3 写打斗）：

| | 结论 |
|---|---|
| 能写 | **单个动作**：一拳、一推、一倒。有"动作主体"机位行（全景/中景 + 低机位贴地仰 + 跟拍/手持）、两个打斗示例、**受击后重建站位**规则（防 H3 打完人漂移） |
| 不能写 | **整场打斗**：没有"一招一镜"拆分规则、没有多回合拆招节奏、没有招式谱。作者自己在 `camera-movement.md` 第 485 行写着 **`打戏另见 sd-combat`** |
| 模型层面更硬的限制 | 一镜 ≤70 词（描写一拳就二三十词）／同框最多 2 人／禁穿门穿缝（打飞出门框就半透明融化）／禁升格慢动作（H3 做不出来，渲染成静帧或糊片） |

**查法**：`grep -rin "combat\|fight\|打斗\|格斗\|武打" references/ SKILL.md`，重点看**作者有没有自己指向别的技能**——那是最诚实的边界声明。
