# 抖音视频页抓取 · 实测取证（2026-10-14 ~ 10-15）

> 场景：凡哥丢抖音分享链接（"分析这个开源项目 / 看看这个博主说的项目"）。
> 需要拿到：**文案 + 口播 + 评论区 + 画面**。以下全是本机实测，不是推测。

---

## 1. URL 形式决定能不能抓到主体（各试 3 次）

凡哥的分享链接**多是个人主页弹窗形式**：

```
https://www.douyin.com/user/self?from_tab_name=main&modal_id=<id>&showTab=like
```

| URL 形式 | 抓到的可见正文 |
|---|---|
| `/user/self?...&modal_id=<id>`（原形） | **3 次都只有 ~1.1K 字符** —— 只渲染出页脚，主视频根本没出来 |
| `https://www.douyin.com/video/<id>` | **第 1 次就 3.1K** —— 主体文案 + 评论区全拿到 |

**动作：收到抖音链接，先把 `modal_id=` 的值抽出来，拼成 `/video/<id>`。**

## 2. 渲染结果不稳定 → 看字符数 + 重试

同一 URL 多次访问的可见正文：**4579 / 3249 / 1637 / 1115 字符**（都见过）。

- **判据：< 2000 字符 ≈ 空壳**（只出了页脚）。
- 抓取脚本应**重试最多 3 次，取"文字最丰富"的那次**，够丰富就提前收工。
- 主视频的标题/文案**不在 HTML 内嵌 JSON 里可靠位置** —— 抖音把主体数据放在 XHR 里，HTML 只有推荐流的 SSR 数据。
  硬正则挖 `"desc"` 会**匹配到推荐位别的视频**（实测挖出的是另一个博主的名字）。
  → **可靠做法：从渲染后的可见文字里挑长行**（标题、文案、评论都在这），HTML 存下来备查即可。

## 3. ⭐ 长视频是【音视频分离轨】—— 截到的 `.mp4` 可能没有音频

**血泪实测**：13 分 11 秒的视频，下载成功（**35,168,402 字节**），ffmpeg 却报：

```
Stream #0:0[0x0](und): Video: h264 ...
Output file does not contain any stream
Error opening output file ...wav
Error opening output files: Invalid argument
```

`ffprobe` 一看：**只有 Video 轨，没有音频轨**。

- 抖音**长视频走分离轨**（video / audio 各一条流）。"挑最长的 `.mp4` 直链"的老挑法**只拿到视频轨** → **转写必然失败**。
- 对比：几十秒的短视频拿到的是合并流，所以**短视频能转、长视频不能** —— 症状有迷惑性。

### 连带的脚本缺陷（已修，别再犯）

原脚本用 `subprocess.run(..., capture_output=True)` 却**不检查返回码、不打 stderr**，
失败了只在后面的 `os.path.getsize(wav)` 上崩出 `FileNotFoundError` —— **真正的 ffmpeg 错误被吞了**，排查多绕一轮。

**规则：调外部命令一律检查 `returncode` + 打印 stderr 尾部；产物不存在就明确报错。**

### 侦察办法

监听页面全部 request，把 URL 按 `mime_type` / `audio`·`video` 关键词**分组打印**，
先看清"到底截到几条流"，再决定下载策略（视频轨 + 音频轨分别下再合，或改用能自动合流的下载器）。

## 4. 拿不到口播时的兜底（别卡死在一个源）

1. **抖音页自带 AI「章节要点」** —— 整页文字里含分段目录，实测拿到 8 段：
   `00:02 引言 / 00:39 原理 / 01:58 工作方式 / 04:00 升级 / 06:39 实操演示 / 08:19 信息收集 / 10:39 自动整理 / 12:13 看法`。
   **信息密度常常够用**，能直接判断"视频讲了什么、有没有我要的东西"。
2. **换平台找原片** —— 同一内容博主常**双平台发**。实测：抖音那条口播拿不到，
   **B站同名视频的简介直接给出项目名**（"我也把这套「萌芽知识库」开源到了 GitHub"），一句话解决定位。
   → 搜法：`<博主名> <标题关键词> bilibili`
3. **评论区** —— 常有人问出你正想问的（仓库地址 / 能不能用 / 替代品）。
4. ⚠️ 三条都拿不到 → **如实说"口播没取到"，不要凭标题脑补内容。**

## 5. 顺带：视频里提到的 GitHub 项目怎么定位

- **视频里常常不给仓库地址**（正文、评论里都没有）→ 只能靠项目名去搜。
- **搜项目名会撞一堆同名搬运/仿冒仓库**（实测项目名 `windows-mcp` 至少 4 个仿冒）。
  **认准 owner 与博主对得上**：博主"三颗门牙" → 仓库 `ThreeFrontTeeth/mengya-knowledge`。
- **GitHub API 匿名限流 60 次/小时** —— 连续查几个仓库就 `403 rate limit exceeded`。
  → 改用**页面抓取读 README**（`web_extract` 一类），别死磕 API。
- README 里要重点看**作者自己的免责/打假声明** —— 实测有项目作者明确打假第三方"加速下载/限速破解"式宣传，
  而视频标题正是那类夸大表述。**视频宣传 ≠ 项目能力，以作者声明为准。**
