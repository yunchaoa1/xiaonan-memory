# 显卡 / 算力硬件采购评估（凡哥）

## When to Use
凡哥说：买显卡 / 买服务器 / 本地小型服务器 / 租还是买 / 某某博主卖的靠不靠谱 / 显存多大够 / 满足 N 人并发 / 预算多少 —— **加载本技能**。
（审核别人出的「并发方案」不在这里，在 `team-management-ops` §8.9／§8.11：那是审方案，这里是买设备。）

## 0. 三件事必须分开判（混在一起必答错）

| 问题 | 能不能答 |
|---|---|
| **卡是真的吗** | 能 —— 查厂商官网型号页，参数、定位、功耗都有 |
| **卖家靠不靠谱** | **多数查不到** —— 短视频卖家没有公开工商信息，别替他背书 |
| **这台适不适合我们** | 能 —— 拿凡哥的口径逐条打勾／打叉 |

**三句话表述**：卡不假 ≠ 渠道可靠；渠道可靠 ≠ 适合我们的用途。
凡哥问"靠不靠谱"时，要**分开答**，别把三件事揉成一个"还行"。

## 1. 先把凡哥的口径翻译成硬条件

他的口径常常带**例外路径**，别只记住一个数字。

实例（2026-11-19 定，本项目现行口径）：
- 目标：月底满足 **20 人并发**
- 硬条件：**显存 48GB**
- 例外：**算力优于 5090 → 显存可降到 32GB**
- 也接受：**消费级 4090 48GB 改卡**、或 **5090**

翻译规则：
1. **显存是第一顺位**，不是核心数、不是代次 —— 视频/图像模型显存不够直接跑不动。
2. **例外条件要双向核**：既没到 48GB、算力又不如基准卡 → **直接排除，不用再谈**。
3. 结论形态用**勾叉**，不要给"综合评分"：每条硬条件一列，满足/不满足一眼看完。

## 2. 报价必须带来源 + 采集日期（铁律，凡哥定过）

- **写法**：`¥29,749–33,999（中关村在线商品页，2026-11 采集）`
- 可用来源：中关村在线（商品页/行情页）、淘宝/京东商品页、国外 CDW / gpupoet（标美元，**不要自己换算当人民币报价**）
- **禁止**：单卡价 × 卡数充整机、凭行情"估算"、把厂商指导价当成交价
- **查不到就说查不到**，不要用推算补空
- 报价单只作**比价**用；下单前必须拿到**书面报价单**（型号全称 × 数量 × 单价 × 整机配置 × 质保 × 到货天数）

## 2.1 每个数值都要有依据，无依据就剔除（凡哥 2026-11-20 铁律，优先级最高）

原话：**「每一个数值我必须要求你找得到，有依据」**。参数和价格一视同仁。

1. 表里每个数都要能指到出处 —— **官方 PDF 写文件名＋页码/表号**；**价格写页面 URL＋商家＋日期**。
2. **查不到依据的数，从表里删掉**：不估算、不写"约"、不拿第三方口径冒充官方。剩下的一律进「未核实」清单，写清"下单前让对方补"。
3. 离群价要说明为什么删（例：同款两家报 61,809 与 185,000，差三倍疑非单卡价 → 剔除）。
4. **自己上一版错的数，这一轮必须明写「更正」并附原文**，不能静悄悄改掉 —— 他会拿两版对。
5. 交表前自问一句：**这张表里有哪个数是我猜的？** 有就删。

本技能 2026-11-20 就是因为没守这一条，把 `RTX PRO 5000 48GB` 报成 2.97–3.4 万（实际 3.4–5.5 万），并据此推荐，整条结论得推翻重写。

## 2.2 价格必须是最新现货价，「参考价」会害人（凡哥 2026-11-20 原话：「你的价格普遍偏低」）

**这是比"没写来源"更隐蔽的错：来源写了、日期也写了，数还是错的。**

1. **中关村在线的「参考价 / 当地参考价」滞后，行情剧烈时能差一倍。** 实例（同一天 2026-11-20）：5090 的当地参考价写 24,399 元，华强北现货 **4.8 万**。上一版据此报 1.95 万，被直接打回。
2. **先查行情再报价。** 搜一句「YYYY年M月 显卡涨价/降价 行情」，看有没有在涨/跌周期里；有就**只用现货价或实地走访价**，参考价降级为"区间下界"。
3. **价格三处交叉验**：① 媒体/实地走访价（深圳商报、21 世纪经济、什么值得买这类带日期报道）② `wap.zol.com.cn/<大类>/<id>/price.html` 的商家报价列表（多家、带商家名）③ 二手平台追踪价（vramglass 之类，标"二手"）。
4. **表里要明写参考价与现货价的落差**，例：「ZOL 参考价 2.44 万已滞后，现货 4.8 万」——他一看就知道为什么换了口径。
5. **采集日期写"日"不写"月"**。本轮行情一天降几百，写"2026-11"等于没写日期。
6. **价格变了结论就会翻转**，所以每万元换算表必须跟着重算，不能只改价格行、留着旧排名。本轮就翻了：5090 从"单位带宽性价比之王"变成"每万元显存全场最差"。

## 2.3 交付物只做他这一轮点名的东西，别加戏

原话：**「你不用考虑 20 并发这个问题，你只需要关心我上一条给你的信息」**（2026-11-20）。

- 他这一轮要的是"性能和价格对比 ＋ 购买计划树"，**就不许把并发推算、峰值显存实测步骤、排队轮次塞进交付物**，那是我自己加的需求。
- 判断法：把交付物里每一节回头对一遍他这句话，**对不上的整节删掉**，不要"顺便也提醒一下"。
- 并发那段知识仍然有效（见 §5），但**触发条件是"他提了人数/并发/够不够用"，不是"我要买卡"**。

## 3. 型号陷阱（不全称下单必错）

- `RTX A4000 16GB`（2021 Ada 前一代）≠ `RTX PRO 4000 24GB`（Blackwell）—— 同一"4000"，差一代差 8G
- `RTX PRO 4000` 另有 **SFF 版**（低功耗小卡，性能更低）
- `RTX 4090 48GB` **不是官方型号**，是改装卡
- `RTX 5090` 与 `RTX 5090D`（国内版）显存/算力口径不同，别混
- `RTX PRO 5000 Blackwell` 有 **48GB 和 72GB** 两个版本，写全容量
- `RTX 5090D` 国内在售**两个版本**：32GB 原版，和 **24GB GDDR7 384-bit 的 v2 版**（ZOL 商品页标 "AI 算力 2375 TOPS"）。同一名字两套参数 → **拿不到官方参数页就不列进表**，要买单独核版本
- `RTX PRO 5000` 的位宽：**官方 384-bit**（产品资料 `Memory Interface 384-bit`），中关村参数页写 512bit 是错的；带宽反算 1,344 GB/s 也只对 384-bit。**参数冲突时以官方 PDF 为准，并在文档里写明谁写错了**

## 2.5 规格数据从哪来（一次拿全，别在网页上耗）

**首选 NVIDIA 官方 PDF，两条就够：**
1. **官方 Linecard**（`valuehub.hp.com/static/nvidia/docs/linecard-2026.pdf`）—— 一张表拿全全系：CUDA 核心、显存、**带宽**、单精度 TFLOPS、AI TOPS、是否 ECC、NVENC/NVDEC。比一张卡一个页快十倍。
2. **官方产品资料 PDF**（datasheet）—— 拿单卡精确值（带宽、AI TOPS、单精度、RT 算力、功耗）。用 `web_extract` 直接对 `.pdf` 链接即可。
3. **官方白皮书附录表** —— `NVIDIA RTX Blackwell GPU Architecture` 的 **Table 3（第 46 页）** 一次给全 4090／5090 的 CUDA、加速频率、**单精度 (Peak FP32 TFLOPS)**、显存、带宽、TGP、FP4 AI TOPS；`NVIDIA Ada GPU Architecture` 的 **Table 1（第 13 页）** 给 4090 的 FP8（660.6 稠密／1,321.2 稀疏）。

**读 PDF 表的两个坑（本次踩过）**
- `web_extract` 对长 PDF 只回开头几万字，**表在附录，抓不到**（只会看到目录里的 "Table 3 …… 46"）。
- `pdftotext -layout` 出来的 NVIDIA 参数页**标签与数值错行一格**：值挂在下一行标签后面。必须把「标签行 → 下一行开头」成对还原，错一格就会把 91.1 读成 210.6、把 660.6 读成 389.9。
- **校验法**：拿带宽反算一遍（GDDR7 28 Gbps × 384 bit ÷ 8 = 1,344 GB/s），对得上才敢写进表。

本地已存副本：`D:\Hermes\cache\gpu\`（blackwell.pdf／ada.pdf／ada6000.pdf／l40s2.pdf），下次直接 `pdftotext -layout` 读，不用重下。

**网页版规格页（厂商站、中关村参数页、TechPowerUp、Wikipedia）多数由 JS 渲染或反爬拦截，抓回来常是空壳。** 抓两次不完整就换 PDF，别在一个站上反复试——这是省时间的正解，不是"某站不能用"。

**参数表里三样必须同时给，少一样就没法判：**

| 指标 | 管什么 | 怎么说人话 |
|---|---|---|
| **带宽 GB/s** | 出片快慢 | 显存搬运数据的速度 |
| **单精度 TFLOPS** | 传统算力 | 老口径，跨代可比 |
| **AI TOPS** | AI 算力（厂家标） | **各家按不同精度标（Blackwell 用 FP4、Ada 用 FP8），跨精度不可直接横比** |

**反常识实例（务必记住）**：`RTX PRO 5000 Blackwell 48GB` 单精度只有 **65 TFLOPS**，低于 `RTX 4090` 的 82.6；但带宽 **1,344** 高于 4090 改卡的 1,008，AI TOPS **2,064** 也更高。
→ **核心数少 ≠ 跑得慢。** 只看核心数会当场判错卡。

### 2.5.1 AI 算力怎么统一成一把尺子（凡哥必问：「4090 的 FP8 为什么那么低，差好多倍？」）

**这不是性能差，是厂商各按自家最高精度标，混在一张表里就成了假对比。** 2026-11-20 他就卡在这句上，整个计划书为此单开一章。

换算公式（**严格成立，可直接写进对外文件**）：

```
FP4 稀疏标称 ÷ 4 ＝ FP8 稠密
FP8 稀疏标称 ÷ 2 ＝ FP8 稠密
（FP4 比 FP8 低一档快 2 倍；稀疏再快 2 倍 → 叠起来 4 倍）
```

**验证法（务必在文档里写出来，让他/林总能自己拿计算器复核）**：
- 5090：`3,352 AI TOPS（FP4 稀疏）÷ 4 ＝ 838` ← 与白皮书 Table 3 官方稠密值 838 一致
- 4090：`1,321.2（FP8 稀疏）÷ 2 ＝ 660.6` ← 与 Ada 白皮书官方稠密值 660.6 一致

**同一把尺子（FP8 稠密 TFLOPS）重排**：PRO 6000 96G 1,000 ｜ 5090 838 ｜ L40S 733 ｜ 6000 Ada 728.5 ｜ **4090 48G 660.6** ｜ **PRO 5000 48G 516（48G 里垫底）**

→ 话术：**「4090 那格不是低，是别人按 4 倍大的尺子标；换成同一把尺子，它排第五，垫底的是 4 万的 PRO 5000。」**
→ 表里两列并列最安全：`厂商标称（注明精度）` ＋ `统一换算 FP8 稠密`；只留一列就必然被问。

**两个换算指标，凡哥一眼看出钱花在哪：**
- 每 GB 显存单价 = 价 ÷ 显存（谁最划算）
- 每万元买到的带宽 = 带宽 ÷ 价 × 10000（谁跑得快）

## 2.6 凡哥报型号常带口误，先复述再算

本次真实发生的两次纠正：`pro6000` → 他说错了，要 `pro5000`；`4090 和 5000 都是 48G 版本`。

规则：
1. **报参数前先用一句话复述口径**：「按你定的：5090 是 32G、4090 是 48G 改卡、PRO 5000 是 48G，对吧」——他一句话就能纠。
2. **表里型号后面必须带容量**：`RTX 4090 48G 改卡`、`PRO 5000 48G`、`5090 32G`。只写"PRO 5000"迟早算错。
3. 前后两次说法不一致（先说 PRO 6000 后说 PRO 5000）→ **按最新那句改，并把上一轮结论作废重算**，不要两版都留着让他自己挑。
4. 已纠正过的型号，这一整轮都不能回退（见 MEMORY 的持续性思维）。

## 4. 渠道：改卡 vs 行货

| | 4090 48GB 改卡 | 行货专业卡（A6000 / PRO 5000 / 6000 Ada） |
|---|---|---|
| 价格 | 便宜几千 | 贵 |
| 显存 | 48G 达标 | 48G 达标 |
| 保修 | **无原厂，只有店保** | 原厂保修 |
| 稳定性 | 双面焊显存、涡轮很吵、长期跑故障率高 | ECC、低功耗、单槽可多卡 |

**判断法**：这台是**唯一的测试/生产机** → 买行货；只是**多台里的替补或先跑起来** → 改卡可以谈。
别为了省几千块，让唯一一台机器带着无保修风险上岗。

### 4.1 魔改卡怎么进对比表（凡哥 2026-11-20 定的口径）

原话：**「魔改卡你只需要记着它只是增加了显存，算力和带宽是不变的，不要考虑其他因素，到时候会有人为筛选。」**

→ 表里 `RTX 4090 48GB 魔改` 就写：**显存 48GB ＋ 官方 4090 原版的 82.6 TFLOPS／1,008 GB/s／450W**。
不要把"改卡后带宽可能下降""双面显存影响寿命"这类推测塞进参数列 —— **保修风险单独提一句就够，承担不承担是他的判断，不是我们替他算的变量。**

## 5. 并发 ≠ 一张卡（最容易被卖家带偏的一句）

> ⚠️ **触发条件：他提了"N 人""并发""够不够用"才写这一节。他没提就别算（见 §2.3）。**

**视频/图像生成是独占显存的**：一个人跑一个任务就占一块显存，别人不能共用。所以：

> N 人并发 ≠ 买一张 N 倍显存的卡

**先实测，再谈买几张**：
1. 跑一个**目标规格**的任务（例：960×544、15 秒），记录**峰值显存**
2. 卡显存 ÷ 峰值 = **同时能跑几个**
3. N 人 ÷ 该数 = **要排几批，或要买几张卡**

**两个口径差几倍，必须当场问清**：
- 「N 人**同时点生成**，各等各的」→ 要买够显存（多卡）
- 「N 人**同时在用、排队出片**」→ 一张卡 ＋ 排队机制就够

给凡哥的话：**一张 48G 卡能做到"N 人提交都不报错、排队出片"；做不到"N 人同时生成"。** 这两句话决定采购量，别含糊过去。

## 6. 卖家靠不靠谱：先顺名字摸主体，再让材料说话

**第 0 步（本次实测有效，别跳过）：拿账号名去搜官网，摸出公司主体。**
抖音号「赋欣工作站服务器」→ 搜「赋欣」→ **上海赋欣科技有限公司，fuxincloud.com，沪ICP备2023012329号-2，上海闵行金茂科技园 A 栋 1 楼，天猫/京东/抖音/视频号四店** → 再抓官网「产品中心」，把在售卡型逐条列出来对他的需求核"他们家有没有这张"。

这一步一次解决两个问题：**主体是否存在（有备案、有地址、有电商店 → 是能对上牌子的公司）**，以及**他家到底有什么货**。比向他一句句问快得多。

三个必说清的口径：
- **有实体有备案 ≠ 案例是真的** —— 官网上写"某某企业客户案例"，没核实就说没核实
- **官网列了 ≠ 现货** —— 官网常跟一句"以具体到货版本为准"，说明货源浮动 → **报价单必须写死型号全称 + 显存容量**
- **主体能查到，仍要给七条材料**（下面）

短视频平台的账号**搜索要登录、公开网页常无工商信息** → 顺名字也摸不到主体时，查不到就是查不到，**不要用"看着挺专业""粉丝不少"当证据**。

要材料，七条缺一不下单：
1. **营业执照** → 自己去国家企业信用信息公示系统查存续、经营异常
2. **打对公账户**，不转个人微信/支付宝
3. **增值税专用发票**（公司采购可抵扣；开不出不买）
4. **显卡 SN** → 到手逐个去品牌官网查保修状态与出厂日期（查不到＝水货/二手）
5. **型号写全**（见第 3 节）
6. **保修范围**：整机保修还是散件保修，坏了几天上门
7. **先买一台**：跑通、拆开看卡、查完 SN，再谈第二批

## 7. 交付形态

- 一张**对比表**：型号 ｜ 显存 ｜ 带宽 ｜ 单精度 ｜ AI TOPS ｜ 报价（来源＋采集日） ｜ 行货/改卡
- **推荐顺序**（稳 → 性价比 → 风险），每条一句理由
- 结尾**只问一个**凡哥能一句话拍板的决策（预算 / 同时生成还是排队 / 要不要专业卡）

### 7.1 凡哥说"出一棵购买计划树"时的固定结构

他要的不是一张表，是**能顺着走到底的决策树**。照这个骨架写：

```
【根】月底 N 人培训测试
├─ 第0步（0 元，必做）：用现有卡跑一个目标规格任务，记峰值显存
│    → 这个数不出来，买几张全是瞎猜
├─ 枝A 预算 ≤X 万 / 低显存档      → 买几张、干什么、单价、总价
├─ 枝B 预算 Y 万 / 必须 48G  ★推荐 → 同上
├─ 枝C 预算 Z 万 / 48G 且要真算力  → 同上
├─ 枝D 预算 W 万 / 单卡最强        → 同上
└─ 枝E 真要 N 人"同时"生成（不推荐）→ 写清总价（通常买不起），用来劝退
```

每条枝必须写全四件：**买几张 / 干什么用 / 单价 / 总价**。只写型号不写数量的不算计划树。

三处必带的收尾：
1. **第 0 步只在他说了并发时放**——先实测单任务峰值显存，再谈卡数（0 元、1 天，省下几万块的瞎买）；他只问"性能价格对比＋计划树"时，**删掉第 0 步和枝 E**，树按「预算档／显存档」分枝即可
2. **枝 E 同理**——只在他说了"N 人真同时"时放，写清总价让他自己看见"这不现实，先买一张＋排队"
3. **「未核实」清单**——所有没抓到官方数或书面报价的项（改卡实测带宽、国内特供版 AI 算力、没查到价的型号）单独列出来，写清"下单前让对方补"

### 7.1.2 他说「买两个 8 卡整机 或者 三个 8 卡整机」时：规模测算三件套

**这是量级不同的口径**（16 张 vs 24 张，几十万到一百多万），不再是"买一张卡"。测算法固定三步：

1. **先算三项总量**：`显存总量＝单卡显存×张数`、`总算力＝单卡算力×张数`（统一用 FP8 稠密，见 §2.5.1）、`总带宽＝单卡带宽×张数`
2. **再算两个每万元**：`每万元算力`、`每万元带宽` —— 张数一变，排名不变（同型号等比），所以**跨型号比才用它，2 台/3 台之间比用总量**
3. **金额只算显卡**：整机（CPU/内存/电源/机箱/散热/网络）**必须单列"由供应商报价"**，绝不用"单卡价×8"充整机价（凡哥定过的铁律）。文件里明写"本表金额仅为显卡部分"

2026-11-20 实测底数（单价见 `references/显卡规格与报价_2026-11.md`）：

| 型号 | 16 张（2 台）显卡额 | 显存总量 | 总算力(FP8稠密) | 24 张（3 台）显卡额 | 显存总量 |
|---|---|---|---|---|---|
| 4090 48G 魔改 @3.0 万 | 48.0 万 | 768 GB | 10,570 TF | 72.0 万 | 1,152 GB |
| RTX 5090 @4.8 万 | 76.8 万 | 512 GB | 13,408 TF | 115.2 万 | 768 GB |
| PRO 5000 48G @4.0 万 | 64.0 万 | 768 GB | 8,256 TF | 96.0 万 | 1,152 GB |
| 6000 Ada @5.3 万 | 84.8 万 | 768 GB | 11,660 TF | 127.2 万 | 1,152 GB |
| L40S @5.675 万 | 90.8 万 | 768 GB | 11,724 TF | 136.2 万 | 1,152 GB |
| PRO 6000 96G @6.72 万 | 107.5 万 | 1,536 GB | 16,000 TF | 161.3 万 | 2,304 GB |

**写法**：方案分「2 台 / 3 台」两档 × 卡型，每个方案框写全六行：卡型与张数／显卡额／显存总量／总算力／适用／取舍；结论里给**一句推荐 ＋ 一句"2 台先跑、验收合格再补第 3 台"的台阶**——这个台阶比一次买 24 张更容易被批。

## 7.1.3 整机平台：CPU 会不会和 NVIDIA「打架」（2026-11-20 核实，凡哥当场问过）

原话：**「CPU 是不是不能用 AMD 的，会和英伟达的显卡打架？有没有这个风险，如果有就在单机购买要求里注明。」**

### 第一件事：这种「听说 A 和 B 不合」的传闻，先找反证
**没有这回事。** 反证是官方在售的 8 卡整机本身就用 EPYC：

| 厂商 | 型号 | 配置 |
|---|---|---|
| 超微 | AS-4125GS-TNHR2 | 双路 EPYC 9004/9005 ＋ 8×NVIDIA HGX H100/H200 |
| 超微 | AS-4126GS-NBR | 双路 EPYC 9005/9004 ＋ 8 卡 |
| 技嘉 | G363-ZR0 | EPYC 9004 ＋ 8 卡 |
| 联想 | SR675 V3 | AMD 平台 ＋ 8×H200 / L40S |

→ **高端的 H100/H200 官方整机就是 EPYC 平台**，真不兼容这些机器根本卖不出去。
→ **别把传闻写进对外文件**：写「不能用 AMD」等于给林总递错误信息，供应商一听就知道我们不懂。

### 第二件事：真风险在主板，不在 CPU 品牌 —— PCIe BAR 空间
大显存卡每张要在主板地址空间占一大块 BAR，8 张叠起来容易爆，症状是**只识别部分显卡 / 开机卡死**。两条公开装机实录：
- EPYC 9275 ＋ 技嘉 MZ33-AR1 装 **4×RTX PRO 6000**：装 1 张正常，**装 2 张直接卡死**（厂商支持回复"多卡可能需调 BIOS"）
- **2×PRO 6000** 报 `PCI/MMIO/BAR 资源耗尽`；已开 Resizable BAR，但 BIOS 里**没有 "Above 4G Encoding" 选项**

### 写不写进文件：**核实无风险 → 一个字都不改**（凡哥 2026-11-20 当晚原话：「没有风险就不要改动任何内容」）

我先按"把真风险落成验收条款"的思路，往文件里加了五处（CPU 行改写、新增「PCIe 与 BIOS」行、验收条加"8 卡全部识别"、风险表加 BAR、附录 C 补两条依据）。他看完直接回：**「没有风险就不要改动任何内容」** → 五处全部回退，重新渲染后 PDF 字节数与改动前完全一致才算回退到位。

**规则（覆盖上面的"落成条款"冲动）**：
1. 他抛出"听说 A 和 B 打架"这类疑问时，**先核实**；**核实结论是"无风险"→ 只在内部记录（台账 ＋ DASHBOARD），对外文件一个字不动**。
2. 即便核实时**旁支发现了别的问题**（本轮就是多卡 PCIe BAR 空间），也**先问再动**，不擅自加章节、加条款、改写他的表 —— 他只要他点名的那一件事。
3. 已经动过的，**完整回退并验证**（重渲染比字节数、逐页目视），然后明说"回了哪几条"。
4. 内部留档仍然要做：这类核实结论（谁家 CPU 能不能配、哪几款整机是官方在售）写进台账／DASHBOARD，下次再问直接取，不用重新查。

### 给林总的一句话（比参数表管用）
> **「CPU 选 Intel 还是 AMD 都行；但签合同前，让对方当场证明这台机器能把 8 张卡全认出来，并且满载跑两小时不黑屏。」**

**方法论（可复用）**：凡哥拿"听说有风险"来问时 → ① 找反证（官方在售整机、官方兼容列表）② 找真风险（用户装机实录、厂商公告）③ **把真风险落成验收条款**，传闻一个字不写进对外文件。

## 7.2 凡哥说「做成 PDF 版计划书 / 谁要去深圳」时

这时交付物**从给凡哥看的 md 变成给外人看的正式文件**，规则多一条：**过程全删，只留结论和可核查依据。**

- **结构照 v3（六章，2026-11-20 当晚最终定版；v2 八章、v1 九章都已作废）**：封面 / 一 候选产品技术参数与市场价格（**表里直接带"市场价格"列**，AI 算力一列直接写统一 FP8 稠密数值）/ 二 八卡整机规模与显存总量（16 张 / 24 张）/ 三 采购方案比较（**算力＋带宽＋价格三合一表 ＋ 每万元换算 ＋ 三个方案框**）/ 四 供应商与合同要求 / 五 风险与应对 / 六 结论与建议 / 附录 A 现场询价记录表（**10 行留白，行高 ≥8mm**）/ 附录 B 九项必核 / 附录 C 数据来源。完整写法照抄 `references/采购计划书_结构与排版.md`
- **他删掉的五章，永远别再写进去**：① 采购背景与用途 ② 独立成章的"市场参考价格" ③ "选型分析" ④ **"技术要求与选型口径"** ⑤ **"AI 算力数值怎么看"**。原话依次是「不用写」「没有必要写」；后两章是他 2026-11-20 当晚一句 **「不要写了，没必要，你直接把 AI 算力的数值写成统一的口径就行了，不用解释」** 删掉的 —— 即：**口径统一体现在数字上，不体现在章节上**（表头写"AI 算力（FP8 稠密 TFLOPS）"，格子里直接写 660.6／838／516／728.5／733／1,000，表下脚注一句"统一按 FP8 稠密口径"即可，不再讲 FP4/稀疏/为什么）。
