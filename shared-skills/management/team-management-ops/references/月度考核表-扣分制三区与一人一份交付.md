# 月度绩效考核表：扣分制三区 · 一人一份生成与校验

> 2026-10 实战固化（凡哥 10-29~10-30 逐条纠正到定稿）。**这是操作层配方**；制度口径与判定判据见 SKILL.md §8.11 ~ §8.11.5。

## 一、定稿口径（凡哥原话钉死的）

| 项 | 口径 |
|---|---|
| 评分制 | **百分制、只有扣分项、没有加分项**（起评 100，逐条往下扣） |
| 结构 | **固定区 40 ＋ 变动区 40 ＋ 临时区 20** |
| 固定区 | 服从上级领导安排 / 考勤 / 日报 / 团队协作 / 跨部门协作，**五项各 8 分，永远不变** |
| 变动区 | **按本职划区，不按项目划**，每月重划（本职定义由凡哥给，写在表头） |
| 临时区 | 本职之外、上级临时调度的工作；**本月无临时活 → 不扣分（20 全拿）** |
| 让位 | **因上级安排暂停/停手的不扣分**（叫停、战略转向、抽调支援） |
| 推辞 | 推辞临时调度 → 固定区「服从上级领导安排」**一次扣满 8** |
| 流程 | 出内容与分区 → 下发个人 → **本人自评（自己算扣多少）** → 流程上传 → 负责人复核 → 汇总上级（陈总） |
| 下发形态 | **一人一份单独的表**（不是总表），各看各的 |
| 自评口径 | 只写「**这一项为什么扣 / 为什么不扣**」，不写辛苦 |

## 二、两类活怎么判（凡哥逐条校正出来的判据）

- **本职** ＝「把这件本职产品做好」：交付、适配、修 bug、**后期完善**、吸取反馈优化
- **临时** ＝「上级另派的一件事」：专项（如「框架选型 → 并发方案 → 高并发实现方式确认」整条线）、跨部门培训与需求整理、运维抢修、服务器统计与采购、演示保障
- **一条临时线跨多天多次动作 → 记 1 件，不拆**（拆开会把临时区白灌掉一半分）
- **别把「他开发的系统」与「他本人被考核」混为一谈**（凡哥 2026-10-30 明确否掉我为唐光辉加的回避条款）

## 三、变动区通用扣分梯（每项都按这个梯子）

| 情形 | 扣分 |
|---|---|
| 达成，能直接拿去用 | 0 |
| 达成但有瑕疵、需修补 | 扣该项 20% |
| 部分达成（缺关键环节） | 扣该项 40% |
| 延期交付 | 扣 30%，另每延 1 天加扣 10% |
| 未交付 / 未做 | 扣该项 100% |

每项都要写清「**达成怎么算**」（例：2.0 落地 18 分 → 达成 ＝ 帧格视界自己操作做出可用成片），否则自评和复核各说各话。

## 四、交付纪律（这几条是被凡哥抓出来的）

1. **逐条对账，不凭印象**：拿 `集团/台账数据.json` 里每人当月**每一条**日报撞表（写脚本比对），漏一项都会被问住（本次 v4 漏 13 项）。
2. **附「全月工作流水」**：把台账原始条目按日期列在表末，让凡哥能逐条核——**这是"没漏"的证据**。
3. **一人一份、互不串人**：每份只放本人分区；生成后用脚本校验「别人的分区标题不出现在我这份里」。
4. **Word 必须有**（下发要走流程），生成后回读校验：段落数 / 表格数 / **残留 `**` 与反引号必须为 0**。
5. **不批量推附件**：多份只报目录＋文件名清单，不逐个 `MEDIA:`。
6. **表里禁止加戏条款**：推演出来的"防弊/回避"规则先问，不直接写。

## 六、已知坑

- **长脚本 `execute_code` 会被截断**（含三引号大段文本时 `SyntaxError: unterminated string literal`）→ 长脚本一律先 `write_file` 落盘再 `python` 跑。
- 字符串里塞中文引号 `"…"` 会撞 Python 引号 → 统一用「」。
- 台账 JSON 用 `json.load → 改 → json.dump`；**只改内存不落盘等于没改**（改账铁律）。
- 目录/文件改名后必须扫全部引用（脚本硬编码路径、技能 references、DASHBOARD、台账、待办）。
