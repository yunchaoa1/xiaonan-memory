## 一、A 层 5 维尺度原文（直接抄进表）

| 维度 | 权重 | 评分标准原文 |
|---|---|---|
| ① 交付质量 | 0.40 | 1、交付后基本不返工、无重大问题，关键链路当场跑通且同输入同结果 → 100 分；2、能出结果但需人工干预 → 80 分；3、时好时坏、或返工 3–4 次 → 60 分；4、跑不通、或返工 ≥5 次 → 0 分 |
| ② 交付时间 | 0.20 | 1、按期交付（实际交付日 ≤ 承诺交付日）→ 100 分；2、超期 1–2 个工作日 → 80 分；3、超期 3–4 个工作日 → 60 分；4、超期 5 个工作日及以上 → 0 分（**每 2 个工作日一档**） |
| ③ 项目完结归档 | 0.15 | 1、项目完结时交齐「原始代码 + 项目说明书」，说明书审核通过 → 100 分；2、交齐但说明书缺节或照着跑不起来 → 60 分；3、只交代码、无说明书 → 0 分（本月没有项目完结 → 按满分；正式部署后的维护迭代同样要归档） |
| ④ 跨部门协同 | 0.15 | 1、有正向口碑留痕（对接部门 / 对方主管反馈配合顺畅、帮了别人）→ 100 分；2、无口碑留痕（本月无跨部门协作或无可评价）→ 按满分；3、有负面留痕（拖了别人后腿、沟通不畅被反馈）→ 50 分；4、因沟通配合造成跨部门工作明显受阻 → 0 分（口碑来源：对接方反馈 / 会议记录 / 主管随手记；不由员工自报） |
| ⑤ 服从性与制度执行 | 0.10 | 1、上级安排按时接、按时回、按要求完成后反馈；日报 / 台账 / 流程等公司制度按规范执行 → 100 分；2、偶有延迟但事后补齐、无实际影响 → 80 分；3、有明确不执行或不反馈的记录 → 60 分；4、多次不执行、或违反公司规章制度并造成影响 → 0 分（无违反＝满分；有具体记录才扣，记录由主管留） |

**被否决的写法（别回退）**：

- ④ 曾用「资产与沉淀（取用率）」→ 凡哥：「没必要，就是项目完结后归档」→ 撤销，改 ③。
- ② 交付时间的四次返工：百分比（按时率）→ 「**太抽象**」；**延期次数** → 「**不是延期几次**」；改期留痕不扣分 → 「**不要在交付时间维度上留有改期的口子**」；"超期但在月内补交 60"的三档版 → 被「**按超时天数、两个工作日一档**」覆盖 → **终版：按期 100 / 超 1–2 个工作日 80 / 超 3–4 个工作日 60 / 超 ≥5 个工作日 0**。

## 二、归档＝《项目说明书》6 节 + 小南审核 4 条

**说明书 6 节**：① 这个项目是干什么的（一句话目标 + 谁在用）② 怎么跑起来（环境 / 依赖 / 启动步骤 / 端口·配置项）③ 东西都在哪（代码目录 / 数据库 / 素材 / 配置 / 部署位置）④ 模块怎么分（3–8 个模块各管什么、怎么互调）⑤ 为什么这么做（关键技术选型与踩过的坑）⑥ 术语表。

**审核 4 条（小南直接审，不找人跑——凡哥选的）**：
1. 原始代码完整、可拉取（哪些仓库/路径，小南要知道 remote/服务器位置）；
2. 6 节齐（缺节 → 60 分档）；
3. **照着说明书能把项目跑起来**（跑不起来 → 60 分档）；
4. 关键决策与踩坑有记录（第 ⑤ 节——最常被漏、也最值钱）。

**可学案例出处**（凡哥明确要求"找找技术的项目归档案例"）：
- **arc42**（arc42.org，免费开源架构文档标准，2005 年起）：12 节里挑出决定"能不能接手"的 6 节；官方理念「只写读者真正需要的，所有章节可选」。
- **DA/T 28《国家重大建设项目文件归档要求与档案整理规范》** + **《建设项目档案管理规范》（2019 修订）**：归档"完整、成套、系统"；「谁形成谁整理」。
- **GB/T 18894-2016《电子文件归档与电子档案管理规范》**：电子文件（源代码、原始数据）随档案一起归档。
- **清华大学科研项目归档办法**：立项 / 实施（设计·图纸·原始记录）/ 结项（技术总结·测试·验收）三段。

## 三、跨部门协同：口碑留痕机制

- **口径**：凡哥原话「这个是属于**口口相传听来的口碑**，需要记录在考核里」。
- **记录表**（台账第 3 页）：日期 ｜ 本部门同事 ｜ 对接部门 / 对接人 ｜ 事项 ｜ 对方评价 / 口碑 ｜ 记录人 ｜ 来源。
- **只认留痕**：没有留痕 → 满分（不制造焦虑）；**有负面留痕才扣**（50 分档）；致跨部门工作明显受阻 → 0。
- **不由员工自报**：来源＝对接方反馈 / 会议记录 / 凡哥随口一句 → 小南代记。**别去要求其他部门填表**（跨部门只给素材、不给制度，别招怨）。

### 实操坑（都踩过）
1. **openpyxl 跨工作簿复制样式**：直接 `cell._style = src._style` → `IndexError: list index out of range`（在 `merge_cells` 时爆）。必须**逐属性复制**：`font / fill / border / alignment / number_format / protection`。
2. **目标文件被占用**：报 `PermissionError` + 目录出现 `~$文件名.xlsx` = 正被 Excel/WPS 打开 → 循环里 **try/except 跳过 + 回复里点名**，让凡哥关掉后重跑；别硬覆盖、别删他的窗口。
3. **不要先删旧文件再生成**：生成失败会两头空 → 先写临时文件，成功后替换。
4. **改完必须程序化自检**：读回每份 `A4:C8`（5 维）两两比对（本次 = True 才交付）+ 核 `=SUM(B4:B8)`、B 层 10 行空白、**`max_row`＝22 且注在第 22 行**（C 层已删 → 不再有 `=B4..` / `=D*B` 那组公式）。
5. **底稿安全**：动凡哥手改过的文件前，先 `cp` 一份到 `D:\Hermes\cache\`（如 `何锦波绩效考核_5维前备份_20260923.xlsx`）再改。
