# 多目标项目推进不动 · 卡点诊断法

> 立档：2026-11-22（凡哥：「小唐现在进度确实很慢，我呢也对数字员工毫无头绪，只能让小吴一点一点的试着做，你觉得如何能解决这个问题呢？」）
> 适用：一个人被一次性派了 N 项功能，周期两三周，进度只在其中一两项上动。

---

## 一、先看事实，别先下"他慢"的结论

小唐「AI 数字员工」五项，11-16 立项、11-27 交，5 个工作日后的台账实况：

| 项 | 状态 |
|---|---|
| ① 报销排版打印 | **已完成**（11-18，还提前一天） |
| ① 延伸：审批／通知／关联 | **已完成**（11-17、11-20） |
| ② Agent 自写日报 | 零记录 |
| ③ 月底自动考核表 | 零记录 |
| ④ 下发项目任务 | 零记录 |
| ⑤ 日历可视化 | 零记录 |

**五天全砸在第①项。** 而第①项恰好是五项里唯一「东西长什么样一眼能看见」的——一个能打印出来的文件。

**规律：进度只会往"有形状"的那一项上跑。** 这不是态度问题，是任务定义问题。

---

## 二、三个根因（按出现频率）

### 1. 没写"做到哪算完"，只剩有产物形态的那项能被推进

「完善报销排版打印」他知道做成什么样算完（打出来能直接用）。
「Agent 自己写日报」「日历可视化」——**没有输出形态、没有数据来源、没有验收标准**。他不是不想做，是不知道做到哪算交。

→ 判据：**逐项问三句，答不出就是没定义，不是他慢**
1. 这一项交出来长什么样？
2. 数据从哪来？
3. 谁给它权限／谁配合？

### 2. 卡点日报写"暂无"，真实卡点是"跨系统数据／权限不在他手上"

②③④⑤ 全都要读或写飞书、OA：自写日报要读日报数据、考核表要读日报＋考勤、下发任务要能写进系统并被人收到、日历要读项目节点。

**接口和权限不在他手上，但他意识不到"拿不到权限"就是卡点** → 卡点栏写"暂无"不是隐瞒。

→ 立项时必须同时问一句：**「这件事要谁给你什么权限？」** 没人给 ＝ 这项做不出来，改期也没用。

### 3. 主管自己也"毫无头绪" —— 这是同一件事的另一面

凡哥原话「我对数字员工毫无头绪」。**领导说不清要什么，执行只能猜**，于是反复打磨唯一猜得准的那项。这不是下属的问题，也不是领导的问题，是"验收标准"缺失。

→ 解这个不需要懂技术：**给每项写一句"验收长什么样"，领导自己能验就行。**

---

## 三、解药：N 项砍成一条闭环

### 选哪条链
**优先选「数据现成 ＋ 省的是主管自己时间」的那条。** 本例＝**日报 → 考核表**（②+③ 本来就是一条链）：

- 数据现成：他们天天在飞书写日报，不用新建系统、不用买接口
- 省的是凡哥自己的时间：月度考核表本来他手工做，跑通第一个受益的是他 → 他最有动力推

这一条跑通，④下发任务、⑤日历的**数据底座也就有了**，剩下的是往前接。

### 时间要拆成两段
「五项全交」按剩余工作日算做不到，就明确拆：
- **第一个节点**：只交那条闭环，用**真实历史数据**跑（例：拿 11 月真日报跑出考核表）
- **第二个节点**：其余项能做多少算多少，**没做的列清单**

### 每项给一句可验收标准（领导不用懂技术）

| 项 | 验收一句话 |
|---|---|
| ② 自写日报 | Agent 写的和他自己写的比：**事实不编、当天活一条不漏** |
| ③ 考核表 | 生成的表 vs 他手填的表：**扣分项差 ≤2 处** |
| ④ 下发任务 | 任务发出去，**被派的人在飞书能收到、能回执** |
| ⑤ 日历 | 打开能看到**每个项目下一个节点＋负责人＋日期** |

判据：**这一段能不能让"不懂技术的人"一眼判过／不过。** 不能就不是验收标准，是愿望。

---

## 四、别用错配人力"一点点试"（最容易犯的补位方式）

**症状**：「让小吴一点一点试着做」。

- 小吴是**前端／UI**：日历、看板那层界面他能做，**agent 逻辑与数据打通他做不了**
- 后果一：用最贵的工时摸最不该他摸的问题
- 后果二：**数据接口没定之前做的界面，大概率要重做**

→ 正确分工：**非核心角色不碰逻辑层**，等接口定了再动手做展示层；逻辑与打通归本职是这件事的人（本例＝小唐，AI 智能体是其本职）。

---

## 五、汇报口径（对凡哥）

**不要写"他慢"。** 写成：

> 「①已完成（还提前）；②③④⑤ 零记录。原因是这四项**还没有"做到哪算完"的定义**，且**数据都在飞书/OA，权限不在他手上**。建议砍成一条闭环先跑通（日报→考核表），给每项一句验收，节点拆 11-24 / 11-27。」

- 先报事实（哪天做了什么、哪项零记录）
- 再报根因（定义缺失 ＋ 权限不在手）
- 再给**一条**建议 ＋ 两个节点
- 末尾**只问一个**决策（要不要按这个改期／要不要先开飞书权限）

---

## 六、复用清单

一个人被派 N 项、周期两三周时，按顺序过：

- [ ] 逐项打勾：有产物／零记录（从台账，不凭日报印象）
- [ ] 对每项问三句：交出来什么样？数据哪来？谁给权限？
- [ ] 三句答不出的项 → 标记"未定义"，**不算他逾期**
- [ ] 选一条"数据现成 ＋ 省主管时间"的链做闭环
- [ ] 给每项一句可验收标准（外行能判）
- [ ] 时间拆两个节点：先闭环演示，后其余
- [ ] 检查是否有非本职角色在"试着做"逻辑层 → 改成等接口
- [ ] 汇报：事实 → 根因 → 一条建议 ＋ 两个节点 → 只问一个决策
