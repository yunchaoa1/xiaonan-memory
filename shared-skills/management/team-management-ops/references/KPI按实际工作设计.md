## 二、怎么改：只填 E 列（openpyxl 要点）

原则：**复制她的文件 → 只写 E 列 → 其余一律不碰**。

```python
import openpyxl, shutil
shutil.copyfile(src, dst)          # 保留她的一切
wb = openpyxl.load_workbook(dst)
ws = wb['全栈工程师']
c = ws['E7']
c.value = "① … → 100 分；② … → 80 分；③ … → 60 分；④ … → 0 分。证据：…"
c.alignment = Alignment(horizontal='left', vertical='center', wrap_text=True)
# 行高按"显示宽度"估：CJK 记 2、ASCII 记 1；每行约 68 单位宽、行高 ≈ 13.2 × 行数 + 4
wb.save(dst)
```

- 原表 E 列的字体/边框已设好（微软雅黑 10、wrap、thin 边框），**只写值与对齐即可**，不要重设样式。
- 长文本必须调行高，否则打印/查看被裁掉；行高原值（33–45）通常不够 4 行文字。
- **不要用自己重建的 xlsx**。本次我先按截图重画了一版，凡哥回"这个是HR这边做的表，按照这个表格去改"——重画版直接作废。

## 三、评分标准四档写法（每项都要有「证据」行）

模板：
> ① …（最好情况）→ **100 分**；② …→ **80 分**；③ …→ **60 分**；④ …（最差/无产出）→ **0 分**。**证据：……**

要点：
- 档与档之间是**可数的台阶**（完成率 ≥90% / 80–89% / 70–79% / <70%），不是形容词。
- 每项证据必须**能当场打开**：架构文档 / 节点清单 / 反馈台账 / 接口文档 / 现场演示 / bug 台账。
- **证据来源就是每日工作日志** → 把日志格式设计好一次，月度评分自动有数（这是 §2 的杠杆）。
- 分数段（100/80/60/0）是**业务判定口径**；等级换算（优/良/合格）与奖惩挂钩**留给人事**，并在表底写明。

## 六、给凡哥讲这张表，必须做人话对照（否则他看不懂）

凡哥原话："这个表的考核内容我有些看不懂"。**交付 KPI 表时必须同时给一张三列对照表**：`原话（HR 的）｜人话（说白了就是）｜你怎么验收（一眼看得出来）`。

- 好用的"验收三问"（让他记住这三句就够）：
  1. **东西在哪？我能看一眼吗？**（要能打开的产物，不要"在做了"）
  2. **换个人照着这个，能不能自己跑起来？**（能＝沉淀了；不能＝还在他脑子里）
  3. **卡在哪？下一版几号给我？**（只问卡点，不问"做到哪了"）
- 还要讲清"表怎么算分"：每项 0–100 分 → 权重＝占总分几成 → **总分＝每项分数 × 权重 相加**；**权重高的项砸了最伤总分**。

## 八、⚠️ 撤销：「发给执行人的自报话术」（2026-09-14 凡哥否掉）

本节原写的是"让执行人自己报本月实际在做的事，再定稿 KPI"。**凡哥否掉了**，原话：
> 「啊？**考核表需要他们实际在做的工作自报吗？我说的哪里还不够清楚？你可以问我**」

**正确口径（取代原话术）**：
- **考核目标由上级（CTO）定**；员工只在**月底做自评打分**（表里本来就有"自评"列），**不参与写自己的考核项**。
- 不清楚项目细节 → **直接问凡哥**（他在，别绕道设计流程让员工自报、也别让凡哥去问下属）。
- 可以要一张**环节 / 页面清单**，用途是任务台账与汇报口径（见 `references/归档与任务台账机制.md` §四），**不是让员工定义自己的考核**。
- 工作内容是浮动的（随时加活）→ 用**工单台账**接住（下发日期／承诺交付日／实际交付日），不要靠"月初清单"（同上 §四）。
- 定稿时仍在**对方原表**上改；**建议改动处挂 openpyxl 批注**（`Comment`），对方一眼分清"建议"与"原文"（同上 §六）。
