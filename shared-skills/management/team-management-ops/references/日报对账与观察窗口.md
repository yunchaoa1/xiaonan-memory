# 日报对账 · 观察窗口 · 战略转向（2026-10-19~29 实测沉淀）

> 适用：每天收到日报入库之后，凡哥问「进展怎么样 / 那几件交没交 / 先观察几天 / 我调整战略了」。
> 前提：日报已在台账里（§8.1 配方），思路是**用已有数据判，不靠再问一遍进度**。

---

## 一、日报入库后的「承诺 vs 证据」对账（三档结论）

**场景**：上周五承诺了 3 件，周一凡哥丢来周五日报 → 他要的不是摘要，是**交没交**。

**四步**：
1. 从台账捞「承诺日＝那天」的行（或会上下发的节点）
2. 逐条到**当日日报的 `内容` 字段**里找**可验证名词**（部署了 / 自动化测试通过 / 打包零报错 / 容器化编排…）
3. 三档落结论：
   - ✅ **完成**：证据充分
   - 🟡 **部分完成**：做了一半，另一半无证据。实例：`已把影视工坊部署在本地` ✓ 但"帧格视界能产出"无证据
   - 🔴 **未达**：日报里只有细项、**没碰承诺的主体**。实例：承诺"人事三块（考勤/工资条/绩效）落地"，日报全是"工资单消息文本优化 / 签名文件查询 / 修 bug"
4. **判不了的单拎一条问凡哥**（"这是唯一靠日报判断不了的一条"），不自作判断
5. 台账状态同步（已完成 / 部分完成 / 未达（超期）），备注写证据原话

**判据**：验收看**产物**，不看"完成"两个字；**同一承诺连续两天只出现细项 = 实质未达**。

## 二、「卡点蒸发」识别（比"卡点写无"更隐蔽）

- **形态**：D1 报实质卡点（例："本地图片生成效果不理想，容易出现幻觉与违背指令 → 考虑更换 API"）→ D2 `卡点` 写"暂无"、`解决` 写"暂无"，**且没提怎么解决的**
- **三种可能**：① 偷偷换方案/已经花钱了 ② 绕过去了 ③ 干脆不报了
- **做法**：不替他想，原文照登 + 报一句「这个卡点是怎么处理的」给凡哥去问
- **台账备注写法**：`⚠️ 10-27 报的 X 卡点本日变"暂无"，未说明如何解决 ＝ 卡点蒸发`

## 三、观察窗口法（凡哥说「先观察 N 天他们的进展」）

**铁律：「观察」必须能判定，否则就是拖延。**

落地四件：
1. 待办挂一条 `★ 回头看 X（观察 N 天）→ 决定是否出清单`，截止＝N 天后那天
2. **观察点写死 3 条**（本次用的三条，可直接复用）：
   - ① 日报里有没有**具体动作**（选了方案/技术栈、拉了哪些数据、切了多少文档）—— 而不是"开始研究了"
   - ② 有没有**能被别人用的产物**（哪怕一个粗糙的问答 demo）
   - ③ **有没有把别的线挤掉**（他手上其他承诺还交不交）
3. 到点必须给**三选一结论**：继续放手 / 出最小可用清单 / 换人做
4. 中途有值得说的（真动手了 / 明显在绕）**当场说，不等到窗口结束**

**本次实例**：小唐 10-27「读代码＋装 Docker＋准备 RAGFlow 工具」＝动手 ✓ / 无产物 ✗；10-28「下载镜像＋配置 RAGFlow」＝仍无产物，且工资单线当天一个字没写 → 结论「出清单」。
→ **判断口径**：路线选对 + 人在动 + 连续两天纯环境搭建 = **不是换人，是给标准**。

## 四、观察期结束要给的「最小可用版清单」怎么写

四步，**每步一个过线标准**，另加硬要求＋里程碑＋三个坑：

| 步 | 内容 | 过线标准 |
|---|---|---|
| 数据源 | 只用最核心那一类；**先拿 50 条** | 50 条能导成一张表，关键四列对齐 |
| 怎么切 | 一个单元＝一个块，**禁切两半** | 随便抽一块能看懂它是哪一条 |
| 怎么找 | 取最相关 top5，**答案必须带出处** | 问 10 次，9 次找对 |
| 怎么算行 | 用 50 条真实样本测，**只记三个数**（答对数 / 出处对不对 / 瞎编几次） | 瞎编目标 = 0 |

**硬要求（关键）**：
- 给死时间点必须**有一个能用的东西**（命令行也算，50 条也算）
- 日报**禁写"配置了 XX / 下载了 XX"**，必须写"库里多了几道题 / 答对几道"
- 里程碑三段：能答一次 → 测三个数 → 按结果定扩不扩

**三个坑**：① 先搭平台再想数据（平台越大越不敢灌）② 一次性全灌（错了查不出哪块）③ 不做出处（答不上"为什么是这个答案"就等于没用）

## 五、战略转向怎么处理（凡哥一句「我调整战略了」）

**凡哥原话样本（2026-10-29）**：「周二调整了战略部署，下周一我要求影剧工坊 2.0 要落地，现在全力配合小李搞定 2.0，**要人给人要钱给钱**。」

**四步**：
1. **原话入册**（台账一行，`来源`＝凡哥口述＋日期，状态＝进行中）
2. **出「让位清单」**：哪条线停 / 退到维护 / 后移 —— 逐条给状态。**他要的是副作用清单，不会自己列**
3. **把授权翻译成对方的动作**：「要钱给钱」→ 让对方报三件（**用哪家 / 按张还是按月 / 上限多少**），否则他拿了授权也不敢动
4. **逼出验收标准**（见下）—— 不定就等于没交付

---

## 六、「落地」必须拆成 A / B 两种验收

- **A 技术验收**：能独立跑通全流程、出一条成品，全程不用人手改
- **B 业务验收**：交给**真实使用方**，他们**自己操作**做出一条能用的东西

**问法**：「"落地"按 A 还是 B 算？」本次凡哥选 **B**。
差别：A 本周就能做到；B 要使用方配合时间。**A 过 ≠ B 过**，验收前必须问清，否则验收会吵。

## 七、月末考核原材料怎么从台账聚合（不凭印象）

按人聚合当月 `work_date`，输出**四指标 + 按周分段**：

| 指标 | 取法 | 能量出什么 |
|---|---|---|
| 日报天数 | 不同 `work_date` 计数 | 出勤/交付节奏 |
| 条目数 + 项目分布 | 计数 + `项目` 分组 | 负荷与跨项目程度（一人一天多项目已拆行，天然可聚）|
| **写了实质卡点的条数** | `卡点` 不是空/"无"/"暂无" | **日报质量**（最有效的一个数）|
| **补交次数** | `备注`/`来源` 含"补交" | 提交纪律 |

- **按周**：W1/W2/W3（以周一为界）→ 直接对上「每周计划 vs 实际进展」的考核口径（§8.10）
- 再叠：**承诺兑现核对**（`承诺` 非空的行逐条看 `状态`）+ **跨月未达单列**
- 产出：每人一页（本月主线 / 承诺核对 / 卡点质量 / 下月关键）＋ **供参考初判**
- ⚠️ **评分尺仍由凡哥定**（§1.5）；初判只写"供参考，不写进正式结果"
- ⚠️ 聚合前**先把台账状态同步到事实**（该已完成的改已完成、该未达的改未达），否则原料本身是错的（改完照 §改账铁律 回读）

**本次实测数字（10 月 · 4 人 · 各 11 天日报）**：条目 11 / 19 / 12 / 11；实质卡点 2 / 4 / 0 / 1；补交 1 / 1 / 3 / 0
→ 一眼看出：**条目最多的人卡点写得最好；产出最大的人日报最差** —— 两个维度必须分开看，不能用一个数排名。

## 八、日报把项目名写错 → 按正确项目归，原文留痕

- **实例**：小吴 10-21 日报写"影剧工坊"，实际是**浪浪椰**（凡哥纠正）；另一例是 ASR 把"智提分 1.0"混成"浪浪椰 1.0"
- **正法**：台账按**正确项目**入库，`备注` 保留 `原文写错"影剧工坊"（凡哥 10-22 更正）` → 可追溯、不算他撒谎
- **判据**：夹在项目归属纠错里，**先看内容像哪个项目**（金币/提现/追剧/播放器手势＝浪浪椰），再落账
- 同一份日报跨天补交时，内容**归工作日**，并把"补交"写进备注（§2.1）

## 九、待办 JSON 写入的守卫坑（本次踩了两次）

- **坑**：幂等守卫用**宽泛关键词**会误命中历史已完成条目 → 新待办被**静默跳过**
  （实例：`if not any("智提分知识库" in t["项"] ...)` 命中了 10-12 那条"帮小何搭智提分知识库"的**已完成**条 → 新条没写进去）
- **正法**：守卫用**新条目独有的短词**（如 `"知识库搭建（小唐配合"`），或先 `print` 所有含关键词的条目再决定
- **写完必须打印复核**（两次都是靠 print 才发现没写进去）
- 另：**另一端/另一个会话可能同时在改这两个 json** → 读-改-写窗口要小，改完 `json.load` 回读；mtime 先看一眼
