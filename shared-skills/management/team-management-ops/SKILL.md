## 0. 交付纪律（三条硬规则，先过这三条再动手）

1. **先问清三件事**：谁要？要什么（**几样**）？什么格式？——对方没说的**不主动加**。
   ⚠️ 素材 vs 制度的边界 = `working-with-fange` 的「跨部门/跨职能交付边界」（2026-09-13 凡哥纠正：给 HR 全套考核制度 = 越界）。
2. **人话优先**：给凡哥的版本必须是大白话，专业术语先翻译（见 `working-with-fange`「交付语言：人话优先」）。
3. **不主动产出"成文攻略"**（2026-09-15 凡哥：「我说过，我只是**在遇到问题时会向你请教**，我**并不需要任何的攻略文本**，可以删掉了。」）：
   - 凡哥要的是**一问一答的陪伴**，不是一套方法论教材；管理者的时间不会花在读攻略上。
   - **攻略 / 指南 / 教材类文件不要主动写、不要顺手扩写**；他要的是**当时那一刻能用的东西**——一张表、一段话术、一条命令、一页纸。
   - 判断问句：这份东西的功能是"**教他怎么管理**"（→ 别写），还是"**他今天要交出去 / 要照着做**"（→ 写）？
   - 已经交付过的攻略会被要求删除（本次连同 `CTO攻略_*.docx`、人话对照表、多个中间版本一起删）——**别把它当资产守着，也别在后续会话里"顺手补一份"**。
   - 删除时说明：删的是**攻略类**，留下的是**工作里真在用的**（考核尺子 / 台账 / 归档规则 / 模板 / 给人事的素材 / 给豆包的稿子），并同步清理 `DASHBOARD.md` 里的交付物清单（否则留死链）。

## 1. 绩效考核内容怎么写

**一句话公式：这个人这段时间要交什么（能数出来）＋ 交到什么算好（能查）＋ 数据从哪来（谁记）。**

### 1.0 ⚠️ KPI 必须从「他们实际在做的事」长出来（2026-09-14 凡哥纠正："KPI要根据我们实际工作内容来设计"）

**两种错法（都被抓过）**：
1. **用通用软件词**：架构设计 / 数据库与 API 设计 / 单元测试 / 联调 —— 那是软件公司模板，不是这两个人每天干的活。员工一看就知道写表的人不懂他在干嘛。
2. **两个人共用一张 KPI 表**：分工不同（前端 / 后端）→ KPI 必须分开写，换岗就跟着换。

**正法**：**KPI ＝ 他们每日日志里出现最多的那几件事 ＋ 每件事能交出来的东西。**

**考核目标由上级定，不是让员工自报**（⚠️ 2026-09-14 凡哥纠正，原话："啊？考核表需要他们实际在做的工作自报吗？我说的哪里还不够清楚？你可以问我"）：
- 员工只在**月底做自评打分**（表里本来就有"自评"列），**不参与写自己的考核项**。
- 你（CTO）不清楚的项目细节 → **直接问凡哥**；别设计"让员工自报工作内容"的流程，那既越位又给自己挖坑。
- 可以向执行人要一张**环节 / 页面清单**（那是"了解项目"的原料），用途是台账与汇报口径，**不是让他们定义自己的考核**。

**按分工重排的表现层**：后端（小何＝整体框架+后端）看**接口/数据/核心能力/自测**；前端+UI（小吴）看**页面实现/设计稿/还原度/联调/资产归档**。
通用软件词 → 实际工作话术的对照表 + 评分标准四档写法 + 本次实例，见 `references/KPI按实际工作设计.md`。

### 1.1 对方给了现成表格 → 她的表就是底稿（不要重画）

人事/其它部门给了自己的表（本次：`全栈工程师&UI…绩效考核表.xlsx`，14 列 + 两轮考核）时：

1. **只填属于业务的列**（如「评分标准」；KPI 描述也是业务内容）——**权重、公式、合并单元格、列宽、格式一个字不动**。
2. **不要按截图/截图式需求自己重画一张**：会和她的表打架，凡哥要的是"在她的表上改"。
3. **她表里的问题不代改**：权重合计不到 100%、错别字、多余空格 → 整理成「**待确认 N 处**」＋ 一句可直接发出的话术（开头放低、结尾留口子，见 `working-with-fange` 跨部门边界），让她自己改。
4. **评分标准四档写法**：`100 / 80 / 60 / 0`，档档可验证，每项末尾附一行「**证据：……**」——证据就是每日日志里的东西（台账 / 清单 / 文档 / 现场演示）。

- **禁用词**：态度好、执行力强、配合度好、有责任心、积极主动 —— 无法验证，人事也没法算钱。想到这类词 = 还没落到"能数出来的事"。
- **标准骨架（4 项 / 权重 100）**：交付 40 ｜ 阶段节点 25 ｜ 质量 20 ｜ 沉淀 15。
- **四档评分**：优 90–100 ／ 良 80–89 ／ 合格 70–79 ／ 待改进 <70。
  **分数与奖惩的挂钩方式由人事定**，CTO 只出业务内容（越界必被纠正）。
- **每个档位必须写清阈值**：如"按时完成率 ≥90% 优 / 80–89% 良"；"同一稿改稿 ≤2 轮优 / 3 轮良"。
- **小团队（2–5 人）**：不搞互评、不堆指标，4 项封顶。
- **考核项必须期初公布**（或入职时告知）；月末临时定 = 员工有异议 + 人事难处理；**试用期更要把标准提前写清**（否则想辞人都没依据）。
- **中途启动的月份**（如 13 号才定 9 月考核）：不挂钩奖惩，只做事实记录，下月起正式按月考核。
- 模板：`templates/月度考核表_骨架.md`；本次实例：`references/绩效与日志设计.md`；**按实际工作重写 KPI ＋ 在对方原表（14 列）上只填「评分标准」列的完整配方：`references/KPI按实际工作设计.md`**（含通用软件词→实际工作话术映射、四档评分标准写法、openpyxl 只改 E 列＋给建议改动挂批注的做法、待确认清单话术）。

### 1.2 评分制度：全部正向（减分制已撤 · 2026-09-14 凡哥定）

- **一套正向评分**：做到给满分，做不到往下走。**不做减分/扣分表**。
- 凡哥原话①：「减分制只能用在这些"规范动作"上。平台功能、工作流打通、AI 能力接入这类交付活不能用减分制——不然他们会**只求不出错、不敢往前冲**。交付用"做到给满分"，规范用"出错才扣分"。」
- 凡哥原话②（随后改主意，以此为准）：「**我们还是恢复到原来，只是这个月没有归档的话，就算满分来算**。」
- → **归档/规范项：本月没有事项 = 直接满分**（这一项不考核）。
- → **交付类永远不用减分或倒扣**。
- 归档项正向档位：换人照着能用 **100** ／缺小步骤 **80** ／缺关键步骤或迟交 3 天内 **60** ／迟交超 3 天 **40** ／没交 **0**。

### 1.3 凡哥原则：不为了打分而增加记录动作

凡哥原话：「跟工作结果没有太大关系的没有必要去设计，反而**增加工作量和精力**。」
→ **验收只看产物**：当场点页面 ／ 并排看设计稿 ／ 走一遍主流程。
据此已删：**走查记录**（UI）、**出片案例**（「**出片是别人去试，不是他来试**」）；**故障修复记录 + 维护迭代记录已合并**为「故障与维护记录」。**别再把它们加回来。**

### 1.4 归档规则 + 考核三支柱（摘要）

- **项目结束的定义**：**正式部署到服务器、并正式可以使用 = 结束**（之后只有维护和迭代）；"第一版可演示"**不算**结束。
- **四个触发点**：① 日常日志 ② 阶段里程碑＝阶段小结（过程留档）③ **项目结束＝《项目归档文档》（设计／如何落地／说明）** ④ 之后每次维护迭代＝记录加一行。
- **归档验收铁标准**：**换一个没参与的人，照「如何落地」能不能独立走一遍** —— 不能就退回重写。
- **三支柱（凡哥定：按 流程／资产／数据 考）**，每人三类**各至少一条**考核项；公司是「**壳 + AI**」模式（给 AI/智能体搭外壳，**不自研算法/模型**）→ KPI 里不写"核心算法实现"，写 **「Agent 能力接入与跑通」**。
- 完整规则（归档三段模板、写错对照表、台账机制、批注做法）：`references/归档与任务台账机制.md`。

### 1.5 考核表 = 定性的尺子；项目由执行者自己填（凡哥 2026-09-14 定）

凡哥原话：「考核表我觉得应该是**定性**的，每个月项目不同是**应该让执行者自己写进去的**。」

**分界（关键，别搞反）**：
- ✅ **执行者可以自己写「我做了什么」**（本月的项目与交期）
- ❌ **不能自己写「什么算好」** —— 尺度必须**主管**定，否则**人人给自己定满分**
- 与 §1.0「考核目标由上级定」不矛盾：**结构 / 尺度由上级定，本月具体项目与交期由执行者填。**

**一张表三层**：

| 层 | 内容 | 谁定 |
|---|---|---|
| **A 定性考核标准** | 维度 ＋ 权重 ＋ 评分尺度（100/80/60/0） | **主管**（**每月不变**、不写具体项目名、**不写本时段在做的事**） |
| **B 本月项目与任务** | 项目 / **项目节点** / 下发 / 承诺 / 实际 / 状态 / 卡点 | ★**执行者本人填**（活一来就写一行） |
| ~~C 本月得分~~ | **已删除**（凡哥 2026-09-23 亲自在李林表里删掉整块 → 其余三份照做；注上移到 **第 22 行**、`max_row`＝22）→ **算分归小南**：月底出汇总时按台账给每人算分，表里不再留 C 层 | — |

**★ 凡哥整改①（2026-09-23）：B 层「项目」后面加「项目节点」——按节点考核，不按整体项目**
- 凡哥原话：「每一项工作按照项目中的**一个节点**来进行考核，不然按整体项目进行考核**目标感太大了，没办法做到精确考核**。」
- → B 层字段固定为：**项目 → 项目节点 → 下发日期 → 承诺交付日 → 实际交付日 → 状态 → 卡点 / 原因**（表留 10 行空白待填）。
- 表同时带 **自评说明 / 自评分数 / 上级评分说明 / 上级评分** 四列（执行者月底自评；**尺度仍由主管定**，见 §1.5 分界）。

**★ 凡哥纠正②（2026-09-23）：A 层维度＋权重「每个月都不变」**
- 小南曾把新同事"本时段在做的事"（多 agent 体系 / 上下文治理）写进 A 层 → 被纠正：**具体在做的事一律进 B 层，A 层只放长期稳定的维度与权重**。
- 新人（小唐 / 小李）A 层 ＝ 与全员**完全同一套五维**（见下方终版骨架），**没有各自的角色化维度**——"多 agent 体系 / 上下文治理"这类**本时段具体方向一律进 B 层**。
- **新人考核落地三件（2026-09-23 实测缺口）**：① 凡哥定「**要考核**」→ 两位新人 09-23 到岗也**计 9 月**（表头保留「9月项目填报」）；② 但**考核窗口只有 09-23~09-30**，而 ① 的原料是"承诺任务 → 有没有交" → 必须**提醒凡哥各下发 1–2 条带「承诺交付日」的任务节点**，否则 B 层空着、① 无原料可评；③ 日报通知**不覆盖考核表**——新人还需知道"**按项目节点填 B 层**"（补一段话术或并进通知）。
- 新人 9 月**没有归档任务** → **③ 项目完结归档**按「本月无项目完结＝满分」走，**不影响得分**（别主动给他们加归档项）。

**在凡哥整改过的底稿上派生新表（本次实测配方）**：`何锦波绩效考核（2026年9月）.xlsx` = **凡哥亲手整改的底稿** → 其余人的表 = `openpyxl.load_workbook(底稿)` → **只改文本**（A1 标题、A4–A7 维度名、C4–C7 评分标准、页签名）→ **另存**：合并区（本次 30 处）、公式（`=SUM`/`=B4`/`=D23*B23`）、列宽、行高**全部自动保留**。⚠️ 别自己重画版式、别新建工作簿。

**★ 凡哥的常态改法（2026-09-23 实测，比上面这条更常用）**：他**随手在某一人的表上改**，然后说「**我在 XX 的表里做了细微改正，对照 XX 的表修改其他的**」→ 三步固定：① `openpyxl` **读回那一份**（全部单元格 + 合并区 + `max_row`）② **与自己发出去的版本逐字 diff**，把他的改动抓出来（本次＝去括号 + **删掉 C 层整块**）③ 改动**同步进生成脚本**、四份重生成，再做程序化逐字比对（`A4:C8` 文本 + `max_row` + 注行位置）。**没 diff 出改动就别猜，更别顺手改他没动的地方。**

**★ 维度骨架（2026-09-23 凡哥终版 · 四人完全同一把尺子）**：

| 维度 | 权重 | 尺度（四人一字不差） |
|---|---|---|
| ① **交付质量** | **40%** | 交付后基本不返工、无重大问题，**关键链路当场跑通且同输入同结果** → 100；能出结果但需人工干预 → 80；时好时坏或返工 3–4 次 → 60；跑不通或返工 ≥5 次 → 0（凡哥 2026-09-23：「关键链路（工作流/agent）这个我没明白」→ **括号已删，别再加回去**） |
| ② **交付时间** | 20% | **按超期工作日分档（每 2 个工作日一档）**：按期交付（实际 ≤ 承诺交付日）→ 100；**超期 1–2 个工作日 → 80；超期 3–4 个工作日 → 60；超期 5 个工作日及以上 → 0**（凡哥 2026-09-23 终版原话：「交付时间按照**超时多少天**计算，我举得**两个工作日为一个扣分范围**」） |
| ③ **项目完结归档** | 15% | 项目完结时交齐**原始代码 + 项目说明书**且审核通过 → 100；交齐但说明书缺节 / 照着跑不起来 → 60；只交代码、无说明书 → 0（**本月无项目完结 → 按满分**；正式部署后的维护迭代同样要归档） |
| ④ **跨部门协同** | 15% | 有正向口碑留痕（对接部门/对方主管反馈配合顺畅）→ 100；**无留痕 → 按满分**；有负面留痕（拖后腿/沟通不畅被反馈）→ 50；因沟通配合致跨部门工作明显受阻 → 0（**不由员工自报**） |

## 3. 盯节点六条规矩（CEO 教的那招的完整版）

CEO 原话：**执行人报时间 → 盯时间 → 到点要结果 → 总结难点卡点 → 开第二轮**。出处=阿里基层三板斧「定目标·追过程·拿结果」，是好招，缺三块要补：

1. 一件事只有**一个责任人**，不写"大家"。
2. 必须有**交期 + 中间看一次**。
3. 到点没做完 → 只问"**卡在哪**"＋"下一轮几号交"；**不问"做到哪了"**（那只会换来编造的进度，施加压力=负杠杆）。
4. **报时间的权力分人**（格鲁夫·任务相关成熟度）：这块活他比你懂 → 让他报；没做过 → **你自己给时间并把活拆小**（新人一定注水时间）。
5. **同一个坑踩两次 = 管理者的责任** → 写一条规矩。
6. 每周每人 **30 分钟一对一，议程由下属定**（人少时性价比最高：5 人 = 2.5 小时/周）。

### 3.1 月度任务台账 —— 工作内容是浮动的时候，考核靠它兜住（凡哥 2026-09-14 定的机制）

**凡哥的问题（原话）**：工作安排**不是**月初月末才加，**随时都会增加工作内容**；所以月度考核应该**先列本月有哪些项目、什么时候下发、预计什么时候交付，然后才是实际交付、卡点，再在交付过程里去考核**。

**解法：下发即登记的任务台账**（`D:\Documents\我的文档\CTO攻略\月度任务台账_模板.xlsx`）
字段：序号｜项目｜任务内容｜**下发日期**｜**承诺交付日**｜**实际交付日**｜状态｜改期次数｜卡点/原因｜负责人

① 随时加行（下发即登记）② 中途加的活**当场定交期** ③ 改期留痕但**不直接扣分**（改期次数是**辅导点**）④ 本月未完成**滚下月标"跨月"** ⑤ 月底**冻结、只统计不新增** ⑥ 考核只数两个数：**按时交付率 + 卡点处理**

- **为什么站得住**：这是 CEO 那套「报时间 → 盯时间 → 要结果 → 总结卡点 → 开下一轮」的**表格化**，也是"承诺 vs 交付"的可数化。
- **一份表三用**：HR 日志原料 ＋ 月度考核数据 ＋ 给 CEO 的一页纸周报 → **不额外增加记录动作**（守住 §1.3 原则）。
- **谁维护**：执行人各自填自己的行（承诺日期他填、实际交付验收后填）；CTO 只做两件事——**派活、验收**。
- 完整规则与本次实例：`references/归档与任务台账机制.md` §四。

## 4. CTO 记分卡（凡哥问"什么算当好"、且他自己没标准时用这张）

**一集几天出 ｜ 返工几次 ｜ 一集多少钱（单分钟成片成本）｜ 几件事不用我也能跑通**

- 最后一项最值钱：从 0 涨到 3，比亲自多出 10 集更有价值（也是投资人真正会问的）。
- 凡哥曾说"没有技术是必须守住的，只要结果就好"→ **需纠正**：结果要可复现，前提是必守三类：①口径与规格（规格/命名/验收标准）②关键资产的唯一副本与权限 ③单点人（只有他会的事要有步骤+备份人）。换技术不伤人，口径飘移和"只有一个人会"才伤人。

## 5. 对上汇报（CEO 一页纸）

结构：三个项目各一行（状态 / 下一步 / 卡点 / 负责人）＋**我需要你决策的一件事**＋我发现的**风险**。
- 风险报法 = **事实 + 影响 + 两个选项**。例：「小何一人扛 OPC 与智提分两条线（事实），任一条延期会互相拖（影响）；要么补一个人，要么把漫剧发布平台推迟（选项）」。
- ⚠️ **单点风险写进给 CEO 的汇报，不写进员工考核表**。

## 6. 前置动作（每次做考核/汇报前先做）

让每个负责人交一张 **"环节清单"**：这个项目有哪些环节、每环节什么状态、谁负责。
**一张清单同时解决三件事**：考核项的分子分母、日志的环节名、汇报的进度口径。没有它，三件事都靠猜。
⚠️ 清单的用途是**台账与汇报口径**，**不是让员工写自己的考核项**（§1.0）——考核目标由上级定，别让"要清单"变成"让他们自报考核"。凡哥手头没有的（如 OPC 平台环节），是他去跟业务方（林总）要，不是让下游编。
