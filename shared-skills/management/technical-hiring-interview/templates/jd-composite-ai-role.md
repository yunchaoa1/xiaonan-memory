# 复合型技术岗 · 招聘文案骨架（BOSS 直聘可用）

> 用在「市场上没有这个合成岗、得自己造名字」的场合（如运维＋AI 开发、算法＋工程、全栈＋运维）。
> 结构固定四块：**干什么 / 要什么人 / 会什么优先聊 / 我们能给什么**。
> 每块都用大白话，不写「负责相关业务支撑」这种看不懂的话 —— 凡哥的尺子是「我看得明白」。

## 一、表单字段

- 职位名称：`<自造的合成岗名>`，例：AI 应用运维工程师（AI 开发 ＋ 服务器运维）
- 职位类型：技术 / `<方向>`
- 工作城市：`<城市>`（允许异地就写「可远程/可异地」）
- 薪资范围：`<区间>`（口径见 SKILL.md：四合一别按单技能价挂，会招不到人）
- 经验要求：`<2-5 年>`
- 学历要求：`<大专及以上>`
- 招聘人数：`1`

> 岗名要**覆盖两种搜索习惯**：一个挂「AI 应用运维工程师」，一个挂「AI 模型部署工程师」之类，两份比一份捞得全。但**先只发 1 个**，跑起来看投递量再补。

## 二、职位描述（整段可直接粘）

我们做 `<业务一句话>`，`<哪些东西>都归技术部管`。
现在缺一个人：`<一句话说清这个岗最硬的两件事>`。

**你要干的事**

1. `<职责 1：日常运维——部署/监控/备份/故障定位>`
2. `<职责 2：把 AI 应用跑起来——接模型 API、部署开源模型、接进现有系统>`
3. `<职责 3：配合上线——打包、发布、回滚、看日志>`
4. `<职责 4：把重复的活写成脚本>`

**我们要的人**

1. `<年限 + 硬技能，要具体到工具名>`
2. `<容器/部署能力>`
3. `<AI 侧最低门槛：用过某类 API 或跑过某类开源模型>`
4. `<脚本能力：Python 或 Shell>`
5. `<态度项：出问题说得清原因，不甩锅>`

**会这三件我们优先聊**

1. `<信号 1 —— 对应筛子第一句>`
2. `<信号 2 —— 对应筛子第二句>`
3. `<信号 3 —— 对应筛子第三句>`

**我们能给什么**

- 一个人管全线，不分工等着，做出来的东西直接上线给真实用户用
- 技术选型你自己定，别拿没跑过的方案糊弄人就行
- 事少、话少、不打卡式管理，交付说话

## 三、有人来打招呼，第一句这么回（复制即用）

你好，我们是做 `<业务>` 的，正在招一个人 `<这个岗最硬的两件事>`。
方便先回我两个问题吗：
1. `<筛子第一句，改写成问句>`
2. `<筛子第二句：让他讲一次真实故障/真实项目，讲不出细节的当场露底>`

> **为什么是这两句**：一问「有没有摸过真东西」，二问「有没有独立扛过事」。真干过的会讲具体故障，只调过 API 的会说「没遇到过」。

## 四、内部筛人判据（不发出去，写给自己看）

- **三句筛子占两句以上** → 两边都碰过，值得聊。
- **只写「调用 API」、没跑过开源权重的** → 直接过。这类人是提示词调参工，服务器一出事就干等。
- **只写「熟练 Linux」、说不出一次故障定位过程的** → 也过。真运维有故事，假的只会说「重启一下」。
- 简历里的**具体数字**（多少张图／多少步／显存多大／一轮多久）拿来做第一道题，答不出显存和成本的基本是包装的。

## 五、发出去之后

1. 每天固定时间看一次新投递，别等积压。
2. 初筛按上面四条过一遍 → 挑 3-5 个给凡哥，**别一股脑全推**。
3. 面试先问「故障定位」那题，五分钟能分出真假。
