## 二、判定框架：分水岭算法（核心工具）

```
自建月固定成本  ÷  API 每百万 token 混合价  =  盈亏平衡的月用量
```

**自建月固定成本**（以 8×H200 为例，2026-10 口径）：
- 整机 150 万 ÷ 36 个月 ≈ 4.17 万/月
- 加电费、机房、运维 ≈ **5.2 万/月**（粗算，需按实际机房核）

**API 混合价**（DeepSeek 官方，2026-09-10 起，高峰价，输入:输出≈4:6）：
- 输入（未命中缓存）2 元/百万，输出 8 元/百万 → 混合 **≈5.6 元/百万 token**

**→ 分水岭 ≈ 900～1000 万 token/月。低于这个数，买机器必亏。**

### 换算成凡哥听得懂的单位（重要）

他不用 token 思考，用**部数**。每次都要换算给他：

| 单位 | 数值 |
|---|---|
| 一部 25 集短剧的**纯文本**环节 | **50～110 万 token ≈ 300～600 元** |
| 分水岭折算成部数 | **每月 8～18 部剧** |

**必须同时给区间 + 说明「这个数要用你自己的账单校准」**——他有 DeepSeek 后台，一除就准。

## 三、经营杠杆（凡哥最该听的一段）

自建 = **把变动成本换成固定成本**。

| | 走 API | 自建 |
|---|---|---|
| 客户来了 | 花钱 | 不额外花钱 |
| 客户跑了 | 不花钱 | **照烧不误** |
| 上升期 | 成本随量涨 | **赚得更狠** ✅ |
| 下滑期 | 成本随量降 | **亏得更快** ⚠️ |

**话术**：生意往上走时自建让你赚得更狠，往下掉时让你亏得更快。上升期自建合理，但必须先想清楚「客户掉到多少台机器就是纯亏」。

**推论**：告诉凡哥「先卖后买」——先用 API 把量跑起来，等月用量稳定压过分水岭再买。反过来做是先押一笔钱赌一个没验证的量。

## 四、AI 短剧全流程 token 拆账（凡哥的 OPC 业务就靠这个）

### 4.1 三个官方/实测口径（都对得上，互相验证）

| 来源 | 数字 | 性质 |
|---|---|---|
| **中国信通院**《词元经济发展研究报告（2026年）》 | **单集 1.5 分钟 AI 短剧，词元消耗 500 万～1000 万** | 官方报告，**全流程含视频** |
| **DataEye 实测**（钛媒体 2026-04-08） | 25 集**纯剧本** ≈300 元；整部剧含视频 **1～1.5 万元** | 实测账单 |
| **抖音平台**（界面新闻 2026-10） | 一部 12 集 AI 短剧，算力成本 **近 20 万元** | 精品仿真人剧 |
| 流媒体网（2026-06） | 1 分钟 AI 视频 ≈ 百万级 token；一部 AI 漫剧可达**上亿** token | 行业口径 |
| 中文在线 | AI 仿真人剧 token = 漫剧的 **2～3 倍**（1080p vs 720p、抽卡重试） | 上市公司披露 |

**行业占比**：国内 Token 消耗中，AI 短剧+视频生成 **55%**、电商营销 24%、软件开发仅 **15%**。

### 4.2 关键：三块成本口径不一样（凡哥 2026-10-21 专门追问过）

| 环节 | 按什么计费 | 进不进「词元」统计 |
|---|---|---|
| 写剧本、拆剧本、写提示词（用 LLM 写） | LLM 文本 token | ✅ 进（但占比极小） |
| **视频生成**（Seedance 等） | **按视频 token** | ✅ 进（**这才是大头**） |
| **生成图片**（场景图/角色图） | **按张**，不是 token | ❌ **不进** |
| 提示词、参考图、参考音频（传进 Seedance 请求的） | **不计费** | ❌ 不进 |

→ **反直觉但要讲清**：视频算 token，图片不算；文本提示词传进视频模型也不收费。

### 4.3 Seedance 视频 token 公式（官方计费口径）

```
video tokens = (输出秒数 + 参考视频秒数) × 宽 × 高 × 24 / 1024
```

16:9 每秒固定 token 数：

| 分辨率 | 每秒 token |
|---|---|
| 480p | 10,044 |
| 720p | 21,600 |
| 1080p | 48,600 |
| 4K | 194,400（仅 Seedance 2.0） |

**验算 1.5 分钟一集**：720p 一条过 = 194 万；1080p 一条过 = 437 万；1080p 抽卡 2～3 次 = **870～1,300 万** ← 正好落在信通院 500～1000 万区间，说明信通院那个数**几乎全是视频**。

### 4.4 一部 25 集剧的最终拆账（直接可用）

| 环节 | token | 折钱 | 占比 |
|---|---|---|---|
| 写剧本 / 拆剧本 / 写提示词 | 50～110 万 | **300～600 元** | **≈3%** |
| 视频生成（1080p，抽卡 2-3 次） | 2.2～3.3 亿 | **1～1.5 万元** | ≈97% |
| 生成图片 | 不计 token（按张） | 几百～几千元 | 另算 |

> **这条结论决定一切**：自建 DeepSeek 只能压住那 3%，视频那 97% 只能走平台 API，自建不了（模型不开源，开源也要大得多的机器）。

### 4.5 所以必须反问凡哥一句

**「OPC 卖出去的东西里，视频是他们自己出，还是你这边出？」**
- 只卖剧本/分镜/提示词（纯文字交付）→ 自建值，1～2 台够
- 一条龙连视频一起出 → 文字自建省的钱会被视频账单淹没，重点该放在视频算力上

### 4.6 纯文本环节到底多少 token —— 社区没统计，按剧本字数倒推

**查证结论（2026-10-21 中英社区翻遍）**：**没有任何机构统计过「写剧本 / 拆剧本 / 写提示词」这一段的纯文本 token**。信通院、DataEye 的公开数字全是**全流程口径（含视频）**。所以别浪费时间找现成数，直接按剧本字数倒推——凡哥有 DeepSeek 后台账单，一除就准。

**倒推公式**：
- 成稿字数 × 1.5 ＝ 输出 token（中文约 1 字 1.5 token）
- 总用量 ＝ 输出 token × **6～11 倍**（拆每一集都要重新带大纲/人设/前文摘要 ＋ 自检重写 ＋ 分镜提示词）
- 一部 25 集 × 3000 字 ＝ 7.5 万字 → 输出 ≈11 万 → **总用量 70～120 万 token**

**折钱（deepseek-flash 官方价，2026-10-21 从 api-docs 抓的实价）**：

| 计费项 | 空闲时段 | 高峰时段 |
|---|---|---|
| 输入（命中缓存） | 0.02 元/百万 | 0.04 元/百万 |
| 输入（未命中） | 1 元/百万 | 2 元/百万 |
| 输出 | 4 元/百万 | 8 元/百万 |

（并发上限：deepseek-flash **2500**、v4-pro **500**；v4-pro 单价约为 flash 的 3～4.5 倍，能不升就不升）

| 用法 | 一部剧成本 |
|---|---|
| 高峰价、不优化 | **≈290 元** |
| **开缓存命中**（同一部剧的设定/大纲反复复用） | **≈150 元** |
| 空闲时段 + 缓存 | ≈60～100 元 ⚠️ 见下 |

→ **290 元跟 DataEye 实测的「25 集约 300 元」对得上，公式可信。**

**100 个 OPC × 每人 4 部/月（400 部）**：不优化 **11.6 万/月**；开缓存 **≈6 万/月**。对比自建一台 5.2 万/月 → **优化过的 API 比自建便宜。**

**⚠️「排到空闲时段」这条对他不适用**（凡哥 2026-10-21 直接否掉：「**OPC 在什么时间生产我们不可能去规定他们**」）。**不可控的变量不许进方案，哪怕它省钱。** 剩下只有缓存优化能走，而且改代码就能实现、零成本。

**客户时间不可控还带出一个硬伤**：自建机器白天被集中提交打满、夜里空转，**按峰值配平时浪费、按平均配一忙就崩**。要顶住波峰得配 1.5～2 台，月成本抬到 8～10 万 → 分水岭跟着抬到 **≈530 部/月（≈130 个客户）**。这条一定要摆给凡哥，它才是「为什么现在还不该买」的真正理由（不是单纯的折旧算不过来）。

## 六、怎么查真实权重体量（别信标题里的参数量）

```bash
curl -s "https://hf-mirror.com/api/models/<org>/<repo>?blobs=true" | python -c "
import sys,json
d=json.load(sys.stdin); s=d.get('siblings',[])
print('shards:', sum(1 for x in s if x['rfilename'].endswith('.safetensors')))
print('total GiB: %.1f' % (sum((x.get('size') or 0) for x in s)/1024**3))
"
```

**实测**：`deepseek-ai/DeepSeek-V4.1-Flash-1017` → **48 个分片、475.3 GiB**（= 510.5 十进制 GB，与官方 511GB 吻合）。
妙用：拿这个数**一秒证伪**「两台小盒子跑满血」——256GB 就是装不下 475GiB。

**注意**：V4.1-Flash-1017 是 2026-10-17 的 **minor update**，架构与参数量未变、权重没变小；比 9-10 首发版多了 benchmark、多了 `encoding.py` 与 deepseek-recipe。
