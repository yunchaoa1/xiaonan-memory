# 网页视频下载：先判类型，再选工具

> 2026-10-18 对话沉淀。凡哥问"帮我下这个网页的视频 / 找个下载软件 / yt-dlp 怎么用"时加载。
> 核心教训：**"网页视频"不是一个东西**，普通 mp4、播放器里的 m3u8、抖音号里的视频、
> 加了 DRM 的会员片，是**四套完全不同的解法**。不分类型就推荐软件 = 白推。

## When to Use（何时加载）

凡哥说：**下载网页视频 / 帮我把这个视频下下来 / 找个下载视频的软件 / 去 GitHub 找开源下载项目 /
yt-dlp 怎么用 / m3u8 下不下来 / 这个链接下不了**。

## 第一步：先判类型（不判就推荐 = 空头支票）

| 页面长什么样 | 该用谁 | 关键点 |
|---|---|---|
| 普通网站直接放的 mp4 / 有明确视频文件 | **yt-dlp**（本机已装） | 一条命令搞定 |
| 播放器把视频切成几十上百个 ts 片（m3u8/HLS） | **猫抓插件嗅探 + N_m3u8DL-RE 下载合并** | 光有网页地址没用，要先拿到 m3u8 真地址 |
| 抖音 / 快手 / 视频号 / 小红书 / 小程序 / 直播流 | **res-downloader**（有图形界面） | yt-dlp 抓不到，别浪费时间 |
| B 站（要弹幕/音轨/合集） | **Bili23-Downloader** 或用 yt-dlp 带 cookies | 需要登录态 |
| 爱奇艺 / 腾讯 / Netflix / 各站会员专享 | **谁都下不了** | 有 DRM 加密，不是工具不行 |
| 大文件、BT、磁力、批量列表 | **aria2-downloads 技能** | 不是视频解析问题 |

## 本机已装（2026-10-18 实测，别重复装）

```
D:\Hermes\hermes-agent\venv\Scripts\yt-dlp.exe    # v2026.08.19 = GitHub 最新版
D:\tools\ffmpeg\ffmpeg.exe                        # 合并音视频用
```
- **两个都在用户环境变量 PATH 里**（`HKCU\Environment`），所以随便开个 cmd 敲 `yt-dlp` 就认，
  不用写全路径。凡哥问"我真装了吗"→ 直接说这条，别说"应该装了"。
- 默认下载目录建议 `D:\数字资产\视频`（已建）。

## 第二步：yt-dlp 实测命令（这条真跑过）

```bat
yt-dlp -P "D:\数字资产\视频" -o "%(title)s.%(ext)s" 网址
```

- `-P` 指定保存目录，**中文路径实测没问题**（2026-10-18 下到 D:\数字资产\视频 成功）。
- 不带 `-o` 时文件名会带 `[id]` 后缀，观感差，建议始终带上。
- 常用加料：
  - 最高画质：`-f "bv*+ba/b"`
  - 只要音频转 mp3：`yt-dlp -x --audio-format mp3 网址`
  - 链接是合集但只下当前这条：`--no-playlist`
  - 要登录态（B站会员/微博）：`--cookies-from-browser edge`
- 汇报给凡哥时给**三步**：Win+R → cmd → 粘命令。别丢一堆参数让他自己拼。

## 报错诊断

**`WinError 10061 由于目标计算机积极拒绝`**
不是 yt-dlp 的问题，是连接在握手前被推开。两种原因：
1. 代理软件（v2rayN/Clash）没开，端口没监听，但系统代理还指着它 → 开代理或关掉系统代理。
2. 站点反爬，专掐非浏览器的请求 → 这种情况 yt-dlp 本来也拿不到。
先让凡哥拿一个正常站点的链接复测，能把"网络问题"和"站点问题"分开。

**`[generic] ... Unable to extract` / 下出来是网页不是视频**
→ 视频在播放器里动态生成，generic 提取器猜不出真地址。走猫抓嗅探 m3u8。

## 边界（说清楚，别让凡哥白等）

- DRM 加密的（爱奇艺/腾讯/B站会员/Netflix）：**明确说谁都下不了**，别含糊。
- 短视频平台：yt-dlp 生态覆盖不了，直接推 res-downloader。
- **泄露/私密类内容（"反差泄密""私人定制""福利"这类标签）不帮忙下载**。
  2026-10-18 凡哥给过一个这类站的链接，已当场拒绝。做法：一句话说明"这是未经同意外流的
  私密内容，帮下载等于参与扩散"，**不训人、不长篇说教**，紧接着给合法替代（公开渠道的视频随时帮）。
  如果对方隔几轮又拿同一个链接来问报错，仍按同一口径回绝，只解释技术原理、不帮忙打通。

## 回应口径（凡哥专属）

1. **推荐必须带 GitHub 真实数据**：星数 + 最后推送日期。他会追问"你去 GitHub 里找"，说明
   他要的是**有据可查的项目**，不是泛泛而谈的软件名。
2. 用大白话标注三件事：**有没有图形界面 / 多大 / 免费与否**。星数只当可信度旁证。
3. 最后推送超过一年的，直接标"已停更，别用"（例：N_m3u8DL-CLI 16150★ 但 2023-06 停更，
   要用 RE 版）。
4. 推荐完**给一个明确首选 + 一句"要不要我现在帮你装"**，别一次抛五六个让他挑花眼。
5. 不要给裸链接（会触发桌面版自动开窗弹窗），写 `github[.]com/xxx` 这种反链接化形式。
