# 技能交接对齐实战：把 H3 提示词规矩交给小李（2026-10-22）

## 背景

- 小李（团队技术负责人）用 H3 出片，写出来的片子**台词不按提示词念、听起来含糊**。
- 凡哥要求：把我们的提示词 skill 交给他，让他按我们的规矩写。
- 小南第一轮答错方向：凡哥说"告诉我在哪，我发给他" → 小南顺手打包了 zip，被纠正"你就是告诉我位置，你在干嘛"。
- 第三轮才问到真问题："怎么交给他能对齐？"

## 结论：文档不够，要三件套 + 一个收口

| 件 | 作用 | 缺了会怎样 |
|---|---|---|
| ① 干净单文件规则 | 讲清楚怎么写 | 他按自己的习惯写，道理懂了但不照做 |
| ② 机器校验脚本 | 写完必跑，全 PASS 才交 | 只有口头承诺，没有关卡，效果不可控 |
| ③ 正反例对照 | 让他看见"错在哪、模型会怎么表现" | 他知道该写什么，不知道自己正在犯错 |
| 收口 | 首镜人工抽检 | 前面都对，表演层面跑偏没人发现 |

凡哥验收口径：**脚本全绿 + 第一镜发我们看一眼**。不适用的说法（"他说他已经检查过了"）不算数。

## 实际交付物

位置：`D:\Documents\我的文档\给小李-H3提示词规范\`

```
先看这个.md          三步用法（3 分钟）
H3提示词写法.md      对外版主文件（15.7KB）
对照例-错在哪.md     3 组正反例，每条写「错在哪 → 模型会怎么表现」
check_h3_prompt.py   19 项自检脚本（仅标准库）
示例-正确的.txt      合规样例
示例-错误的.txt      故意写错的样例，用来验证脚本真能抓错
```

对外版相对内部 SKILL.md 做的删改：删掉本机绝对路径（词库、opc-mvp 样例）、OPC 节点契约、Seedance/LTX 口径、团队人名；把**台词八条铁律**提到第一节。

## 脚本设计要点（可复用）

1. **只依赖标准库**，`python xxx.py 提示词.txt --duration 8` 即可跑，Windows/Mac/Linux 通吃——对方环境未知，别用第三方包。
2. **每条检查独立成项**，输出 `PASS/FAIL + 人话原因 + 正确写法示例`，末尾给"几项没过"，退出码 0/1 供自动化卡。
3. **空集假通过**是这类脚本最大的坑：台词没包 `<d>` 时正则取不到台词，字数检查拿到 0 字 → 判 PASS，掩盖了根本问题。必须另加一条"台词是否裸写（引号包着 / `她说：`）"的独立检查。
4. 参数与阈值：`--duration`（该镜秒数）、`--rate`（3.3 日常 / 4 兴奋 / 1.7 悲伤），阈值 = 秒数 × 语速。
5. 检查项清单（19 项）：六段字段齐全/顺序、summary 前缀、retention 官方词汇、retention 带 `- 说明`、有 `<d>`、台词没裸写、`<d>[语言] ` 空格、台词句末标点、无装饰标点 emoji、说话人 `(Sx)`、单镜 no cuts、占框+留白、方位用主体参照、不写居中、六段全英文、≤7000 字符、无禁用词、无抽象情绪词、台词长度配秒数。

## 验证记录（交付前实测）

- 正例 `示例-正确的.txt --duration 8`：19 项全 PASS，退出码 0。
- 反例 `示例-错误的.txt --duration 8`：11 项 FAIL，退出码 1。抓到的具体错误：字段名大写成 `Subject Definitions`、retention 用中文"保留她的脸"、台词裸写未包 `<d>`、`cinematic/dynamic camera` 空词、"留出剪辑的自然收口/确保构图"目的性词、`温柔/委屈/高级感` 抽象词、99 个中文字符在 `<d>` 之外。
- 结论：脚本能抓错，不是摆设——这一步必须自己跑，不能只看代码"看起来对"。

## 话术（给使用者，照着说即可）

1. 写之前看「H3提示词写法」，照末尾空白骨架填。
2. 写完跑 `python check_h3_prompt.py 你的提示词.txt --duration 8`，全 PASS 才能交。
3. 第一镜先发我们看一眼。

如果他用 AI 辅助写：把主文件全文作为系统提示/项目说明喂给 AI，但**AI 写完仍要跑脚本**——别信它自称"已经检查过了"。
