# 凡哥口述更新 → 记账与提醒流程（2026-10-13 实战定）

触发：凡哥发一条状态 / 派活 / 结论（"xx 已经在群里下达了" · "现在小李正在教…" · "要求 12-15 交付"）。

## 四步（顺序固定，别跳）

1. **对账（先查后写）**：先扫三个源看**有没有记过** —— `集团/台账数据.json`、`集团/凡哥例行与待办.json`、`DASHBOARD.md`
   - 套路：`execute_code` 里 `json.load`，用 `"关键词" in json.dumps(t, ensure_ascii=False)` 逐条扫；DASHBOARD 用 `search_files`
   - 实测：元气森林 / 浪浪椰 的派活在台账 **0 条**（只在 DASHBOARD 有项目档案）→ 新增，**不能假设已记**
2. **记账**
   - 台账行字段：`work_date / 人 / 项目 / 节点 / 内容 / 状态 / 承诺 / 实际 / 卡点 / 解决 / 来源 / 备注`
   - 新增行最省事的写法：`dict(rows[-1])` 复制末行模板 → pop 掉要改的键 → 赋新值
   - 状态只有 `待办 / 进行中 / 已完成`；**结项＝`状态: 已完成` + `实际: <日期>`**
   - `来源` 必填（口述＝`凡哥 <日期> 口述`；会议＝`会议纪要`）；责任人未知写 `待确认`＋备注"待补：谁"（**人力归凡哥定，不按岗位推定**）
   - 写盘：`json.dump(d, open(p, "w", encoding="utf-8"), ensure_ascii=False, indent=2)`
   - ⚠ 长中文 payload 一次写完会被**截断成 SyntaxError** → 字符串拆短、分步赋值
3. **挂提醒**（有未来日期的才挂）
   - 时刻口径：**催别人交东西 → 对方下班前 2 小时（16:00）**；**提醒凡哥本人核实 → 11:00**
   - 实现：`cronjob(action=create, no_agent=True, script="remind_<主题>.py", deliver="bot-chat", schedule="<ISO 时刻>", name=...)`
   - 脚本正文用 `MSG = (...)` **分段 patch** 写；写完先 `python 脚本.py` 跑一遍看正文完整
   - `gateway_running: false` 是**误报**（App 自带调度器会 fire；判断靠 `last_run_at`）
   - 记账三件套：脚本**绝对路径** + **job_id** + DASHBOARD 一条；并回填待办 JSON 该条的 `备注`（前一步卡在谁、什么时候催）
4. **回话**：报"这件过了" + 一个问题 + 一句"下一条是 X，你说继续我就摆上来"

## 半条结项判据（本次实例）

「让帧格视界（姚总）用起来」——凡哥口述"小李正在教他们用" → **达成，划掉**；
同一条里「部署到杨董那台本地服务器」因小李报过**单卡故障**未确证 → **留 `进行中` ＋列出要核的点**，并问他一句。
**宁可留半条，不划假账**（台账连带考核，划错是替凡哥背责任）。

## 并发提交核对（同一仓可能有并行 agent）

本次实测 14:03 有另一个会话提交了 DASHBOARD → 自己 commit+push 后补跑三条核对：
`git log --oneline -3`（我的 commit 在历史里）· `git status --short`（工作树干净）· 目标文件条数对（`git show HEAD:集团/台账数据.json | python -c "import sys,json;print(len(json.load(sys.stdin)['任务']))"`）。
