# 标志选型阶段：排行榜调研结论 + 12 母题清单 + 单色稿后处理

> 来源：2026-09-11「天使OPC数字社区」logo 项目第三轮（领导评审后返工）。
> 适用：凡哥替别人（领导/客户）要标志、需要"多给几个可选"的时候。

---

## 一、排行榜 / 权威调研结论（选型前必须先摆出来）

**调研出处**
- LogoLounge 2026 Logo Trend Report —— 统计 **30,000+** 标志，方法为观察而非个人喜好；中文摘要在 logonews.cn（`2026-logo-trend-report`）。
- 全球「最被记住 / 最知名标志」榜单（Apple / Nike / McDonald's / Coca-Cola / Mercedes / Mastercard / Audi / Starbucks 等）。

**结论（可直接复用的判断依据）**
1. 最被记住的标志共性 = **极简 + 一个有含义的故事 + 高对比 + 可缩放 + 不过时**。上榜的标志**都不追潮流、不堆特效**。
2. **Nike 对勾 = 胜利女神（Nike）的翅膀**，同时又被读成「对勾 = 成功」→ **一形两义**是天花板手法，**而"翅膀"本身就是世界第一标志的母题**。做「天使」类品牌天生占这个便宜，要主动利用。
3. **Mastercard 交叠双圆 = 连接 / 信任；Audi 四环 = 团结；Mercedes 三芒星 = 覆盖**。要表达「连接 / 社区 / 平台」这类**关系语义，用几何叠合最省力也最显高级**。
4. LogoLounge 2026 **年度主题 = 动势（dynamics）**（标志要有起飞 / 前进 / 过程感）；**第 1 名趋势 = 负空间里藏第二个意思**（V Balls：举臂 V 形围成的圆 = 人群 / 团结 / 共享能量）；另有 **Little Blip**：一个刻意的「歪一下」制造记忆点。
5. 报告对 2026 的定性：**是对过去十年「扁平极简、彼此长得一样」的反动**，原话是「brands want to be **remembered**, not just legible」。
6. 2026 的其它可借趋势：Simple Twist（干净几何 + 一个意外角度）、Crafted Linework（钞票/印章式精细线）、Stamp & Seal（邮票/印章式）、Morph-Marks（一个静态主角标 + 会动会变形的数字版）。

**由此推出的两条反面结论（本次踩过）**
- ❌ **只做单色极简几何 = 撞素材库脸**（连续几轮被判「太土 / 太简单 / 没设计感」的根因）。
- ❌ **Glitch 错位叠印属潮流手法**，与「不过时」相悖 —— 凡哥明确说「抖音只是举例，不是必须照着做」。需要年轻化时才用，且只作可选项。

## 二、面向「决策者（领导）」的选型流程

决策者要的是 **能看懂 + 有含义 + 不花哨**；抽象几何在他们眼里就是「不知道画的啥」。

1. **先做排行榜调研**，把结论摆出来（否则只是凭手感画，容易被一句「没设计感」打回）。
2. **给 ≥12 个不同母题的单色符号**，一个图标一张图：
   - 每个都是**具象、可一眼叫出名字**的形（见下方母题清单）
   - **同一符号不要出多版本 / 多档位** —— 选型稿给多版本会淹没判断
   - 每张附 **星级 + 一句话含义 + 淘汰建议**（附淘汰建议能帮领导快速收敛）
3. **交付形态**：一页 HTML 选型页（每卡一图/名/星级/说明）+ 白底与深底两张拼版（拼版方便打印或投屏给领导看）。
4. **方向定稿之后**才展开：多档复杂度（仅图标 / 锁标 / 完整品牌板）、各场景应用（App 图标、favicon、社媒、头图、名片）。
5. 汇报文件位置时**成品目录与过程稿目录分开报**，并说明哪些是废稿（凡哥会想清理）。

### 12 母题清单（可复用，含本次实测星级）

| # | 母题 | 语义 | 实测 |
|:--:|------|------|:--:|

## 三、AI 稿转「精确单色 + 真透明」后处理配方

白底纯色稿的**精确解**（比"白底去背"干净，抗锯齿边缘天然正确）：

```
alpha = 255 - min(R, G, B)        # 白底 → alpha 0；纯色主体 → alpha 255
像素色统一填目标品牌色（如 #0052d9）
按 alpha 包围盒裁切 → 补 10% 留白 → 正方形 → resize
```

- 生成阶段（`image_generate` / GPT Image 2）提示词固定后缀：`single flat color deep azure blue #0052d9 on pure white background, no gradient, no shadow, no 3D, no text, no letters, no border, no mockup, centered, generous margin, thick confident strokes, crisp vector edges, high-end premium brand identity, award winning logo design`。
- 出图后**自己先拼版看过**（vision）再交付；AI 稿常见瑕疵：细线条歪、形状残缺、多余碎屑、颜色残留 —— 拼版时把 16/32/64px 小样并排放，一眼看出哪些缩小就糊。

## 四、实测环境坑（本机）

| 现象 | 解法 |
|------|------|
| SVG→PNG 用 cairosvg 报 `no library called "cairo-2" was found` | 本机无 libcairo 原生库 → 改用 **`pip install resvg-py`**（单文件 Rust 渲染器，无原生依赖，中文渲染正常） |
| SVG 里路径数据忘包 `<path d="...">` 直接写在 `<g>` 里 | resvg **静默忽略**，渲染出来只剩其他元素（曾误判为"渲染器有问题"）→ 先 `cat` 出 SVG 原文核对结构 |
| 中文变豆腐块 | SVG 里显式写 `font-family="Microsoft YaHei, 微软雅黑, Source Han Sans SC, sans-serif"` |
| 图形在画布上偏 | 渲染后量 alpha 包围盒 → 反算 viewBox 单位平移量 → 用 `<g transform="translate(dx dy)">` 归一化；双色稿按「两色并集」的包围盒算 |
| 16px favicon 里标看不见 | favicon 色块内标占比放大到 **~78%**（App 图标用 ~62%），并单独出 16/32/48/64 与多档 `.ico` |
| 展示页/选型页要核对 | 用 Chrome `--headless=new --screenshot=out.png --window-size=W,H "file:///..."` 渲成图，再自己看一遍（比只"文件写完"可靠） |
