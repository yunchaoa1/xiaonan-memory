# 把能力复制给别人的 agent（2026-11-16 起）

## 0. 第一条：先查对面有什么扩展机制，不要按想象打包

2026-11-16 凡哥问「怎么能把你现在的能力复制给其他人的 agent」，我先按"DeepSeek 那边就是个聊天 agent、只能塞系统提示词"设计了一整套纯提示词包，被打回：

> 「我感觉你又靠你的直觉脑补了，你去查 deepseek harness 到底是怎么回事」

**平台能力边界是事实问题，不是常识问题。** 打包形态完全取决于对面有什么机制，猜错就是整包作废。

## 1. 三种形态，先判再打包

| 对面是什么 | 打包形态 |
|---|---|
| 原生支持 skill / 插件目录 | 拷目录（SKILL.md + references + scripts + templates），带一份安装说明 |
| 只有系统提示词框 / 人设栏 | 压成**单文件短版**（一两千字：身份 + 硬规则 + 自检清单）+ 知识库材料另给 |
| 产品内置（要嵌进自家平台给客户用） | 拆成提示词模板存数据库，节点调用时拼 system prompt，质检放后端接口 |

共同点：**能带走的永远是三样——规则、门禁（可验证的检查）、示例**；带不走的是判断力，所以门禁越具体越值钱。

## 2. 已核实的事实：DeepSeek Harness（dsh）

核实日期 2026-11-16，来源＝官方站 deepseek 点 com 斜杠 zh 斜杠 harness、仓库 README。

- DeepSeek 官方开源的 **agent 运行时**（不是聊天客户端），TypeScript，MIT。
- 架构是 **everything-is-a-plugin**，基于 Cordis（论文 arXiv 2608.25512）。
- 形态：桌面端 + `dsh web`（本地网页）+ 源码安装；另有 headless / Python SDK 的说法。
- **skills 是它的插件之一**，不是只能靠提示词。
- 插件生态入口在 GitHub topics 的 `dsh-plugin`；仓库里另有 `AGENTS.md` 与 `docs/`。
- ⚠️ **没核实到的部分不要编**：skills 放进哪个目录、frontmatter 要什么字段——这轮抓文档站被网络挡了，没读到。下次要给 dsh 打包，第一步是读官方 quickstart（`deepseek-harness.github.io`）那页，而不是照 Hermes 的目录习惯套。

## 3. 查证顺序（照着走，别跳）

1. 官方产品站 / 文档站首页 → 它自称是什么（agent 运行时？聊天产品？IDE 插件？）
2. 仓库 README + `AGENTS.md` + `docs/` → 扩展机制叫什么、有没有 examples
3. 插件/技能生态目录（GitHub topics 或 marketplace）→ 别人是怎么装的，照抄一个现成包的目录结构
4. 以上都拿不到 → **如实说拿不到**，然后给凡哥一条他能自己跑的命令（他机器上 `ls` 一下配置目录），而不是猜

网络受限时的替代：文档站抓不到就用仓库文件（github 原始文件、`git ls-tree` 看目录树），别把"我没抓到"说成"它没有"。
