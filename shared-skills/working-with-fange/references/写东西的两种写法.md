# 写东西的两种写法 · 派活步骤 · 检查员判据

**来历**：2026-11-23。凡哥在一天里纠正了四次「你又自己干」，最后一次给了根因诊断：「你现在所有写的东西都是判决书对吧？所以你的遵循度不高」。

---

## 一、判决书 vs 步骤说明：完整对照

### 判据表

| 维度 | 判决书 | 步骤说明 |
|---|---|---|
| 句子的主语 | 规则本身（「不许 X」） | 我的下一个动作（「第 2 步 派写手」） |
| 有没有序号 | 常常没有，是散落的禁令 | 必须有，能说「回第 3 步」 |
| 有没有分支 | 极少 | 每步带「不行 → 回第 N 步」 |
| 结束条件 | 无（永远在提要求） | 有（做完是什么样，可数可看） |
| 什么时候有用 | 事后审判 | 动手当时 |

### 四个判决书信号（看到就重写）

1. **只有禁止，没有下一步**：「不许」「禁止」「严禁」
2. **只有要求，没有动作**：「必须确保」「要保证」「务必」
3. **只有标准，没有做法**：「质量要高」「要严谨」「不能马虎」
4. **只说角色职责，不说交接动作**：「检查员负责挑毛病」（而不说它拿到路径后做什么、交什么回来）

### 同一件事的两种写法（本次真实例子）

**判决书版**（我 2026-11-23 上午写进 skill-router 的，五条）：
> 1. 开工先判分派
> 2. 写的人不许当检查员
> 3. 提交前必过机器关卡
> 4. 代理的自报不算数
> 5. 不许等凡哥提醒

**步骤版**（下午改写后的形态）：
```
第 1 步  拿到活，先看最后交给谁。
         交给凡哥的 → 第 2 步；自己看的 → 直接干。
         做完是什么样：说得出「这份东西最后给谁」。

第 2 步  劈成两份指令。
         一份写（干什么、什么约束、写到哪个路径）；
         一份查（第一句写「你只挑毛病，不许改文件」）。
         做完是什么样：两份指令都在手里。

第 3 步  派写手。收它的产出路径 + 自检报告。
         做完是什么样：磁盘上真有那个文件。

第 4 步  把路径给检查员。收它的清单。
         不合格 → 回到第 3 步，把清单原样交给写手改。
         做完是什么样：清单上每条都有「已改/不成立」的结论。

第 5 步  清单清空了 → 去第 6 步。
         还有条目 → 回第 3 步。

第 6 步  跑 gate_check.py --dir <稿件目录>。
         退 0 → 交付；退 1 → 看它说缺哪个凭证，回第 2 步。
```

## 二、四角色与交接

| 角色 | 干什么 | 绝对不干 |
|---|---|---|
| **幕僚长**（主代理） | 拆活、定标准、派活、验收、汇报 | 不写稿、不改文件、不跑片 |
| **写手** | 按任务书产出文件，交路径 + 自检报告 | 不自判合格 |
| **检查员** | 只挑毛病，出问题清单 | 一个字都不许改 |
| **跑片员** | 提交、盯进度、收片、抽帧 | 不改稿 |
| **档案员**（重大改动时） | 记变更日志、维护基线、查有没有被覆盖 | — |

**交接链**：幕僚长 → 写手 → 幕僚长 → 检查员 → 幕僚长 → 写手（改）→ 检查员（复查）→ 跑片员 → 幕僚长 → 凡哥。

**界线要可数**：产出一个以上文件 → 走全链。「这活不大」是后门，必须堵死——凡哥 2026-11-23 三次抓我，理由都是「这活不大」。

## 三、检查员的判据清单（可直接喂给子代理）

判断一份文档是「步骤说明」还是「换了包装的判决书」，逐句问：**这句话告诉我下一步做什么，还是什么算错？**

- 是我的动作 → 记一条「合格」
- 是审判 → 记一条问题，写出「原文 + 属于哪类 + 改成什么」

**三类硬不合格**（出现即判不合格）：
1. 步骤顺序走不通（例：第 4 步要用的东西，第 5 步才产出 → 首轮必然失败，回退又指错方向 → 死锁）
2. 字段/格式对不上真代码（例：说「检查员回报过/不过」，但 `gate_check.py` 认的是 `checked_at_epoch` / `passed` / `segments_checked`）
3. 适用范围写错（例：`gate_check.py` 只认 `seg*.txt`，流程却把文档/配置也划进全链）

## 四、代理自报的三次翻车（2026-11-23 同一天）

| 代理自报 | 独立复核结果 |
|---|---|
| 「否定词扫描器命中 0」 | 全片 7 处否定词：seg01 nothing / seg05 cannot / seg07 without / seg12 not / seg13 nothing / seg16 not / seg18 never |
| 「5 段全部通过，EXIT=0」 | 参数不全对齐；另有 2 段超出单镜词数上限未清零 |
| 「工作流全部合格」 | 检查员挑出 9 条问题，其中 5 条硬伤，含 3↔4 步流程死锁 |

**共同根因**：代理的自检用的是它自己的词表和自己的想象流程。**它检查的标准，就是它写的时候的标准——所以查不出自己漏的那一类。**

**动作**：代理交东西，一律自己重验；它最自信的地方正是最该抽查的地方。用比它更全的词表（否定词要包含 `neither` / `nor` / `hardly` / `seldom` / `barely` / `nobody` / `nowhere`，`h3_lint` 的 H13 会漏这几个）。

## 五、硬关卡（比记性可靠）

`D:\Hermes\scripts\gate_check.py --dir <稿件目录>`

- 没有 `_review/*.json` 凭证 → `exit 1`，拒绝提交
- 凭证必须同时满足三条：`passed=true`、报告时间晚于稿件最后修改（改完没重审 = 没审）、审的段数 ≥ 现有段数（不能只审三段就交全片）
- 实测：对 `D:\Hermes\cache\emotion\new`（22 个稿件）跑 → `❌ 没有审稿凭证 —— 不许提交`，退出码 1

**为什么要有它**：凡哥说「我不能每次都提醒你」。我答应「记住了」没有用，机器拦得住才有用。
