# 找回凡哥“之前聊过”的内容：历史会话检索流程

适用场景：凡哥说“周五咱们写的小说/故事/提示词”“上次那个版本”“之前聊过的内容”。这类内容不一定保存成 md 文件，可能只在 Hermes `state.db` 或 request dumps 里。

## 快速判断

1. 先确定时间锚点：例如“周五”要用系统日期算出具体日期，不要凭记忆。
2. 先搜共享仓库：`xiaonan-memory` 里的 `characters/`、`prompts/`、`stories/`、`memory/`。
3. 如果仓库无命中，不要马上问用户重复；继续查 Hermes 历史会话。

## 历史会话优先路径

- `session_search(query=...)` 适合普通召回，但对压缩过的长会话、cron 会话、request dump 不一定能命中。
- 如果 `session_search` 没命中，而用户给了明显日期/关键词，直接查 SQLite：`D:/Hermes/state.db` 的 `messages` 表。
- 关键字段：`id, session_id, role, timestamp, content`。时间字段是 Unix timestamp。
- 搜索时同时用：标题/角色名/关键词/用户原话片段。例如：`小说|故事|第一章|章节|大纲|齐白兰|齐镇海|骑楼故事馆`。

## 输出给凡哥的方式

- 先告诉他“找到了/没找到”，不要先铺排检索过程。
- 如果有多个版本，按时间线列：草稿1、草稿2、最终版，并说明为什么判断哪个是最终版。
- 直接贴最终正文；如果正文很长，先贴标题、位置、开头和版本判断，再按凡哥需要继续整理。
- 明确说明是否已经保存成文件；如果没有，建议保存到 `D:\Hermes\xiaonan-memory\stories\...md`。

## 2026-08-03 案例

凡哥问“周五咱们一起写的那个小说故事”。最近周五是 2026-07-31。文件搜索没找到单独 md；两个 D 盘 `小说.docx` 修改时间分别是 2025-12-24 和 2026-03-24，排除。SQLite 命中同日会话：

- 11:41 《骑楼故事馆》：日常温和版，凡哥觉得太平。
- 11:56 《歪了一点的廊柱》：直播唱飘+弹幕+歪廊柱隐喻，凡哥要求保留框架但重写。
- 12:02 《爷爷忘了》：最终方向，齐镇海只忘齐白兰相关记忆，适合短剧钩子。

判断原则：用户最后一次纠正后生成的版本通常是最终方向；要同时保留前版作为可复用框架。
