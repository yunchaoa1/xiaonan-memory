## 1. 读树函数（照搬的核心）

`D:\Hermes\scripts\gen_mindmap_all.py` 顶部：

```python
import os, sys, json, zipfile
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from xmind_writer import write_xmind, read_xmind_titles, tree_to_md

def read_xmind_tree(path):
    """读 .xmind → 嵌套元组树 (标题, [子节点…])，用于把一张图原样搬到另一张图"""
    with zipfile.ZipFile(path) as z:
        content = json.loads(z.read("content.json"))
    def walk(t):
        kids = t.get("children", {}).get("attached", [])
        return (t.get("title", ""), [walk(k) for k in kids])
    return walk(content[0]["rootTopic"])

PLAN  = read_xmind_tree(OUT + "/元气森林平台_落地方案.xmind")
DRAMA = read_xmind_tree(OUT + "/影剧工坊_六节点思维导图.xmind")
MOVED = [PLAN, DRAMA]          # 照搬分支（定稿原文·专业词免检）

TREE = ("技术部 · 项目总图（各项目落地方案汇总）", [PLAN, DRAMA, <手写分支…>])
```

- 只读 `content.json` 的 `rootTopic → children.attached`；**标题与层级原样透传**。
- 图被凡哥在 XMind 里另存过也没关系（体积变大＝加了样式），内容仍按 `title` 读出。
- **"搬进来 / 替换到对应位置"＝把该源图整棵作为总图的一条一级分支**；搬完从总图文件**回读**该分支自证（别只说"改了"）。

## 8. 内容对齐规则（图内容＝凡哥原话）

- **只装他的话**：他口述产品/链路后，节点措辞尽量用他的原句（例："当周测试或者是月测试时，没有答对 → 会有相应的惩罚，可以设置僵尸啃食劳动成果…"）；他会逐句核对。
- **禁自编推论/总结句** ✗（2026-10-11 被他抓出并全删的例子：「奖励会累积：答对越多，园林越丰富」「玩法核心：答对＝收获，考砸＝损失」「（循环）」「从答题结果里」——凡是他没说过的加工，一律不加，哪怕"意思没错"）。
- **缺数据处**：`负责人 待指派｜进度 ○ 未开始`（或"规划中"），不编人、不编时间。
- **`其他保持不动`**＝只改他点名的那块，其余分支一字不碰；交付时说明"哪些没动"。
- **`先别管别的`**＝一次只交他点名的那一件（他逐件验收，别顺手处理别的）。
- 交付格式：把改动**逐条列表**回复（改哪句 / 删哪句 / 留哪句 + 原因），他按表验收；文件开着的话提醒"关掉重开"。

## 9. 双机协同与提交顺序（都踩过）

- **先 commit → 再 pull --rebase → 再 push**：有未提交改动时直接 `git pull --rebase` 会报 `error: Please commit or stash them` 并**静默跳过**（此前 push 的"成功"输出可能造成假象）→ 正确顺序：`git add -A && git commit` → `git pull --rebase` → `git push`。
- **DASHBOARD 编号会撞（两台机同一时段）**：2026-10-10 双方都写了 10.53 → 插入前用 `re.findall(r"### 10\.(\d+)", d)` 取 max+1 **自动定号**，别手选；写完 git log 核对谁是谁。
- **跨天校正**：长会话跨天后，图/DASHBOARD 里的日期先跑 `date` 核实再写（本次 10-10→10-11 又返工一次）。
