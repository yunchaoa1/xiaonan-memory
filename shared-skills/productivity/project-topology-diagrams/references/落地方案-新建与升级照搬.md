## 一、动手前的强制刹车（凡哥的规矩，本次验证有效）

出**新交付物**前先发一条确认：`我理解你要 X ／ 涉及 Y ／ 我先检查 Z`，并附上
**我查到什么 + 我打算怎么分（一级分支草案）+ 一个卡点问题**，让他一眼能点头。
- **一次只问一个问题**（抛多个他会说「太多了」）
- 本次问的是「登录后才进得去的那三页给不给我账号」→ 凡哥直接丢来三份页面存档 HTML ＝ 确认
- 确认里给**可点掉的结构草案**（五段一级），比问「你想要什么结构」有效得多

## 二、站点当口径源：取全量，别只看首页

1. 单页应用（SPA）首页只有 `#app` 空壳 → **直取前端包**：`curl` 站点 `/assets/index-*.js`，用正则抽
   ① 路由 `path:"/xxx"` ② 含中文的字符串字面量（＝菜单/按钮/状态文案全表）
2. 再用 Playwright 逐路由真渲染，取 `page.inner_text("body")` + 整页截图
   （全量取法＝同技能 `references/站点取全量-路由与文案抽取.md`）
3. 凡哥随后可能补「登录后页面的存档 HTML」（浏览器另存，约 1.2MB）→ **别通读 HTML**，
   正则去掉 `<script>/<style>` 后抽文本（1.2MB → 1.3KB 纯文案，够写图）
4. 站点的导航、文案、价格、状态标注**原文照进图**；缺的（登录墙内、未开放）如实标

## 五、台账 / JSON 编辑的两个细节

- 改 `集团/台账数据.json`、`集团/凡哥例行与待办.json` 用 python：`json.loads` → 改 → 写回时
  **保留原行尾**：`newline=""`，且 `if b"\r\n" in raw` 时 `dumps(...).replace("\n","\r\n")`
- 原任务结项就**改状态不删行**：`状态: 已完成` + `实际: <日期>` + `备注:` 写清交付物
- 改完必须 `git commit` + `push`，并在交付话术里报 commit 短号
