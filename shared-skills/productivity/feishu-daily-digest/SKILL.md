# 飞书每日群与日报汇总（口令：上班了）

## 触发

凡哥说 **「上班了」** → 立刻跑本流程。别人说这句不触发。
他上班时间不固定，**所以不用 cron 定时**，纯口令触发。

## 一句话需求

凡哥原话：「团队协作和跨部门协作需要每天对群里的信息做汇总」——汇总结果直接当**考核留痕证据**（谁 @ 了多久没回、谁的配合请求超时、跨部门需求响应时效、日报谁没交）。

## 执行步骤

1. **读汇报机器人**（飞书左侧会话「汇报」，带机器人标签）
   - `computer_use(action='capture', app='Feishu.exe', mode='som')`
   - 从 AX 树文本里取：**汇报提交统计**（应交/实交/缺谁）、**每人日报卡片**（今日完成/卡点/解决方法）
2. **读技术部群**（凡哥点开会话后同样 capture 读 AX 树）
3. **读天使控股群**（同上，对象＝帧格视界等合作方）
4. **出汇总**（格式见下），同时把结果落盘
5. **记台账**：日报条数、群留痕事件写进 `集团/台账数据.json`；汇总写 `集团/飞书摘要_YYYY-MM.jsonl`（一行一天，便于月底考核聚合）

## 输出格式（凡哥认这个）

```
【MM-DD · 技术部】
日报：应交 4 实交 4 ✅（李林 18:40／吴伟俊 19:10／何锦波 次日 07:48 迟交 −2／唐光辉 20:05）
群里：吴伟俊 12 条｜何锦波 8 条｜李林 5 条｜唐光辉 2 条
  · 10:12 你 @李林 要 2.0 界面 → 11:40 回（✅ 32 分钟内）
  · 14:05 你 @唐光辉 要知识库数据 → 18:00 仍无回应 ⚠️（对应协作项「约定时限未回应 −1/次」）
【MM-DD · 天使控股】
  · 帧格视界 10:30 提 2.0 试做需求 → 10:45 已回 ✅
  · 超过 1 个工作日未回应：无
```

日报判定按考核表的**三档**：18:00–次日 8:00 准时（不扣）｜8:00–9:00 迟交（−2）｜9:00 之后视为未提交（−4）。

## ⚠️ 踩过的坑（2026-10-30 实测）

1. **文字能读，点击不稳**：AX 树里消息文本、汇报卡片、统计数字全都能直接读，**不需要 OCR**。但 `coordinate` 点击在这台多屏机器上映射异常 —— 传 `[1500,528]` 实际点到 `(2832,551)`，传 `[1001,497]` 点到 `(2312,518)`，**两次都点飞**。
   → **做法：让凡哥自己把技术部群 / 天使控股群 / 汇报 点开**（他点一下即可，不用截图、不用发给我），我 capture 就能读到整页内容。
2. `element=` 裸索引会被拒：报 `bare element_index is not accepted; pass element_token, or snapshot_id together with element_index`。当前 capture 结果**不带 token/snapshot_id**，所以 element 点击走不通。
3. `click` 的 `app` 参数要用 `Feishu.exe`（不是中文名「飞书」，否则报 `input_target_mismatch`）。
4. 窗口最小化 / 锁屏时读不到 → 直接告诉凡哥「飞书窗口得开着」。

## 要更省事的长期方案（未做，需凡哥开权限）

飞书开放平台自建应用 + 权限 `im:chat:readonly` + `im:message:readonly` + 把应用加进两个群 → 定时/按需拉全部群消息，不依赖屏幕。密钥由凡哥自己填。凡哥问起再说，别催。

## 验收标准

- 汇总里每条都能落到「谁、几点、说了什么、有没有回」
- 日报部分要给出**谁没交 / 谁迟交**
- 落盘成功（`集团/飞书摘要_YYYY-MM.jsonl` 追加一行）才算完成
