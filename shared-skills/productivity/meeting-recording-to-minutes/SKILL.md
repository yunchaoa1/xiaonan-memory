# 会议录音 → 会议记录 ＋ 待办事项

凡哥丢来一个会议录音（`@file:...m4a`，常在工作区外），要的是**会议记录 + 待办统计**，并且
「**你也要参与进来**」＝记录里必须单列**小南自己的任务**。全程**本地转写，不出网**（会议含战略/融资/法律内容）。

**实测基准 ①（2026-09-30）**：72 分 48 秒 / 78MB m4a → 1871 段 → **GPU 转写 18 分钟**（≈4× 实时）→ 记录 1.8 万字 + 12 条待办 + 5 条我的任务。
**实测基准 ②（2026-10-12）**：77 分 14 秒 / 86.6MB m4a → **1636 段** → GPU 转写 **1055 秒（17.6 分钟 · ≈4.4× 实时）** → 纪要 17.4KB + docx 46KB。
**实测基准 ③（2026-10-13 · 产品商讨录音，不是会议）**：两段 m4a 分别 **218.9s → 96 段** 与 **866.2s → 336 段**，共 18.1 分钟 → 同一脚本循环跑完，**合计转写 281 秒（≈3.9× 实时）**。**多段录音用 `for` 循环分别出 txt/json**（分段边界＝文件边界，比拼接后再转写更清楚、更好引用）；`initial_prompt` 术语表要加**本次专名**（本次加「浪浪椰发布平台」）。
**实测基准 ④（2026-10-19 · 新制后第一次周例会）**：**33 分 08 秒 / 37MB m4a → 622 段 → 转写 444 秒（≈4.5× 实时）**；ffmpeg 转出 16k wav 61MB，跑完即删。全程三方并行不打架：**转写在后台跑、同时 `read_file(offset)` 分批读 txt、边读边定纪要结构**。

→ **四场都落在 3.9–4.5× 实时**，估时长公式：**预期转写分钟 ≈ 音频分钟 ÷ 4**（给凡哥报时间时用这个，别报得比实际久）。短音频（合计 <20 分钟）**一次 `process(wait)` 就能把全稿拿回来**，不用开场就去批读。

## When to Use

- 凡哥发录音/视频文件 + 「做一个会议记录」「统计出待办事项」「你也要参与进来」
- ⭐ **每周一例会录音（固定节奏 · 凡哥 2026-10-16 定）**：凡哥每周一开例会（总结上周＋规划本周）并**录音发来**、提醒团队自记 → 产出 **会议记录(.md+.docx) ＋ 待办表 ＋ 小南任务表** → 会上定的交期**登记进台账**（＝月度考核「每周计划 vs 实际进展」的原料），**月末最后一个工作日**用「每天日志 ＋ 每周例会纪要」做考核原料
- 任何 **>10 分钟**的中文长音频要成稿（短教程视频另见 `media-learning` §2b 的双线对齐）
- 会上定了框架，要转成给团队对齐的文档（那一步接着走 `project-topology-diagrams` 出脑图）
- ⭐ **凡哥丢「商讨 / 头脑风暴录音」并说「解析一下，咱们展开你对我一问一答」**（2026-10-13 浪浪椰发布平台案）→ **他要的不是会议纪要**：走 ①–④ 同一条转写链路，但产出换成三样 —— ① **产品需求底稿 `.md`**（定位 / 对标 / 已定口径 / 待定清单）② **一问一答**（**一次只问一个**，见 §2b；他答一项就**当场落进底稿**，别攒到最后）③ 收口后交 `project-topology-diagrams` 出**落地思维导图**。⚠ 底稿要**边问边 `patch`**（每轮结论立即入库），因为中途会跨轮次/上下文压缩；**底稿里的"待定项"要写清是谁在等谁**（例：并发的"谁做/时间"＝等凡哥与小何小吴沟通，不是等小南）。

## 总览（五步，别跳）

```
① ffprobe 看时长 → ② ffmpeg 转 16k 单声道 wav → ③ faster-whisper large-v3 后台转写（边跑边读）
→ ④ 分段读稿、按议题归档 → ⑤ 出 .md 纪要 + .docx + 待办表 + 我的任务表
```

### ① 看文件（先看时长再决定要不要跑）

```bash
cd /d/Hermes/attachments && ffprobe -v error -show_entries format=duration,bit_rate,size \
  -of default=noprint_wrappers=1 "9月30日.m4a"      # → duration=4369.66 (≈72.8 分钟)
```
附件常在 `D:\Hermes\attachments\`（报 "path is outside the allowed workspace" 不用管，**terminal / read_file 照常能读写 D 盘**）。

### ② 转音频（native 程序吃原生路径！）

```bash
mkdir -p /d/Hermes/cache/audio
ffmpeg -y -v error -i "9月30日.m4a" -ac 1 -ar 16000 -c:a pcm_s16le "D:/Hermes/cache/audio/meeting_16k.wav"
```
⚠ **MSYS 路径不被转换**：给 ffmpeg 的输出路径要写 `D:/...` 正斜杠原生路径，写 `/d/...` 会 `exit 127`。

### ③ 转写（脚本＋本地模型）

模型已下好常驻：`D:\Hermes\models\faster-whisper-large-v3`（2.9G，**复用，别再下**）。没有时才取（huggingface.co 本机不通，**走镜像**，约 90 秒）：

```bash
HF_ENDPOINT=https://hf-mirror.com python -c "
import os; os.environ['HF_ENDPOINT']='https://hf-mirror.com'
from huggingface_hub import snapshot_download
snapshot_download('Systran/faster-whisper-large-v3', local_dir=r'D:\Hermes\models\faster-whisper-large-v3',
                  allow_patterns=['*.bin','*.json','*.txt','*.md'])"
```

跑转写（**后台 + notify**，别前台干等 18 分钟）：
```bash
cd /d/Hermes/scripts && python transcribe_meeting.py        # 见 scripts/transcribe_meeting.py
```
关键参数（都在脚本里，改文件名即可复用）：`device="cuda"` / `compute_type="float16"` / `language="zh"` /
`beam_size=5` / `vad_filter=True` / `condition_on_previous_text=False` /
**`initial_prompt`＝人物·项目术语表**（谢泽凡/何锦波/吴伟俊/李林/唐光辉、OPC、影剧工坊、智提分、浪浪河…）——
术语表对中文会议**准确率提升最大**，且**逐段写 txt+json**，所以能边跑边读。

### ④ 边跑边读（不要等它跑完才开始干活）

- 转写脚本**每 20 段 flush 一次**到 `.txt`（带 `[起-止]` 时间戳），用 `read_file(offset=…, limit=420)` 分批读（一次约 400 行 ≈ 17KB，全文约 1900 行）。
- 读的时候就把内容往议题上归：**战略/管理/项目/风险/人事**，并记下**时间戳区间**（写进纪要，便于回溯）。
- 别把整篇一次性塞进上下文：**分批读、边读边定结构**。

### ⑤ 出三份东西

1. `会议记录.md`（结构见 `references/meeting-minutes-format.md`）→ 2. 同名 `.docx`（凡哥要转发）：
```bash
python D:\Hermes\scripts\md2docx_meeting.py     # 见 scripts/md2docx_meeting.py（标题/表格/加粗/引用都转）
```
3. **待办表**（写在记录里 + 回复里再列一遍短表）：`事项 / 责任人 / 时间节点 / 验收标准`。

## 硬规矩（凡哥口径，逐条踩过）

1. **转写原文一字不删改**；记录里只**校正人名与项目名**，原文稿（`.txt`/`.json`）原样保留交付。
2. **ASR 存疑词不脑补**：听不准的专有名词标 `[待确认]`，**在回复里点名问他**（实例 2026-09-30：「哈马斯」「LibTV/Lib」；会后要过一句"准确名字给我一下"）。项目名常被听错：影剧工坊→"影视/智聚/YouTube 工坊"、海螺 AI→"海罗"、RAGFlow→"Wrap Cloud"、ComfyUI→"CoverUI" → 用 `initial_prompt` 术语表压这类错，并建 `references/meeting-minutes-format.md` 里的校正表。
   - **2a｜能自己查的先自己查，只问查不到的。** 把存疑词分两摞：**外部可查**（产品名/模型名/开源项目/工具）→ 自己 `web_search` 查证后**直接写进纪要并标"已查证 + 来源"**；**只有内部信息**（人名职务、公司主体、资金链路里的人）→ 才问他。2026-10-12 实例：把「千问3.8」自己查成 `Qwen3-8B`（并发现 Qwen3 家族**无 27B**，据此给凡哥提了精确问题）、把「REA」自己查成 GitHub `morluto/rea`（Reverse Engineer Anything，MCP server）—— 都省了他一轮。
   - **2b｜问他时一次只问一个 —— 一次抛 20 个问题是错的。** 2026-10-12 我把 21 个存疑点按 ABC 三组一次性列给他，被回「**一问一答的来吧，太多了**」。正确：**按"影响程度"排好序 → 一次只发一个 → 等他答 → 吸收完（改纪要 + 改下游文件 + 重生成 docx）→ 再问下一个**。每个问题只带必要上下文（他为什么该关心这一个点），不问全名这类的敏感信息，纪要里保持称呼（"林总"）即可。
   - **2c｜校正后的名词要全库回填，不能只改纪要。** 凡哥确认正确写法后，立刻 `grep` 整个记忆仓库 + 技能库 + 当前会话产物，把所有旧错形一起改（2026-10-12：`诺进/诺镜` → **`诺境科创（海南）有限公司`**，命中 DASHBOARD / MEMORY / 两个技能 reference / 集团文件 / 纪要 共 6 处，MEMORY 里那个错字还是我上一次自己写进去的）。**主体名/人名这类"错一个字就全错"的词，校正后必须回读确认 `grep` 结果为空**，再重生成 `.docx`。
   - **2d｜人名和"身份"必须写在同一句里 —— 否则永远查不出来。** 2026-10-12 凡哥问「**你忘记了吗？林总是我们集团的 CEO 啊**」：这条信息其实早就在 DASHBOARD 里（写成"CEO 是凡哥大哥"），**但没有任何一处把「林总」和「CEO」绑在一起** → `grep 林总` 只出"林总打通链路""林总印象"这类**动作**，连不出他是谁。**做法**：① 人名第一次进纪要就落「**关键人物**」表（称呼↔身份↔角色，骨架见 `references/meeting-minutes-format.md`，名册见 `references/group-roster.md`）；② 转写里见到称呼，**`grep` 要搜两遍 —— 搜名字、再搜角色词（CEO/董事长/副总/负责人）**；两边都命中却不在同一句 → 说明缺一条显式绑定，补上。
3. **归属＝会上明确认领 / 本人陈述**；没人认领写「待认领」，**禁止按岗位推定**（与日报口径「谁写＝谁做」分开记，记录里注明来源）。
4. **「你也要参与进来」**＝记录末尾必须有一张 **小南任务表**（我能独立做的打底稿/统计/技能化，别只列别人的活）。
5. **决议 vs 提议分开**：会上吵过但没定的事写"待定/未决"，**不要写成决议**；凡哥说"你说说看"的段落属于讨论。
6. **敏感内容如实记、不外发**：融资时间表、开源模型商用风险/授权策略、薪酬与考核思路 → 记录里保留，交付物只给凡哥，**不进共享区、不写进 Team 文档**。
7. 会议里凡哥交办给**数字员工/我的话**（例："录音→转文字→总结要点→结合项目分析"）→ 这既是记录内容，也是**我的能力清单**：如实标"已跑通/待做"。
8. **凡哥在会上一句「记住」＝这条必须单列成表 + 进台账**（2026-10-19 例会实证）：他反复强调的 deadline（周四演示／周五服务器＋工资单）我在纪要最前面做成两行表，并同步 `集团/台账数据.json`（带承诺日）→ 他当场不再重复要求。**只写在正文段落里的"记住"，下周他会再问一遍。**
9. **会后凡哥口述纠正 → 纪要要改，不是只记在心里**：本次他一句"小何是周五落地**智提分** 1.0"（原稿听成浪浪椰）→ 立刻改 `.md`、**重生成 `.docx`**、改台账/待办，并在原句留"凡哥 10-19 会后更正"字样可追溯。改完回复里明说"改了三处"。

### 交付前必查四项（2026-10-12 新增）

1. **新增章节先查编号，别直接叫「十、」** —— 本次往纪要尾部追加「十、凡哥会后补充」时，正文**已有**「十、待办事项」→ 冒出两个「十」，`grep "^## "` 一眼看出乱。做法：追加前先 `grep -n "^## "` 看现有编号，**接在最大号后面**（本次改成「十三、」），**并同步改子标题**（`10.1 → 13.1`）。改完再 `grep "^## "` 复核一遍顺序。
2. **改完 `.md` 必须重生成 `.docx`** —— 凡哥拿到手、要转发的是 **Word**，不是 md。本次一份纪要来回改了 6 轮（公司主体名 → 关键人物表 → REA 口径 → 云扉放弃 → 集团名 → 审核段），**每一轮都要**重跑 `md2docx_meeting.py`，否则他拿到的是旧版。**把它当交付前的最后一个动作**（与「自检 `**` 残留」一起做）。
3. **会上内容 vs 会后口述补充，分节记** —— 凡哥事后把会议外的新决策/新信息讲给你（本次：云扉放弃、并发方案任务、杨董身份、集团现名）时，**另开一节**（如「十三、会后补充（重要更新）」）并标日期，**不要混进会上的时间轴里**（会上纪要带时间戳、可回溯录音；会后补充没有录音支撑，混记会让\"哪句是会上说的\"失真）。凡哥认可这个分法。
4. **课题外的闲聊不入记录**（凡哥 2026-10-12：「那只是课题外的聊天内容，**不需要记住**」）—— 跟本次会议主题无关的闲谈，**不写进纪要、不落进清单/台账/记忆**；拿不准就先问一句，别自作聪明当\"背景补充\"存下来（存错了他要回头清）。

## 坑

- **中文长音频别用 CPU medium**（`media-learning` §2b 是给 ≤2 分钟短教程的）→ 70 分钟会磨到失去意义；用 GPU large-v3。
- **模型/下载**：`huggingface.co` 本机不通 → 一律 `HF_ENDPOINT=https://hf-mirror.com`；不要在这条路上反复试直连。
- **ffmpeg / python 等 native 程序**：路径写 `D:/...`，不写 `/d/...`（MSYS 不转换 → exit 127）。
- **别前台等**：转写放后台 + `notify=true`，同时分批读稿（同一轮里 wait → read 交替）。
- **音频别留在 cache**：跑完删 16k wav（实测 134MB），**模型留着复用**；原录音归凡哥（`D:\Hermes\attachments\`）。
- **长会一定有"重复讨论同一议题"**：按**议题**归并、不按发言顺序流水账（例：考核量化在 28–45 分钟反复出现 → 合成一节）。
- **会议里的数字/日期是承诺，不是事实**：写进待办时保留"会上说的"，并与台账/总控台交叉核对，冲突就问。
- **待办落进 JSON 台账/清单时，别用 patch 工具追加长条目**：长 `new_string` 会被截断 → JSON 校验失败（`Expecting ',' delimiter`）→ **整体拒写**。改用 `execute_code`：`json.loads` 读 → 前插/后插 → `json.dumps(..., ensure_ascii=False, indent=2)` 写 → **`json.loads` 回读校验一次**。凡是要往 `集团/台账数据.json`、`集团/凡哥例行与待办.json` 加条目，一律走这条。（2026-10-12 实测）
