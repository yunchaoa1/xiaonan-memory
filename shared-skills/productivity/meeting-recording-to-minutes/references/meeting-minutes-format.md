```markdown
| 会议性质 | 战略方向 + 管理制度 + 项目方向（非日常） |

## 关键人物（本记录涉及）—— **称呼 ↔ 身份 ↔ 在本项目里的角色，一行绑死**
| 称呼 | 身份 | 在本会 / 项目中的角色 |
|---|---|---|

## 一、速览：这场会定了什么
（8–12 条短句，每条＝一个结论；凡哥只看这一节也能抓住全场）

## 二、逐议题记录
### 1）<议题>（起始–结束 分钟）
- 结论 / 讨论要点 / 分歧（未决的显式标"待定"）
（按**议题**归并，不按发言顺序流水账；每条挂时间戳区间）

## 三、决议与共识
## 四、待办事项（见 §2 表）
## 五、小南的任务（"你也要参与进来"必须单列）

```

## 2. 待办表字段

| 字段 | 规则 |
|---|---|
| 事项 | 具体结果，不写主题词 |
| 责任人 | **会上明确认领 / 本人陈述**；没认领写「待认领」；**不按岗位推定** |
| 时间节点 | 会上说的原话（如"今天下午""节后""下周天使轮前"）；没说的写「待定」 |
| 验收标准 | 可观察到的东西（例：能生成 15–25 秒视频 / 出框架草图分多少个模块） |
| 来源 | 时间戳或议题号（便于回溯） |

- **决议 ≠ 提议**：吵过没定的写"待定/未决"，别写成决议。
- **小南的任务**单独一张表：只列我能独立交付的（打底稿、统计、技能化、台账），不要把自己的活混在团队待办里。
