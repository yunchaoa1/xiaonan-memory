# 产品教程制作（文本版 + 视频版）

## When to Use

- 凡哥说「做个教程」「写使用说明」「帮助文档」「教学视频」「培训材料」
- 要给客户 / 培训班 / 新员工出一套「这个产品怎么用」的东西
- 需要同时要文字版和视频版

不适用于：产品营销物料、宣传片、功能介绍 PPT（那是另一套，别混）。

凡哥说「做个教程」「写使用说明」「帮助文档」「教学视频」「给客户/培训班出一套怎么用的材料」时加载本技能。

## 0. 最高铁律：没进过真实界面，不写操作步骤

教程的每一步都必须是**真实界面上真实存在的按钮**。没亲自跑过产品 → 只能写到「结构和方法」这一层，操作细节必须由产品负责人提供（让他带我走一遍并录屏），**不许按截图或想象补齐**。

自检：这句话我是看着界面写的，还是想出来的？想出来的 → 不写。

## 1. 先定一件事：给谁看

**一次只问一个问题**：给第一次用的普通用户、给批量培训的学员、还是给老用户学进阶？

三种的深度、语气、单条时长完全不同。没定就开工 = 白做。

## 2. 依据（每条规矩都挂出处，别凭感觉）

| 规矩 | 依据 |
|---|---|
| 文档分四类不混写：手把手教程 / 任务指南 / 速查参考 / 原理解释 | Diátaxis <https://diataxis.fr/start-here/> |
| 手把手教程必须：有意义、做得完、路径合理、覆盖完整；小步、早出结果、具体 | Diátaxis 教程专页 <https://diataxis.fr/tutorials/> |
| 教学视频单条 < 6 分钟；讲解人画面与操作画面交替；家常录制可能优于棚拍 | Guo, Kim & Rubin 2014, ACM L@S'14, 690 万次观看记录 <https://up.csail.mit.edu/other-pubs/las2014-pguo-engagement.pdf> |
| 视频必须有同步字幕，字幕要标说话人 | WCAG 2.2 SC 1.2.2（A 级）<https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html> |
| 开头写范围 + 不在这页讲什么 + 写给谁 + 前置；结论先给 | 谷歌技术写作 <https://developers.google.com/tech-writing/one/documents> |
| 课程 / 单功能短视频 / 帮助中心三套分开 | Runway 教学站实际结构 <https://academy.runwayml.com/> |

引用原文与边界说明见 `references/tutorial-method-evidence.md`。

## 3. 分类：四类入口，视频只做前两类

1. **入门一条龙** —— 从注册到导出第一个成品，手把手，全流程只做一条
2. **任务指南** —— 「我要做某某事」，一个任务一页
3. **速查参考** —— 参数、上限、格式，只列不解释
4. **原理解释** —— 为什么这么设计

视频版只做 1、2。第 3、4 类做成视频既费时又没人看。

## 4. 唯一真源：底稿表

一行 = 一个任务，六个字段：**任务名 / 给谁 / 开始前准备 / 步骤 / 每步看到的画面 / 最容易错在哪**（另加时长、两版状态）。

文字版照它写，视频版照它录。产品改版只改这一行，两版一起改。

模板：`templates/教程底稿表.csv`

## 5. 文本页骨架（固定，不许改顺序）

```
# 动词开头的标题
> 这页讲什么 / 讲给谁 / 开始前准备 / 这页不讲
## 做完你会得到（先给结果 + 结果截图）
## 步骤
1. 做什么 → 你应该看到什么
2. ……
## 做不出来先看这里（三个最常见错 + 怎么退回）
## 下一步
```

硬规矩：
- **每步必须写「你应该看到什么」**——学员卡住时唯一能自救的线索
- 一步一个动作，出现「然后」「同时」就拆开
- 按钮名用界面原文，不写「点击相应按钮」这种话
- 截图必须自己当版截，不用旧图、不用别人给的

模板：`templates/文本教程页.md`

## 6. 视频规格与结构

- 一条一个任务，3-6 分钟，超 6 分钟拆
- 标题写成果不写功能名：写「做出第一条 15 秒短剧」，不写「节点编辑器介绍」
- 结构：前 20 秒放做完的样子 → 录屏实操配讲解 → 最后 15 秒「你刚学会了什么、下一步看哪条」
- 讲解人小窗/人头穿插在操作画面里（论文结论），不必棚拍
- 字幕单独做，术语和按钮名按界面原文；烧一份 + 留一份 `.srt`
- 默认 1920×1080 / 30 帧 / 16:9（凡哥定了发布渠道再调）

模板：`templates/视频脚本.md`

## 7. 本机能力（已实测）

| 需求 | 做法 | 状态 |
|---|---|---|
| 全屏录屏 | `/d/tools/ffmpeg/ffmpeg -f gdigrab -framerate 30 -i desktop -pix_fmt yuv420p out.mp4` | 实测可出片 |
| 中文配音 | `python -c "import asyncio,edge_tts; ...Communicate(text,'zh-CN-YunxiNeural')"` | 实测可出声 |
| 剪辑/拼接/压片 | 同一个 ffmpeg（在 `/d/tools/ffmpeg/`） | 可用 |
| 烧字幕 | `-vf subtitles=xx.srt`（需要 libass） | **未验证**，先跑一条短片确认再承诺 |

脚本：`scripts/record-screen.sh`（录屏，Ctrl+C 停）

TTS 是机器音，凡哥要求真人讲解时改用他或产品负责人录音，脚本不变。

## 8. 生产顺序（别一上来铺全量）

1. 定受众（一个问题）
2. 产品负责人带我走一遍主线，全程录屏当原始素材
3. 底稿表只填三个卡点（S01-S03）
4. 出三页文本 + 三条样片
5. 找个没用过的人照做一遍 → 卡在哪改哪
6. 模板定死，再批量做剩下的

## 9. 验收标准（只有一条）

**一个没用过的人，照教程做完，能出成品。** 中途问「这步在哪」就算没通过，回去改那一步。

不看写得漂不漂亮。

## 10. 坑

- 没进产品就写步骤 → 全是废的（铁律 0）
- 把「教程」和「任务指南」混写 → 两边都不好用
- 视频拍成功能介绍（点这个按钮、那个按钮）→ 没有成果锚点，看完不会做
- 一次做 30 条再给凡哥看 → 方向错了全废，先三条打样
- 用自动识别字幕直接出 → 术语和按钮名全错
- 用旧版界面截图 → 改版后教程变错误指引
- 拿干净账号录屏前不清桌面/书签/私聊窗口 → 泄露无关信息
- 凡哥说「我只要教程」时别顺手做成产品介绍片或营销物料

## 11. 落到哪里

`D:\Documents\我的文档\01_项目\<项目名>\教程\`，下分 `底稿\ 文本版\ 视频版\ 成品\`。
按 `D:\Documents\我的文档\目录规范.md`：项目产出进 01_项目，不为教程新开一级目录。
