# 开工前把规则源读全（2026-11-23 血的教训）

## 实证：用了 1/6 等于没用

一个技能目录：**54 份文件、20.8 万字**（主文件 + 20 份 references + 脚本 + 测试）。
实际只读了 **5 份（25%）**，漏掉的里面有一份 `checklist.md` —— **62 项检查清单**。

结果：成片做出来了、机检"全绿"、我自己验收也过了，用户一看就否：**"人的面部表情""说话的节奏一直不变"**。
两个毛病都在漏掉的那几份里写着怎么处理。

## 规范怎么说（Anthropic Agent Skills）

**渐进式披露，三级**：

```
第一级  name + description      预加载（约 100 tokens/技能）
第二级  SKILL.md 正文            判断相关才读，建议 <500 行
第三级  references/scripts/assets  按需读，不读不占 token；脚本是跑的，不是读的
```

**所以"全读 20 万字"是错的**（违背设计，挤爆上下文），**"凭判断挑几份"也是错的**（一挑必漏）。

## 真正的病：读了指令，没执行它指向的下一步

> 「技能选择和执行是两件事。失败可能因为选错技能，也可能因为**选对了、然后跳步**。」

实际情况是第二种：

- 技能选对了 ✅
- `SKILL.md` 也读了 ✅
- 里面第 12 条写着「情绪必须落成四区肌肉，**详见 `acting-facs.md`**」
- **读到了这句话，没去点开那个文件** ❌

因为读的时候脑子里在想"这次要解决的是 A 问题"，把"表演层"当成锦上添花跳过去了。

## 机检的盲区：抓不到"缺席"

机检能抓「你写了错的词」，抓不到「你什么都没写」。

`checklist` 里机检栏标 `—` 的，就是**机器管不着、必须人眼过**的项。实测这类项恰恰是最容易漏的：

| 检查项 | 机检 | 实情 |
|---|---|---|
| 情绪落成肌肉动作 | 有（只抓"写了结论词"） | 抓不到"一个动作都没写" |
| 不说话的人有反应 | **无** | 必须人眼 |
| 说话镜写了视线落点 | **无** | 必须人眼 |
| 台词标点落到身体上 | **无** | 必须人眼 |

**所以"机检全绿"不能当验收结论。**

## 正确流程

```
① 读 SKILL.md 全文（它 <500 行，是目录 + 铁律）
② 把里面每一条指向 references/xxx.md 的铁律列出来 → 这就是必读清单
③ 按清单逐份读，不按自己判断挑
④ 技能自带的执行清单（checklist / gates / scripts）逐项打勾，这是执行关不是参考
⑤ 机检必须跑，FAIL 清零
⑥ checklist 里机检标 — 的，逐条人眼过
```

## 一句话判据

**不是"我读了多少"，是"技能让我做的，我做了几步"。**

## 附：用户为这件事批评过的原话

- 「能解决这个问题吗？」（追问机制，不要决心）
- 「我觉得你太武断了，你去查查 agent 该如何正确的调用 skill」（**做机制前先查规范，别自己发明**）
- 「技能摆在那头一次你没用，这一次你是用了还用不全」（两次不同病因：选错 / 跳步）
