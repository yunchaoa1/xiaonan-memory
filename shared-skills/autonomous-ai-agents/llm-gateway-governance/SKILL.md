# LLM Gateway Governance · 多人 LLM 调用收口治理

## When to Use

公司/团队里 **N 个人各自注册大模型账号、各充各的钱**（自建 key、各调各的），导致：

1. **统计不了** —— N 个后台 N 份账单，加起来才知道花了多少
2. **管不了** —— 谁的 key 泄露、谁在跑死循环，看不见也拦不住
3. **财务走不通** —— 个人充值发票抬头不是公司，报销困难
4. **成本失控** —— 峰谷价差、批量任务跑在高峰时段、没人调度

或者用户直接问"我们几个人都在用大模型，怎么弄合适""怎么统一管理/统计 LLM 用量"。

**这是组织级的成本与权限治理，不是单 Agent 调优。** 单 Agent 省 token 看 `agent-cost-optimization`；
本技能管的是"一个组织的调用入口、身份、账目"。

## Core Model

### 收口三层，缺一层都不成立

```
① 账号收口：N 个散账号 ──► 1 个企业/组织实名账号
② 入口收口：所有人 ──► 1 个自建网关（base_url 指向它）
③ 身份收口：网关发出的请求带身份 ──► 可按人统计、限流、吊销
```

只做①：官方后台只能看账号总量，按人分不出来。
只做①②，不做③：网关看得见流量，但分不清人。
**③ 是这套方案的价值所在** —— 开发者手上只拿虚拟 key，真实 key 只存在网关里。

### 先核实上游平台的能力边界（不要假设）

动手前必须查清上游官方到底有没有：子账号 / 团队 / 按 key 用量 / 按 key 限流 / 企业套餐。
**大多数国产大模型开放平合没有这些**，如果假设有，方案会整个做错。

判定方法：抓官方文档站 `sitemap.xml`，把全部页面过一遍再下结论（页面数量少，一次就能核完）。
结论要写进交付物，并注明"已核 sitemap N 页"。

### 一个高频关键坑：Agent 工具不上报身份

用 **Agent 工具（Claude Code / Codex / OpenCode / Cursor / Cline 之类）写代码调 API** 的场景，
工具不会在请求里带用户标识。于是：

- 官方那套 `user_id` 参数在 Agent 场景**基本用不上** → 别把它当方案
- "按人统计"只能靠**网关侧**做：每人一把虚拟 key，网关按 key 记账
- 部分网关（如 LiteLLM）能**强制把出站 user 参数覆盖成调用方身份**，正好补上这个缺口

### 三档方案与选型

| 档 | 做法 | 能统计 | 能管 | 代价 |
|----|------|--------|------|------|
| ① 最轻 | 收口到一个组织账号 + 每人一个 key（代码里带身份参数） | 只能看总量，按人要翻日志 | 只能事后追责 | 几乎为零 |
| ② 自建网关（**几人规模首选**） | ①之上加一台网关，每人发虚拟 key | ✅ 看板按人看 token/费用/次数 | ✅ 额度上限、模型白名单、审计、一键吊销 | 一台机器 + 半天 |
| ③ 厂商企业套餐 | 走云厂商/聚合平台的企业版 | ✅ | ✅ | 贵、绑厂商 |

选型口诀：**人少（≤10）且自己写代码 → 自建；不想运维 → 买企业套餐。**

## Procedure

### 1. 问清三件事再出方案（其余自己判断，不要连环追问）

- **账号现状**：各自注册各充各的钱，还是已有共用账号？
- **使用形态**：写代码/Agent 调 API（能被网关接管），还是主要用网页版聊天（网页版进不了网关，要另想办法）？
- **有没有常开机器**：内网闲置机 / 云服务器 / 什么都没有？

形态决定了网关能不能覆盖全部调用。**如果用户用的是网页版，先说清网关接管不了，再给方案。**

### 2. 定硬件

- **云服务器（推荐）**：最低档即可；人在哪都能连；⚠️ **不要架在个人工作机上**（关机全组断）
- 内网常开机器：省钱，但要求同网段可达
- 配置口径：几人的网关 + 数据库，2 核 4G 舒服，2 核 2G 也能跑；系统 **Ubuntu 22.04 LTS**
- 选型的判断依据：**公司已有云账号就复用** —— 省一整套实名，发票也好开

### 3. 拆分人机分工（这一步决定用户体感）

把任务撕成"只能用户本人办"和"代理能办"两摞，写进交付物，逐条标负责人：

| 只能用户本人 | 代理能办 |
|---|---|
| 主体实名认证（需执照/授权） | 服务器上装网关、配渠道 |
| 付款 / 对公汇款 / 发票 | 建账号、发虚拟 key、设额度 |
| 提供 key、服务器 IP、云控制台 | 验收脚本、成员接入一页纸、文档 |

### 4. 交付物清单（缺一项用户就会卡住）

```
README.md                 总览：问题/方案/铁律/进度勾选
01-用户操作手册.md         只写"用户本人办"的部分，零基础分步
02-云服务器采购指南.md     买哪家/什么配置/买完给我哪三样
deploy/docker-compose.yml 网关编排（✅ 用官方模板做底稿，别自己写）
deploy/bootstrap.sh       一键部署（装 Docker→生成随机密码→起服务→打印地址）
deploy/部署步骤.md         代理执行清单，含验收
03-成员接入配置.md         每人一页纸：改 base_url + 换 key（等知道具体工具再写）
```

### 5. 部署要点

- **compose 必须用官方仓库的现成文件做底稿**，只改：把默认弱密码换成随机强密码、补 `SESSION_SECRET`、
  不对外暴露数据库/缓存端口。**不要凭记忆手搓 compose。**
- 部署脚本自动生成随机密码并写回 compose，避免默认密码裸奔
- **云控制台防火墙要单独放行网关端口**（如 3000）—— 这一步在控制台里做，不在服务器里

### 6. 验收（必须实测，不许自报成功）

```bash
curl http://<网关IP>:3000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-<某成员的虚拟key>" \
  -d '{"model":"<模型名>","messages":[{"role":"user","content":"你好"}]}'
```

- [ ] 返回正常回复
- [ ] 网关后台日志能看到这次调用：谁的令牌、多少 token、扣多少额度
- [ ] 故意用错 key → 正常报错（没漏放）
- [ ] 默认管理员密码已改

### 7. 成员接入

每个成员只改两处：**base_url 指到网关** + **key 换成虚拟 key**。
按成员实际用的 Agent 工具写对应配置（**问清楚是哪几个工具再写，不要脑补**）；
兼容性（尤其走 Anthropic 格式的 Claude Code 类工具）**要在部署时逐个实测**，
不能只凭文档就说"支持"。

## Teaching the user (凡哥) the parts only he can do

用户说"我不会，你一步一步教我"时：

1. 先给**路线图**（5 行以内，让他知道总共几步、哪几步是他的）
2. 每步写成 **打开哪个网址 → 点哪里 → 填什么 → 会看到什么 → 完成标志**
3. **不要脑补界面路径**。没登录过他的账号，就写"具体按钮以你屏幕上看到的为准"
4. 明确说 **"卡住就截图发我，我读图告诉你下一步"** —— 这是最快也最不会出错的路径
5. 把"不可逆"的坑前置警告（见 Pitfalls），别等他点完了才说
6. 涉及公司主体、财务、用章时**提醒他先跟相关同事打招呼**，不要让他办到一半被卡住

## Pitfalls

- ❌ **假设官方平台有子账号/团队/按 key 统计** → 先核官方文档全站 sitemap 再下结论
- ❌ **把"每人发一个 API key"当成能分账** → 并发和账单很可能按**账号**计，与 key 无关
- ❌ **企业实名不可逆** → 个人实名账号不要直接改成企业（多数平台不允许改回）。先确认主体，必要时新注册
- ❌ **对公汇款方开户名与实名名称不一致** → 钱进不来。这一条必须一字不差地警告
- ❌ 把网关架在个人工作机上 → 关机全组断
- ❌ 只说"部署完了"，不验云控制台防火墙 → 90% 的"打不开"是这原因，不是服务没起
- ❌ 默认管理员密码不改就上公网 → 官方 README 明确警告，等于裸奔
- ❌ 价格用记忆里的数字 → 用第三方比价文章时**标注来源和"会变"**，并提醒看**续费价**而非首年活动价
- ❌ 拿"未实测"当"已验证" → 上游兼容性、模型可用性一律标注验证状态

## Verification Checklist

- [ ] 上游平台的团队/子账号/按 key 统计能力已核官方文档
- [ ] 使用形态（Agent 调 API vs 网页版）已确认，覆盖范围说清
- [ ] 交付物清单齐（含"只能用户办"的分步手册）
- [ ] compose 来自官方底稿，密码已随机化
- [ ] 防火墙端口已放行并在浏览器验证
- [ ] 默认密码已改
- [ ] 端到端 curl 实测通过 + 后台日志对得上
- [ ] 各成员 Agent 工具兼容性逐个实测，未测的标注未测
