# 网关方案与选型 · 参考

## 一、三档方案（按团队规模选）

| 档 | 做法 | 统计 | 管控 | 成本/工作量 |
|----|------|------|------|------|
| ① 最轻 | 收口到 1 个组织账号 + 每人一个 key + 代码带身份参数 | 只能看账号总量 | 事后追责 | ≈0，半天 |
| ② **自建网关**（几人~几十人首选） | 网关统一入口，每人虚拟 key | ✅ 按人看 token/费用/次数 | ✅ 额度上限、模型白名单、审计日志、一键吊销 | 一台机器 + 半天~一天，软件 0 元 |
| ③ 厂商企业套餐 | 云厂商/聚合平台企业版（有"多 Key 配额分配""统一 Key + 用量看板"这类现成能力） | ✅ | ✅ | 贵、绑厂商，但不运维 |

**判断**：人少（≤10）且自己写代码 → 自建更划算；完全不运维 → 买企业套餐。

## 二、自建网关选型对比

| | **New API**（推荐入门） | One API | LiteLLM Proxy |
|---|---|---|---|
| 定位 | 中文生态、UI 完善、开箱即用 | New API 的上游项目，同类，更简 | 企业级虚拟密钥与预算治理 |
| 部署 | 官方 compose 一键（**New API + Postgres + Redis**） | 单可执行文件 + Docker | 需要 Postgres |
| 用量/成本 | 后台看板：按令牌/用户看用量、成本分析 | 有基础统计 | 按 key/user/team 追踪支出，内置各模型成本表 |
| 额度控制 | 用户**配额余额**、分组、状态 | 有 | 按 key / user / team 的 `max_budget`、周期自动重置、超预算拦截、TPM 限速 |
| 身份补位 | 令牌维度记账 | 同 | **可强制把出站 user 参数覆盖成调用方身份**（补上 Agent 工具不带身份的缺口） |
| 多上游 key | 渠道**多 Key 模式**（轮询/加权随机，坏 key 自动跳过） | 有 | 支持 |
| 适合 | 中文团队、要好上手、几人的规模 | 极简需求 | 需要精细预算/团队治理 |

**结论口径**：几个人 + 要中文后台 + 想当天跑通 → **New API**；
要按人/按团队设硬预算和自动重置、或要接多上游统一治理 → **LiteLLM**。

## 三、New API 关键操作（据官方文档）

- **渠道管理** `/console/channel` → 右上「添加渠道」→ 选服务商类型 → 填渠道名 + **API Key** →
  勾选模型（或「填入默认模型」）→ 高级配置可填 **Base URL / 优先级 / 权重 / 模型映射 / 参数覆盖 / 自动禁用** → 提交。
  列表里点「测试」单个渠道，或「测试所有渠道」。
  一个渠道放多把 key：编辑渠道 → **多 Key 管理** → 轮询模式（Round Robin / 加权随机）。
- **用户管理** `/console/user` → 列表 → 「编辑」可改 **角色 / 分组 / 配额余额 / 状态（禁用即无法登录）**。
- **API 令牌** `/console/api-token`（每个账号自己的令牌）。
- ⚠️ 界面细节以实际控制台为准，实操时对照官方文档核对，别凭记忆写步骤。

## 四、云服务器选型口径（自建方案）

| 项 | 建议 |
|---|---|
| 厂商 | 腾讯云 **轻量应用服务器 Lighthouse** / 阿里云轻量（**公司已有云账号就复用**，省实名、发票好开） |
| 配置 | **2 核 4G** 舒服（网关+DB+缓存），2 核 2G 也能跑 |
| 镜像 | **Ubuntu 22.04 LTS 纯净系统镜像**（别选花哨应用镜像，Docker 自己装） |
| 系统盘 | 50G 起 |
| 地域 | 就近（上海/广州/北京） |
| 带宽 | 套餐自带够用（网关只转发文本，不吃带宽） |
| 防火墙 | **单独放行网关端口（如 3000）** —— 在云控制台里配，不在服务器里 |

价格：2 核 2G 约百元/年级、2 核 4G 约两百元/年级（⚠️ 第三方比价文章的活动价，**会变**；
低价多是新用户首购价，**看续费价再下单**）。以官网实时为准。

## 五、部署后加固（建议，可后补）

- SSH 改密钥登录、关密码登录
- 网关端口来源限制到公司出口 IP
- Nginx + HTTPS（避免 key 明文过网）
- 定期备份：`tar czf newapi-backup-$(date +%F).tar.gz data/ docker-compose.yml`

## 六、合规口径

自建内部网关属于正当用法（官方项目合规声明的适用场景：合法授权的 API 网关、内部管理、私有化部署）。
但要注意：**上游服务条款、平台规则、内容安全要求仍然适用**；官方 API 流量走境内服务器，
敏感数据该私有化部署就私有化（不要用公开 API 传敏感数据）。
