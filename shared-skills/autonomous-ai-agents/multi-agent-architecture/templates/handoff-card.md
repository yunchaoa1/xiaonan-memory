# 结构化交接卡（Handoff Card）模板

**用途**：多 agent/多岗位之间**交接只传字段、不传原文** —— 这是治"上下文溢出"的核心动作；
同时让"谁欠谁什么、什么时候交、怎么算过"一目了然。

**为什么是这张卡**：字段与凡哥定的一模一样 ——
- 拓扑图模块卡：`开始时间 / 预计交付 / 状态 /（超期）卡点 / 解决方案 / 再次交付时间`
- 日报三段式：`今日完成 / 卡点 / 解决方法`
→ 直接把现成流程的字段复用到 agent 交接上，**不需要发明新协议**。

## 模板（复制改内容）

```markdown
## 交接卡 · <上游节点> → <下游节点>

- 项目 / 模块：
- 责任人：上游 <谁> → 下游 <谁>
- 输入物（下游需要的字段，逐条列；只列需要的，不给原文）：
  - 例：本集剧本全文 / 角色清单（含母版ID）/ 场景清单 / 关键情节 3-5 条 / 情绪曲线
- 输出物（下游要交回什么，含格式与长度要求）：
- 验收标准（可判定，例：字段齐全 / 分镜数 ≥ N / 情节无断点）：
- 卡点（有则写：卡在谁、卡在哪一步）：
- 期限：开始 / 预计交付 /（超期时）再次交付：
- 引用指针（要细节时去哪取：文件路径 / 资产ID / 版本号）：
```

## 使用规则

1. **输入物只列"下游真正要用的字段"** —— 想给原文的时候，问一句"这个字段下游用得到吗？用不到就换成引用指针"。
2. **验收标准必须可判定**（数字/字段/清单），不写"质量好"这类词。
3. **卡点照日报的写法**：卡在哪 + 谁卡着 + 解决方案；超期一定写**再次交付时间**。
4. **Agent 化时**：上游子图返回 = 填"输出物"字段；下游子图入参 = 只吃"输入物"字段（其余走引用指针）。
5. 交接处**加校验**：字段缺失/长度异常 → 自动回上一步重跑或告警（别静默吞）。
