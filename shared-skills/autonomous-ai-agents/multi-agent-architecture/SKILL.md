# 多 agent 体系 · 上下文工程

**用途**：处理"多 agent 怎么搭 / 上下文为什么爆 / 团队怎么 agent 化"这一类问题。
当前场景锚点：**影剧工坊**（原制剧工作流）的卡点＝「上下文超出导致的情节崩塌」；**小李（李林）**给方案＝LangGraph 全局图 + 子图；**小唐（唐光辉）**在做集团/团队级多 agent 体系（先做**团队镜像 agent**）。

## When to Use
- 凡哥说「多 agent / 多智能体 / 一个主导几个专业干活的 / 团队镜像 agent」
- 凡哥说「LangGraph / 全局图 / 子图 / 上下文溢出 / 上下文投影」或要求**科普**
- 要给小李/小唐出**设计素材**，或把"上下文治理"写进影剧工坊的待办/验收口径
- 要把团队协作流程（日报、交接、验收）agent 化

## 一、LangGraph 全局图 + 子图（官方文档已核，2026-09-21）

一句话：**把"AI 干活"画成流程图**——节点＝动作，边＝流向（可条件分流/回退），一块 **State 黑板**在图上流动，**checkpointer** 逐步存档、断点续跑。

| 概念 | 大白话 |
|---|---|
| State | 带字段的黑板（剧本/分镜/资产/进度/卡点），节点读它改它 |
| 节点 / 边 | 节点＝一个动作；边＝顺序；条件边＝按结果决定下一步（校验不过→回上一步） |
| Checkpointer | 每步自动存档 → 断点恢复（＝小何日报里那个"断点恢复"的工业级版） |
| **全局图（父图）** | 总调度/项目经理：定顺序、分流、返工，持有**全局黑板** |
| **子图** | 一个专业岗位的完整小流程（剧本/分镜/生图/视频…），**内部对父图不可见**（只认输入输出接口） |

**两种接法（官方原表）**：
1. **子图直接挂成节点**（`add_node`）→ 父子**共用同名字段**；
2. **在节点里调用子图** → 父子**各自一套字段** + 中间写转换函数 ← **我们要的是这种**（每个岗位只拿自己那份，不吞全剧原文）。

多层可嵌套：全局 → 子 → 孙。细节原文摘录见 `references/langgraph-subgraphs-official.md`。

## 二、它为什么能解「上下文超出 → 情节崩塌」

现在的问题：每一步都把前面**所有原文**塞给模型 → 越到后面越长 → 超上下文 → 截断 → 情节崩 / 内容短缺。

| 动作 | 治什么 |
|---|---|
| **上下文隔离** | 子图只能看到自己那套键（官方："子/父的键在这里根本访问不到"）→ 剧本原文不会一路灌到生视频 |
| **交接结构化** | 父子之间传**字段**不传原文（→分镜只给：角色清单/场景/关键情节/情绪曲线）→ 上下文从"整部剧"降到"一集/一段" |
| **投影 + 落盘** | 全局黑板只留**摘要+引用指针**，要细节按指针取（＝小何说的"上下文投影"）；每步存档＝断点恢复 |
| **交接校验边** | 校验字段完整性/长度阈值，不足→**自动回上一步或告警**（治"内容短缺"被静默吞） |

### ⚠ 必须先知道的坑（官方文档明写，且极像我们卡点的成因）
> **子图有自己的 checkpoint 命名空间 —— 子图更新了状态，父图可能看不到（不是立即同步）。**

没处理就会"**父图以为拿到了，其实是旧的/空的**"。官方两个解法：① 用 **Store** 传跨图数据；② 配置**子图直接写父图检查点**。
→ **点名让小李/小何在影剧工坊里重点验这一条**（先验"父子状态可见性"，再谈其它）。

**Checkpointer vs Store（官方分工）**：checkpointer＝线程内短期（会话连续性 / human-in-the-loop / 容错）；Store＝跨线程长期（用户偏好、事实、共享知识）。

## 三、团队镜像 agent（凡哥 2026-09-23 提）

**目标**：以我们 5 人团队为原型，做"**一主导 + 多专业**"多 agent 体系（先做**镜像团队**版），主导 agent 像凡哥一样接需求、拆模块、派活、盯卡点、验收。

| 角色 | 人 | agent 职责 | 私有记忆/技能 |
|---|---|---|---|
| **全局图 · 主导** | 谢泽凡 | 接需求→拆模块→派活→盯进度与卡点→验收→复盘 | 总控台 + 拓扑图 + 台账 |
| 子图 · 后端/框架 | 何锦波 | 应用与后台连接、接口、数据流、部署、断点恢复 | 架构与部署规范、LangGraph 编排 |
| 子图 · 前端/UI | 吴伟俊 | 界面、交互、组件、构建打包、多端适配 | 设计规范、组件库 |
| 子图 · 多 agent 体系 | 唐光辉 | agent 架构、编排、评估、落地 | 多 agent 设计模式 |
| 子图 · 上下文治理 | 李林 | 上下文预算、子图切分、检索/投影、模型调优 | 上下文工程、评测集 |

**三个关键设计点**
1. 每个 agent **只拿自己那份字段**（＝第一节的隔离机制）
2. 交接用**结构化交接卡**（输入物/输出物/验收标准/卡点/期限）→ **凡哥的日报字段就是这个协议**，直接复用（模板见 `templates/handoff-card.md`）
3. 记忆两层：**全局黑板**（DASHBOARD/拓扑图，长期）+ **子图私有记忆**（各自技能与资产）

**落地三步（建议）**：① 主导 + 2 专业（后端+前端）跑最小闭环，接一个真任务 ② 再加"上下文治理""多 agent 设计"两子图 ③ 才扩到 5 人全镜像 + 返工循环。

**风险（别当万能药）**：工程改造不是改参数（拆图+定字段+写转换+加校验）；先用**一集剧本**跑通"剧本→分镜→生图"再扩链；跨集一致性要靠**角色母版/设定**当锚点，否则各子图各写各的。

## 四、流程纪律（跟凡哥/同事干这类活）

- **科普先核后讲**：凡哥要证据分级（实测 > 官方 > 传闻）——先拉官方文档再开口，**给出来源**，不凭记忆讲。
- **交付形态未定不动工**：给 **A. 设计蓝图 / B. 真搭 / C. 先蓝图后落地** 三选项等凡哥拍板；顺带列清"要确认的 3 件事"。
- **平级只给素材**：小唐是多 agent 体系的设计人 → 我们出的是**参考素材**，不越位定制度、不替他改设计（卡耐基口径）。
- **口径以凡哥为准**：小唐＝**唐**光辉（2026-09-23 确认；凡哥先打成"堂"、随后更正）；只在凡哥给了口径后落记录。
- **「只是告知情况」≠ 要方案（2026-09-23 凡哥纠正）**：他介绍团队变动 / 新同事分工 / 集团情况时，**只记录 + 理解，不主动产出设计内容或方案**——本次小南把本技能第三节的镜像设计直接交出去，被回「我只是告诉你我们团队现在的情况，**不需要你来定内容**」。
  → 分级：**他要的（科普/解释/记录）可以给；他没要的（设计/蓝图/落地建议）等他明说**。问一句「要不要我出方案」比自己先出一份便宜得多。
