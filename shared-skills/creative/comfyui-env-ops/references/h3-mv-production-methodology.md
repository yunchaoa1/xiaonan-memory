## 一、标准前置流程：5 步，Treatment 先于 Storyboard（🟡🔵）

| 步 | 产出 | 干什么 |
|---|---|---|
| 1. Song Intent | 几句话 | 情绪弧 + 目标听众 |
| 2. **Treatment**（1-5 页） | 概念文档 | 概念 / 视觉语言规则 / 段落推进 / 参考意图 / 约束 |
| 3. Storyboard | 帧序列 | 构图、机位、运动、转场连续性 |
| 4. Shot List | 表格 | 要出什么、什么顺序 |
| 5. Production | 素材 | 生成 / 拍摄 |

**关键判断（业界）**：Treatment 修订便宜，Storyboard 修订贵 → 先把"这片子是什么"定死，再进"怎么拍"。
**我们自己那版的毛病**：从歌直接跳到提示词，**整个跳过了 Treatment 层**。

## 二、MV 分镜 ≠ 电影分镜（🔵，AI 同样适用）

- **跟歌走，不跟剧本走**（歌的时长是锁死的，分镜必须倒推自音轨）
- 每帧带**时间码或小节号**（传统板写 `Bar 17, beat 1`），不是只有构图
- **表演层 + 概念层双轨**并行，标出交汇点（哪段从表演切到叙事）
- **副歌重复必须"升级"**（三次副歌不能一样，否则第二遍就疲）
- **长镜头是 1 帧，不是 5 帧**（写"hold 4 bars"，不是画 4 张几乎一样的图）

## 三、段落 → 视觉职能 → 镜头类型（🟡 H3 专用）

| 歌段 | 视觉职能 | H3 镜头类型 |
|---|---|---|
| Intro | 建立世界与视觉语言 | 广角环境 / 物件母题 |
| Verse | 引入表演者或叙事动作 | 中景表演 + 故事插入镜 |
| Pre-chorus | 提速、制造预期 | 移动镜头、更紧的剪辑、渐亮 |
| Chorus | **最强的可重复画面** | 英雄表演 / 群体动作 / 变身 |
| Bridge | 制造对比 | 新地点 / 慢动作 / 抽象 |
| Outro | 收 | 回到母题 / 淡出 |

**「视觉系统一页纸」**（写提示词前必须定）：表演者身份+发型+服装+配饰+妆容 ｜ 2-3 个复用地点 ｜ 色彩与灯光规则 ｜ 主歌与副歌各自的镜头规则 ｜ 重复的物件母题 ｜ 画幅与交付分辨率 ｜ **哪些段落有可见演唱** ｜ 哪些声音来自模型、哪些来自母带。

## 四、镜数量级：H3 与传统差一个层级（最容易搞错）

| | 镜数（4 分钟歌） |
|---|---|
| 传统真人 MV | **80-150 镜** |
| 传统分镜帧数标准 | 40-80 帧 |
| **H3**（单镜 4-15 秒） | **10-30 镜**（2:30 的歌 ≈ 10-17 镜） |

→ **H3 一镜扛一整个段落职能**；**"逐句配图"是错的**（传统 MV 可以，H3 不行）。

## 五、H3 硬约束

- 单次生成 **4-15 秒**（15 秒是单次上限，不是项目上限 → 分段生成再拼接）
- 素材上限：图 ≤9 ｜ 视频 ≤3 ｜ 音频 ≤3 ｜ **合计 ≤12**
- 切镜铁律：**5s = 1-2 镜 / 10s = 2-3 镜 / 15s = 3-4 镜**；**切越多脸越漂**
- 提示词 ≤7,000 字符，**无独立负向提示词字段**
- 长宽须 **32 的倍数**；768p 探索 / 2K 交付
- ⚠️ **音频上限分两套口径**（云端 API ≤15 秒 / 本地开源权重不受限）→ 详见 `references/h3-audio-duration-and-limits.md`（含 `duration` 实际生效值、输出音轨由模型生成等源码级事实；⚠️ 该节点 `widgets_values_named` 写 9、**按位数组写 15 —— 生效的是 15**，别只读按名那份）

## 六、参考图必须各司其职

- **上传槽位顺序 = 提示词编号**（从上到下、从左到右 = `参考图1…9`；写"图 1 里的女人"）
- **每个文件一个窄职责**，禁止"五个文件都去描述同一个电影感"：
  图 → 锁身份 / 产品几何 / 文字 / 环境 / 关键帧；视频 → 运动 / 镜头语言 / 节奏；音频 → 音色 / 语速 / 节拍
- 上传前**删冗余参考**（两张冲突角度的角色图、三块不同色板的风格板 → 只会让失败更难诊断）
- 组合描述写**一句话**（谁在哪、和什么互动），**不要写清单**（清单会让三样东西各干各的）

## 七、提示词写法（🟡 H3 指南共识）

- 字段顺序固定：`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`（Singularity 的官方规范另加 `id`/`subject_definitions`/`summary`/`retention_analysis`/`detailed_description` 七段结构）
- **时间轴标签**：`Shot 1` 不带时间戳；后续每镜 `[Shot 2] At 00:03.000, ...`。切镜要引入**真正的新信息**（新主体/新空间/新视角），只是景别变了就推镜头、别切
- **运镜写成一句完整话**：运动类型 + 幅度 + 速度（"相机小幅度慢速推近"）
- **情绪写可观察行为**："固定向下凝视、手指静止、肩膀抬起" > "悲伤"（实测会被字面执行）
- **明确写"相机不动"** 比不写更好（不写会持续漂移重新构图）
- 时长诚实：标注的起止必须等于实际生成秒数
- 禁空词：`cinematic` / `dynamic camera` / `cool VFX` / `epic` / `high quality`（说了等于没说）

## 八、可直接落地的产出物（建议采纳）

1. **Treatment 一页纸**：概念一句 + 视觉语言规则 + 6 段职能表 + 约束
2. **AV 双栏分镜表**（🔵 celtx / studiobinder 的 MV 标准格式）字段：
   `镜号 ｜ 时间码/小节 ｜ 时长 ｜ 层次(表演/叙事) ｜ 景别 ｜ 机位与运动 ｜ 内容 ｜ 歌词/段落cue ｜ 是否对口型 ｜ sync point 标记 ｜ 所需参考图`
3. **Sync Points 清单**：必须命中的时刻（drop、hook 首句、静音切点）
4. **视觉系统一页纸**（见第三节）

## 十、配套：系统学习手册（8 模块）与「他要的学习材料长什么样」

凡哥看完上面的方法论后原话：「**看来我很还需要专项学习一下，minimax h3 制作MV的知识**」。
**他要的不是零散技巧，是一份成体系的专项学习手册** —— 以后凡哥提「专项学习 / 我得学一下 X」时，
产出物应当是「模块化 + 每节有证据分级 + 能当教材读」的文档，而不是几条 tip 或一段解释。

8 模块骨架（本次实际交付的结构，可直接复用）：

| 模块 | 内容 |
|---|---|
| ① 心智模型 | H3 不是「文生视频」，是**音视频联合生成**的多模态缝合器 |
| ② 输入系统 | 三类素材三种职责 / **槽位顺序 = 提示词编号** / 数量上限 / 本地 vs API 两套口径 |
| ③ 提示词规范 | 七段结构，含 **`<Subject N>` ≠ `<Picture N>`** 这个最大的坑 |
| ④ 音视频联合的坑 | 母带音轨、preroll、口型漂移、AudioLock、输出音轨归属 |
| ⑤ MV 专项流程 | 本文第一~八节 |
| ⑥ **我们工作流的节点地图** | 每个节点干什么、参数在哪一格调（最能省他时间的一节） |
| ⑦ 故障手册 | 症状 → 原因 → 处置 |
| ⑧ 学习路径 | 推荐看什么、按什么顺序看 |
