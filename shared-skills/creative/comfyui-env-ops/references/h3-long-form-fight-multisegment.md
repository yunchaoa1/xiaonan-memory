# H3 长打斗：单段 15 秒上限怎么拼出 30–60 秒的完整一场

> 适用：凡哥要「一场完整的打斗」「更长的成片」「30 秒以上」，
> 而不是一个动作、一次交锋。
> 来源：2026-11-19 本机实测 + 官方帧格规则 + AI-KSK 的八拍编排口径。

---

## 一、先回答「15 秒够不够」：不够，15 秒只是一段交锋

| 时长 | 能装什么 | 影视口径 |
|---|---|---|
| 5 秒 | 一次交换：一人进攻 → 一人挡 → 一人退 | 一个动作组 |
| **15 秒** | 一个回合：试探 → 攻 → 挡 → 反击 → 抢回主动 → 收势（**八拍**） | 一段 bout |
| **30–60 秒** | 完整一场：开局压制 → 中段翻盘 → 结尾定胜负 | 一场 fight scene |
| 2–3 分钟 | 一整场动作戏（含地形变化、换武器、多人介入） | 一场 sequence |

**15 秒的八拍 ≈ 每拍 1.9 秒，一拍只够做一个动作。** 所以「完整打斗」必须分段拼，
不是把提示词写长就行 —— **H3 单段出不了 15 秒以上**。

---

## 二、单段帧数上限（别填 15.0，会被截）

H3 帧数必须落在 **`17n + 5`** 格点：

- `n = 20` → **345 帧 = 14.375 秒** ← 单段实际能用到的上限
- `n = 21` → 362 帧 > 360，**超过 15 秒拿不到**

**所以单段写 `14.3s`。** 填 15.0 会拿到多余帧，尾巴那段没提示词就会崩成噪点色块。

四段 × 14.3s = **57.2 秒**，正好落在「30–60 秒」区间。

---

## 三、四段式结构（起承转合，本次用的骨架）

```
段01  对质升级   → 摔文件 → 抓衣领 → 对方掰手腕
段02  第一次交火 → 掰开 → 挥拳落空 → 反手命中 → 撞书柜
段03  A 压制     → 格挡 → 打中胸口 → 逼到墙角 → 抓领抬手
段04  翻盘收势   → 抬膝顶腹 → 肘击后颈 → 倒地 → 站着喘
```

**每段内部仍按八拍编排**（定位试探 → 首攻 → 格挡 → 反击 → 夺回主动 →
二次进攻 → 最后接触 → 稳定收势），只是四段各承担弧线的一段。

**权力关系必须在段间翻转**（段 03 是 A 压制，段 04 必须翻盘）。
一路单方面挨打不是打斗，是施暴 —— 观众会跑。

---

## 四、段缝衔接（这是长打斗最容易翻车的地方）

H3 **每一段都是独立采样，段与段之间不共享画面/状态上下文**。

**铁律：每段正文的第一句，必须复述上一段末帧的准确姿势。**

✅ 正确（段 02 开头）：
```
<Subject 1> stands on the left with his back to the corner; <Subject 2> stands on the right
with his left hand closed on <Subject 1>'s collar and his right arm drawn back at shoulder
height. This is exactly the position the previous moment ended on.
```

❌ 错误（H3 会重演上一段的动作，或凭空换姿势）：
```
承接上一段 / 接上文 / continuing from the last shot
```

**段间默认设「状态跳点」**：每段起始状态要能独立成立。跨段不要把同一个连续动作拆开
（段 01 打出去、段 02 才落地 = 两段都废）。

**拼片用 ffmpeg concat**（本机 ffmpeg 在 `/d/tools/ffmpeg/ffmpeg`，不在 PATH）：

```bash
cd <ComfyUI>/output
printf "file 'a.mp4'\nfile 'b.mp4'\nfile 'c.mp4'\n" > list.txt
/d/tools/ffmpeg/ffmpeg -y -v error -f concat -safe 0 -i list.txt -c copy out.mp4
```

四段同参数（同分辨率、同 fps、同编码）才能 `-c copy` 直拼，否则要重编码。

## 八、顺手记的两个本地操作坑

1. **`cv2.imwrite` 不认 MSYS 路径**：`/d/Hermes/cache/x.jpg` 会静默失败（返回 False，
   文件夹里没东西）。一律写 `D:/Hermes/cache/x.jpg`。
   抽帧校验时 `imwrite` 的返回值要看，别只看循环跑完了。

2. **ComfyUI 跑完一批容易被回收**，下一批提交前会 `WinError 10061 目标计算机积极拒绝`。
   → 批量提交脚本第一件事先 `curl /system_stats` 探活，不通就重启再等就绪。
