# 守护/看门狗把跑片脚本重复拉起（2026-11-23 实测）

## 现象
逐段跑片脚本（`run_all_cg.py`，外部 cron 每 10 分钟跑一次 `watchdog_pianxin.py` 看门）一晚堆到 **21 个实例**，物理内存只剩 1.7GB；日志每一行重复两遍（多实例同时写同一个 log）；跑片状态文件从未写成，进度永远 0/20；间隔性出现「段01 失败：['ERROR']」——其实是另一个实例把 ComfyUI 杀了重启导致在跑的 prompt 中断。

## 根因两条
1. **存活判定用 wmic**：旧看门狗靠 `wmic process where "name='python.exe'" get CommandLine` 找 cmdline。**本机 Win11 已无 wmic**，命令永远返回空 → 每 tick 都判「进程不在了」→ 每 10 分钟再起一个。
2. **重启前无条件删锁**：`os.remove(lock)` 之后才 spawn，等于把互斥锁拆了，新实例和旧实例都能“取得锁”，互杀 ComfyUI。

## 修法（照抄）
- 存活判定换 **psutil 扫 cmdline**：
  ```python
  def runner_pids():
      me = os.getpid(); out=[]
      for p in psutil.process_iter(["pid","cmdline"]):
          if p.info["pid"]==me: continue
          if "run_all_cg" in " ".join(p.info.get("cmdline") or []): out.append(p.info["pid"])
      return out
  ```
- **锁文件只信活人**：锁里记的 PID 仍在 `runner_pids()` 里 → 就当在跑，**不删不重启**；PID 已死才清陈旧锁。
- 启动条件改成：`if runner_pids() or live_lock_holder(): return`（旧版缺的就是这道闸）。

## 还有两个连通坑（22:00 后实测）

### A. 看门狗用 shell=True 拉起长跑子进程 → cron 报「3600 秒超时」
`subprocess.Popen('cd /d ... && python run_all_cg.py >> log 2>&1', shell=True)` 会在中间多一层 `cmd.exe`，而 cmd.exe 要等 python 退出才退出；cron/no_agent 会等脚本的 stdout 关闭 → 子进程活多久就卡多久，脚本自己早返回了也照样 3600s 超时。
**修法**：不经 shell、不用 `cd /d`，直接列表参数 + 自己接句柄 + 脱离子进程：
```python
env = {k: v for k, v in os.environ.items() if k.upper() not in ("PYTHONPATH", "PYTHONHOME")}
logf = io.open(r"D:/Hermes/cache/run_daemon.log", "a", encoding="utf-8", errors="replace")
subprocess.Popen([PY, "run_all_cg.py"], cwd=r"D:/Hermes/cache/emotion",
                 stdout=logf, stderr=subprocess.STDOUT, env=env, close_fds=True,
                 creationflags=subprocess.CREATE_NO_WINDOW | subprocess.CREATE_NEW_PROCESS_GROUP)
```
验证：看门狗手动跑一次，**0.1 秒返回**才算对（之前是 120s 不断）。

### B. ComfyUI 起不来，报 `ImportError: cannot import name '_imaging' from 'PIL'`
栈里的 PIL 路径是 `D:\Hermes\installs\...\venv\Lib\site-packages\PIL`（Hermes 的环境），根本不是 ComfyUI 自己的 `.venv`。原因：Hermes/App 启动的进程带着 `PYTHONPATH`，一路传给 ComfyUI → 捡到别的环境里残缺的 Pillow。
**修法**：起 ComfyUI（及其父脚本）时把 `PYTHONPATH` / `PYTHONHOME` 从 env 里剔掉（上面 A 的 `env=` 已包含）。修好后启动 20 秒就绪；修不好会白等 4 分半才报「起不来」。

### C. 别乱杀「重复」实例
`run_all_cg.py` 自己会再拉起一个子 python（两个进程成对出现是正常的）。杀掉父进程会连带子进程一起死，而正在渲的那条 prompt 还在 ComfyUI 里白跑十几分钟没人收账。**判断谁在干活：看 `run_all.lock` 里记的 PID，只清不是锁主的那个。**

## 先查后动（顺序别反）
1. `curl 127.0.0.1:18188/queue` 看 `queue_running` / `queue_pending`（注意本项目 ComfyUI 端口是 **18188**，不是默认 8188）
2. psutil 数一遍实例：个数 > 1 就是这事
3. 杀重复实例（**只杀 run_all_cg，别杀 ComfyUI**——在跑的那条 prompt 会自己渲染完）
4. 修看门狗 → 等下一个 tick 自动起**一个**干净实例
5. 验证：`已提交 …` 只出现一次、`queue_running` 唯一、`ls -t output/*.mp4` 有新增

## 别踩
- 已产出的 `G01_0000N.mp4` 不代表脚本记了账：中断的 prompt 产物会留在 output 里，但 state 没写 → 重跑会再出一份（多花约 10 分钟），**不要手改 state 冒充完成**，让 clean 实例自己跑一遍。
- 14 秒 H3 段 ≈ 4 chunk × 168s + 模型初始化 2.75 分钟 ≈ **13–14 分钟/段**，20 段 4–5 小时，别按“几分钟出片”估计。
