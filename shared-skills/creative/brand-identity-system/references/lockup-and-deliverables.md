# 锁标排版与交付包（Lockup & Deliverables）

## 一、锁标构成

```
[ 符号 ]  [ 主字标 ]      ← 横版（默认，用于站标 / 邮件签名 / 横幅）
          [ 副标   ]

   [ 符号 ]               ← 竖版（用于启动页 / 证书 / 方形物料）
 [ 主字标 ]
 [ 副标   ]

[ 符号 ]                  ← 图标位（App图标 / favicon / 社媒头像）
```

**分工**：符号讲一个词（品牌性格）；主字标 = 品牌名；副标 = 业务说明
（例：主字标「天使OPC」+ 副标「数字社区」）。

## 二、实测比例表（横版锁标，来自一次实际交付）

| 参数 | 值（以符号高为基准） | 说明 |
|---|---|---|
| 符号高 | 214 px（画布尺度任意，按比例换算） | **主角** |
| 主字标字号 | **96** ≈ 符号高的 45% | 见下方「首版错误」 |
| 副标字号 | 42 ≈ 主字标 44% | 字重更轻、字距更宽 |
| 主字标↔副标 行距 | 16 | 约副标字号的 0.38 |
| 符号↔字块 间距 | 60 ≈ 符号高的 28% | 太近显拥挤，太远显散 |
| 文字转行（tracking） | 副标 ≈ 0.22em | 副标靠字距拉开，撑住与主字标的宽度差 |
| 画布内边距 | 62 | 锁标四周留白 ≥ 符号高 25% |
| 垂直对齐 | 字块**光学中心**对符号中心 | 不要用基线对齐 |

### 「首版错误」——必须避免

首版把主字标设成 116、符号 190 → **字标比符号还重，符号沦为字标的配图**。
降到 96 / 符号升到 214 之后主次才立住。**任何一个锁标，先问：谁是主角？**

## 三、中文标准字

- 交付稿的「中文标准字」应做**字形设计**（字面、字重、笔画收尾、字距），
  **不要直接把系统字体排版当成品交付**。
- 但**参考排版**（系统字体快速排一版）非常有价值：可以在 20 分钟内证明
  「加字标后差别有多大」，用于推动用户拍板。**必须在图上标注「参考排版，非最终字体设计稿」**。
- 本机可用中文字体（Windows）：
  `NotoSansSC-VF.ttf`、`Noto Sans SC Bold/Medium (TrueType).otf`（= 思源黑体）、
  `Source Han Serif SC Heavy (TrueType).ttf`（= 思源宋体 Heavy，适合做有质感的标准字）、
  `msyh.ttc / msyhbd.ttc / msyhl.ttc`（微软雅黑 常规/粗/细）、`simhei.ttf`、`Deng*.ttf`。
- 混排中英（如「天使OPC」）：思源黑体 Bold 中西文同族，最省事且协调。
- ⚠️ **缺字坑（实测踩过）**：`Source Han Serif SC Heavy` **缺 `U+00B7`（`·`）**——用它排
  「方向 02 · 金线徽章」这类小标签，`·` 会显示成**方框**，整块标签看着像坏了。
  → **小字标签统一用思源黑体（`Noto Sans SC Medium`）；宋体只留给大标题。**
  换用任何字体后，先渲一张小样核对缺字，别等交付页出来才发现。

## 四、精修清单（定稿前逐条做）

1. **光学居中归一化**：渲染 → 读 alpha 包围盒 → 反算 viewBox 平移量 → 重新生成。
   **双色/多层稿按所有层的并集居中**，不是按主色层。实测曾偏 10.55 单位（肉眼难辨但比例就是歪）。
2. **笔画渐细**：羽枝/笔画给不同宽度（如 9.4 / 8.0 / 6.6），比等宽更像「器官」；等宽 = 棍子。
3. **错位/叠印层参数锁定**：偏移 5 单位（viewBox 100），错位层在下，主色层在上。
4. **小尺寸专项**：16 / 32 / 64 px 三档渲染实测；favicon 用**放大版**（色块内标占比 ≈ 0.78，
   默认 ~0.62 时 16px 几乎看不见）。
5. **四场景验证**：浅底（双色标）/ 深底（反白标）/ 单色（印刷）/ 彩色底（反白透明标）。

## 五、交付包目录结构（实测规模：约 100 个文件）

```
<资产根>\final\
├── <方案名>\                     ← 每个方案一套，便于用户挑选/切换
│   ├── mark\                     ← 主标：dual(双色) / mono(单色) / white(反白)
│   │     mark-dual.svg / .png / -512.png / -1024.png
│   ├── appicon\                  ← App 图标三底版 × 尺寸阶梯
│   │     appicon-blue / -dark / -white  (.svg + 1024/512/192/180/152/120.png)
│   ├── favicon\                  ← favicon.ico(16/32/48/64) + .svg + 各尺寸 PNG
│   └── social\                   ← 社媒头像（深底/白底 × 1024/512）
├── 使用规范.md
└── 交付总览.html
```

要点：
- **SVG 必给**（矢量可缩放改色，这是核心价值）；PNG 给透明底。
- **App 图标必须给色块底版本**（蓝底白标 / 深底双色 / 白底双色）——
  纯透明标直接当 App 图标会「飘」。
- `.ico` 多尺寸可用 PIL 一次生成：`im.save("favicon.ico", sizes=[(16,16),(32,32),(48,48),(64,64)])`。
- 尺寸阶梯按平台惯例：1024（源）、512、192（Android）、180（apple-touch）、152、120。

## 六、使用规范.md 必含条款

1. **色彩规范**：主色 / 错位色 / 深底色 / 反白 的十六进制值，各用在哪
2. **留白规范**：四周留白 ≥ 标志高度 25%
3. **最小尺寸**：双色标 ≥ 32px；小于 32px 必须用色块底（favicon 版）
4. **禁止事项**：不改色（除黑白转换）、不拉伸变形、不加阴影/描边/渐变、
   不在杂乱背景上放单色标、**错位量不许自行调整**
5. **文件清单说明**：每个目录放什么、什么时候用哪个

## 七、交付页/对比页的验证（不要漏）

生成 HTML 之后**必须实际渲染看一遍**：

```
chrome.exe --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1400,1800 --screenshot="D:/Temp/check.png" "file:///<percent-encoded-path>"
```

注意：路径含中文时必须先 percent-encode（用 `urllib.parse.quote`）。
截图后用 vision 核对：图形是否都显示（有无破图）、深底格是否可见、
小尺寸是否显示、排版是否错乱。**核对通过再给用户看。**
