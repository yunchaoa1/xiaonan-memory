# 矢量重绘技法 —— 把定稿图形真正"造"出来

适用：方向已圈定，要把标志**精修/重绘**成可交付的矢量稿（精确色值、真透明、可无限放大、能出单色/反白/favicon）。
出处：2026-09-14 「OPC × 单翼」定稿过程（resvg-py + 代码参数化生成几何）。

## 0. 何时必须重绘

- 用户说「**这两张只是参考，不要在上面改动，重新设计**」→ 一律从零重绘，不在素材上做修饰。
- 用户给出「美工要求」（如"O 要完全闭合、左边不要突出"）→ 改几何参数，不要用位图修补。
- AI 生图（`image_generate` / gpt-image-2）= 位图 + 色阶噪点 + 色值不可控 + 边缘发毛 → **只能定方向，不能交付**。

## 1. 渲染器（本机已验证）

```python
import resvg_py
png = resvg_py.svg_to_bytes(svg_string=svg_text, width=1800)   # 参数名 svg_string（不是 svg_str）
```
- **中文字体**必须显式指定，否则豆腐块：`font-family="Microsoft YaHei, 微软雅黑, Source Han Sans SC, sans-serif"`。
- 不要手写 path 数字，用 Python 参数化生成（贝塞尔采样 → 输出 path），改一处参数即可全图重排。

## 2. 月牙形（羽翼/刀形/锥形羽带）—— 最大的坑

```python
pts = bez(lead) + bez(trail)
# lead : 根部 → 尖端（前缘）
# trail: 尖端 → 根部（后缘）
```

**⛔ 不要对 trail 再做 `list(reversed(...))`。**
后缘本来就该从尖端写回根部；再反转一次，多边形变成"来回同一条线"，图形**退化成一根发丝**。
（本次在这上面白丢两轮，还误判成"羽带太细"。症状就是：宽度参数怎么加都还是细线。）

**厚度控制**
- 锥形羽枝：trail 与 lead **近似平行（等宽）**，只在尖端附近收拢。trail 控制点收得太快 → 「标枪/发丝」感。
- 主羽要"饱满"：根部厚度取笔画宽的 **1.6–2 倍**，中段保持 60–70%，只在末端收尖。
- 判断方式：把渲染图和参考图并排丢给 `vision_analyze` 问"主羽够不够厚、像不像翅膀"，**不要凭数字感觉改**。

## 3. 接缝处理 —— 两个形要"长在一起"

把附加形状的**闭合边改成贴着主体外圆的圆弧**：
`A r r 0 0 <sweep> <起点>`，其中 `r = 主体中心线半径 + 笔画宽/2`。
本例：主羽底边改成绕 C 外圆 `r=100` 的弧 → 台阶消失，读作"翅膀从 C 身上长出来"。
sweep 方向用眼睛验证：弧形要**凸向附加形内部**才算咬合。

## 4. 等宽圆头（monoline）字母的几何算术

- **基线对齐**：视觉底线 = `圆心y + 半径 + 笔画宽/2`。各字母按**视觉底线**对齐，不要用中心线。
- **P 的碗有数学上限**：碗内空宽度 ≈ `碗半径 − 笔画宽`。
  例：笔画宽/字高 ≈ 22%（粗体）+ 碗半径 62 → 内空只剩 18 → 必然挤成一坨。
  → 解法 A：碗弧端点落在**竖杆右缘**（内空 ≈ r − SW/2）。
  → 解法 B：P 写成「**横杠 + 竖杆**」的 Γ 形 —— ⚠️ **只在横排上下文里成立**。
    一旦字素被**孤立或竖排**呈现（如竖排字标「O/P/C 叠成一列」），Γ 会被直接读成 **L**。竖排场景必须用带碗的 P。
  → 解法 C（竖排场景推荐）：**碗收短 + 竖杆下探** —— 碗只画到竖杆的 60–70%，杆再往下留出一截 → 读作正常的 P。
  ⚠️ 反向坑：碗画到**和竖杆一样长**会读成 **D**（实测在竖排字标里立刻暴露）。
- **字母间距**：用**光学间距**校（外壳边缘之间的距离），不要用中心点等距 —— 带碗的 P 会显得偏。
- **O 要求"完全闭合"时**：用 `<circle>`，不要用带缺口的 arc；左侧不要留任何延长尖角（用户会直接指出来）。

## 4b. 字素「孤立可读性测试」（每次必做，比路人测试更早）

把每个字素**单独拿出来**读一遍 —— 在上下文里读得对，不代表**孤立或竖排**时也读得对。
用户是在竖排字标里一眼看出来的：低级，但致命。

| 现象 | 根因 | 修法 |
|---|---|---|
| P → **D** | 碗与竖杆等长 | 收短碗，竖杆往下探出一截 |
| P → **L / Γ** | 用了「横杠 + 竖杆」的开放写法 | 竖排场景必须用带碗的 P |
| C → **δ / 6** | 弧的 `sweep` 取反，鼓向另一侧 | 换 sweep，确认凹面朝向字母开口侧 |
| 整个字读错 | 中文字标拿现成字体排 | 笔画要与标志同款处理 |

**姿势**：先测**单个字素** → 再测**整串** → 最后才谈与图形的融合。顺序反了会反复返工。

## 4c. 翅膀 / 羽毛的绘法（实测配方）

- ⛔ **不要用深锯齿**（会读成**蝙蝠 / 枫叶 / 蕨叶**）—— 本次最大的形态误判，改浅、改圆才是羽毛。
- ✅ **分层锥形羽带**：每侧 **3–4 条**，**根部连成一片**（底边相切、无缝隙），**末端各自收成尖**，条与条**间隙均匀**。
- 主羽（最外那条）**最厚最长**，往内逐条变短 → 轮廓自然形成翅膀的斜度。
- 双侧翼：同一组参数 `x → 2*cx − x` **镜像**即可，不要手工重画（手工必然不对称）。
- 中间留出身体位（竖排字母柱）：翼的**根边贴住字母柱外缘**，只留 **6–8 单位**呼吸缝 —— 缝太大两者脱开，缝为零又糊在一起。
- 字母柱占宽要与翼间缝隙**等宽**：字母比缝隙宽 → 会被翅膀吃掉（实测过，竖排 OPC 被翼根部切碎）。

## 5. 融合第一原则：视觉重量必须匹配

两套素材**重量/语言不同**（写实插画 vs 等宽线条字）直接拼 = 用户口中的「**四不像**」。
（实测：翼上字下 / 字上翼下 / 分列两侧 / 嵌进字母环内 / 反白压底 / 加粗咬合 / 双翼合围 —— **7 种结构全失败**。根因不是排版，是"插画有明暗纹理"vs"字标是纯平线条"。）

只有两条路：
1. **把插画重画成同款线条语言**（通常更好，本项目最终采用）；
2. 把字加粗到与插画同重量（试过，笔画撞在一起闷成一团）。

**融合是否成立的判据：能不能说成"一个形"**
- ✅「字母从翼形里刻出来」「C 的上端长成主羽」「字母的弧线延展成羽翼」
- ❌「翅膀在上面、字母在下面」「环套在字外面」→ 用户原话：*字是字、环是环，两块东西贴一起*

**找融合钥匙**：在两份参考里找**本来就重合的元素**。
本例：单翼左端收拢的圆点 ＝ OPC 里 O 开口处那颗蓝点 → 那就是锚点，全部结构围绕它组织。

## 6. 交付自检循环

渲染 → 拼版 → `vision_analyze` 逐张客观评（问"像不像专业标志 / 还有什么要改"，**直说缺点**）→ 改参数重来。
产出后**先自己看再交付**；HTML 提案页用 `scripts/render_html.py` 渲染核对（图片路径写错只会静默破图）。

## 7. 从位图抠图 = 死路（别再试）

用亮度阈值/百分位 + 连通域过滤，从带光晕/渐变的渲染图里提取"二维单色"：
**试了 4 轮（阈值→连通域→裁切→分图调参）全部失败** —— 光晕残留、内部破洞、反射斑块、背景亮带被抠进来。
→ 让图形**直接以目标形式重新生成/重绘**，不要在错误的形式上做修复。见 SKILL.md 第 6 节。
