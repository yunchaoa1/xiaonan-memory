## 模块 0 · 先建立心智模型（不建立这个，后面全是死记）

**H3 不是"文生视频模型"，是"音视频联合生成的多模态缝合器"。**

三个必须刻进脑子的点：

1. **它一次同时生成画面 + 声音**（不是先出画面再配音）。所以**声音要在提示词里一起写**，写不好声音，画面也跟着糟。
2. **它把参考素材当"材料"用，不是当"提示"**。每份图/视频/音频都要在提示词里**被指派一个职责**——不指派，它就乱用。
3. **单次生成 = 一个镜头段，不是一支 MV**。4-15 秒是**单次上限**。MV = 多次生成 + 组装。

> 一句话：**H3 是"镜头引擎"，MV 是"用镜头引擎拍出来的片子"。** 搞混这两层，就会写出"一句话生成整支 MV"这种不存在的期待。

## 模块 1 · 输入系统（素材怎么喂）

### 1.1 三类素材，三种职责（🟡 多份指南一致强调）

| 素材 | 上限 | 唯一职责 |
|---|---|---|
| 参考图 | **≤9 张** | 锁身份 / 产品几何 / 文字 / 环境 / 关键帧 |
| 参考视频 | ≤3（各 2-15s） | 运动 / 镜头语言 / 节奏 / 表演 |
| 参考音频 | ≤3（各 2-15s） | 音色 / 语速 / 节拍 |
| **合计** | **≤12** | — |

**铁律：每份文件只给一个窄职责。** "五张图都用来描述电影感"是最常见的失败方式——模型会在五个解释之间摇摆。

**上传前删冗余**：两张冲突角度的角色图、三块不同色板的风格板 → 只会让失败更难诊断。

### 1.2 槽位顺序 = 提示词编号（🟡 实测）

上传区从左到右、从上到下 = **参考图 1…9**。提示词里就写 `image 1 里的女人`、`image 2 的裙子`。

组合描述写**一句话**（谁在哪、和什么互动），**不要写清单**：
- ✅ `image 1 的女人坐在 image 3 的沙发上，抱着 image 2 的狗，三者在同一画面，镜头缓慢推近`
- ❌ `image 1：女人。image 2：狗。image 3：沙发。`（→ 三样东西各干各的）

### 1.3 音频：云端 vs 我们本地（🟢 本机实证 + 源码）

| | 云端 API | **我们本地** |
|---|---|---|
| 单次音频总长 | **≤15 秒**（超了直接拒：`total audio duration 24138 ms exceeds 15000 ms`） | `MiniMaxH3MediaLoaderFantastic` **可载入整首母带并任意段剪辑**（`h3_media_io.py:312`：`start/end` **在采样前裁剪源**，保留段才进管线） |
| 能不能单独送 | ❌ 必须配图或视频 | 同左 |
| 计费 | 参考音频免费（只按输出秒计费） | 本地电费 |

**凡哥 2026-09-15 截图实证**：`爱的记忆.mp3` 全曲 2:30 载入、`0.00 → 149.98`、`150.0s kept`，带 `+Segment / −Segment / Use segment`。

⚠️ **但有一个尚未实测的关键问题**（见模块 4.3）：整轨音频进去后，模型是"整轨做条件、只生成 9 秒画面"，还是"只取前 9 秒"？**跑一次即知，这个答案决定整个分镜骨架。**

## 模块 2 · 提示词七段规范（🟢 官方，本机有原件）

### 2.1 固定结构（字段名不要改）

```
id="x..."                          ← 镜头唯一标识

subject_definitions:               ← 先定义"谁/什么"（把参考图的身份、服装、环境关系写在
                                    这里，不要写在画面描述里）

summary:                           ← 一句话说清这镜要什么

retention_analysis:                ← 逐份素材声明"保留到什么程度"（见 2.2 词表）

detailed_description:              ← 画面细节：动作因果链 / 运镜 / 情绪（见模块 3）

overall_soundscape:                ← 环境声：在场所有人都能听到的（房间底噪、天气、远处车流）
                                     写不清楚就写 N/A

non_diegetic_music:                ← 只有观众能听到的配乐（或 N/A 表示静音）
```

**多镜时**：`[Shot 1]` 不带时间戳；从第 2 镜起 `[Shot 2] At 00:03.000, ...`。

### 2.2 retention 词表（🟢 官方，固定词汇，别自创）

| 画面 | 音频 |
|---|---|
| `fully_preserved` | `fully_copy` |
| `partially_preserved` | `partially_copy` |
| `attribute_transfer` | `reference` |
| `weak_reference` | `weak_reference` |
| `newly_generated` | |

### 2.3 🔥 最容易踩的坑：`<Subject N>` ≠ `<Picture N>`（🟢 官方重点）

- **参考图不自动等于第一帧。**
- 图只提供**外貌 / 身份 / 服装 / 环境 / 风格关系** → 写进 **`subject_definitions`**（当 `<Subject N>`）
- 图真的**当首帧 / 关键帧 / 构图锚** → 才用 `<Picture N>`
- 搞混的后果：模型把一张"身份参考图"当成"首帧"，画面的开场构图就被那张图绑死了。

### 2.4 首行对齐说明（🟢 官方）

| 模式 | 首行写什么 |
|---|---|
| T2VA（纯文生） | 跳过，直接从 `integrated_multimodal_description` 开始 |
| I2VA（一图当首帧） | `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` |
| FL2VA（首帧+末帧） | 分别声明 Picture 1 对齐 0.00 秒、Picture 2 对齐 `S.SS` 秒（S.SS = 实际生成长度，两位小数，如 9.00） |

## 模块 3 · 画面描述怎么写（🟢 官方 + 🟡 实测）

### 3.1 动作写"因果链"，不是动词堆

```
准备 → 触发 → 加速 → 主动作 → 接触 → 反应 → 恢复 → 终态
```
孤立动词（"她在走"）出来就是漂浮的动作。因果链出来才像真的在做事。

### 3.2 运镜写五要素，一句完整话

**机位/景别 + 运动类型 + 方向 + 速度与幅度 + 跟随对象**
- ✅ `相机小幅度慢速推近，跟随她的目光落到床头的小熊`
- ❌ `cinematic camera` / `dynamic shot` / `cool angle`（空词，等于没说）

### 3.3 情绪写"可观察行为"（🟡 实测会被字面执行）

- ✅ `视线固定向下，手指静止不动，肩膀微微抬起`
- ❌ `她很悲伤`

观察维度：**眼 / 脸 / 呼吸 / 姿态 / 手 / 注意力**。

### 3.4 明确写"相机不动"，比不写更好（🟡 实测）

不写 → 模型会持续漂移、重新构图。写 `The frame never moves.` + 列出不该做的运动 → 整段稳住一个固定机位。

### 3.5 声音两条轨道要分开写

- **`overall_soundscape`**：在场角色**能听到**的（房间底噪、雨声、车流、油锅滋响）
- **`non_diegetic_music`**：只有**观众能听到**的配乐。**写乐器与结构，不要写情绪词**：
  - ✅ `低音持续弦乐 + 紧张的拨弦 + 稀疏的电子脉冲，低鼓，最后两秒渐强`
  - ❌ `cinematic music`（这是愿望，不是需求）

## 模块 4 · 音视频联合的坑（本手册最值钱的部分）

### 4.1 单次生成 4-15 秒，**15 秒是单次上限，不是项目上限**（🟡 实测）

MV = **把歌分段、每段一镜、最后组装**。这是所有教程的共同做法。

### 4.2 切镜预算（🟡 实测，**反直觉但很重要**）

| 单次生成时长 | 建议镜数 |
|---|---|
| 5 秒 | **1-2 镜** |
| 10 秒 | 2-3 镜 |
| 15 秒 | 3-4 镜 |

**切得越多，每次剪切都要重新匹配参考 → 脸越容易漂。** 参考模式下尤其明显。

> 推论：**一镜一镜地"逐句配图"是错的**。H3 应该"一个镜头段落承担一整段音乐职能"。

### 4.3 ⚠️ 音频路线：已确认 vs 未知（🟢 我们工作流源码）

**已确认：**

| 事实 | 依据 |
|---|---|
| 每次生成的时长 = `MiniMaxH3ReferenceSplitter.duration`，范围 **1-15 秒整数** | `h3_context_ir.py:369 / :459` |
| **我们这版设 9 秒**（216 帧 @24fps） | 工作流 `#221 duration=9` |
| 生成的音频 latent **长度 = 生成时长，且零初始化** → **输出音轨是模型自己生成的** | `h3_unified.py:80-81, 116` |
| 参考音频**只作条件**，不等于输出音轨 | `h3_unified.py:147` |
| `MiniMaxH3AudioLock`（把参考音频锁成输出音轨）**我们这版是 bypass** | 工作流 `#226 mode=4` |

### 4.3b ✅ 已解决：走 **A 路线**（2026-09-15 读源码定论）

**问题**：整首 2:30 放进去后，模型是"整轨做条件、只出 9 秒画面"，还是"只取前 9 秒"？

**答案：A —— 整轨做条件。** 依据 `h3_unified.py:531-537`：

```python
for index, audio in enumerate(ref_audio_values, 1):
    encoded_audio, audio_t = _encode_reference_audio(audio_vae, audio)   # ← 按音频自身长度编码
    real_ref_items.append({"type": "audio"})
    real_ref_blocks.append({"kind": "audio", "ref_audio_t": audio_t, "audio_latent": encoded_audio})
```

- 参考音频**按自身实际长度整段编码**成参考块，**不被 `duration` 截断**
- `duration` **只**决定**目标**帧数（`h3_unified.py:652 length = duration_to_length(...)`）
- 素材数量上限只管**个数**（图≤9/视频≤3/音频≤3），**不管时长**

### ✅ 由此定下的路线：**音频不切，只切画面**

口型不会遭遇"切片偏移累积"的问题（切歌派的坑与我们无关）。

### ⚠️ 但仍有两个必须知道的保留

1. **长度外推风险**：模型大概率没在 150 秒参考音频上训练过 → 超长参考**结构上支持，效果未知**。**需一次实测确认口型质量**（可以先用 30 秒试，再推整轨）。
2. **输出音轨不是原曲**：生成的音频 latent 是**独立的、零初始化、长度=duration**（`h3_unified.py:116`）→ 模型"听着原曲唱自己的"。要拿到原曲音轨，两条路：
   - **后期把音轨替换成原曲**（社区标准做法："母带音轨 mask 置 0 保护，最终 MP4 用原曲音轨"）
   - 或**启用 `MiniMaxH3AudioLock`**（`#226` 现在是 bypass，mode=4 → 改为 mode=0，strength 0.35）

### 4.4 社区踩过的坑（🟡 实测，先用别人的血换）

- **不要继承上一镜的视频 latent** → 越往后画风越浓、线条越粗、色调漂移
- **音频切片按偏移算不对** → 对口型越来越偏（切歌派的通病）
- **5 帧 preroll 是必须的**（124 帧 @24fps = 5.1667 秒）
- **母带音轨 mask 置 0 保护**，最终 MP4 用原曲音轨
- **分辨率长宽必须是 32 的倍数**（1280×720 无效）
- **一镜一 prompt，场景必须换**
- **素材超限不报错，只出坏片**（图 ≤9 / 视频 ≤3 / 音频 ≤3 / 合计 ≤12）
- **特写比远景更容易出好口型**

## 模块 5 · MV 专项流程（🟡 业界标准 + 社区）

### 5.1 五步前置流程（**Treatment 先于 Storyboard**）

```
① Song Intent  → ② Treatment（1-5页）→ ③ Storyboard → ④ Shot List → ⑤ Production
```
**Treatment 改动便宜，Storyboard 改动贵。** 先把"这片子是什么"定死。

### 5.2 MV 分镜 ≠ 电影分镜（🔵 但 AI 同样适用）

- **跟歌走，不跟剧本走**。每帧带**时间码或小节号**（传统板写 `Bar 17, beat 1`）
- **表演层 + 概念层双轨**并行，标出交汇点
- **副歌重复必须"升级"**，三次副歌不能长一样
- **长镜头是 1 帧，不是 5 帧**（写 `hold 4 bars`）

### 5.3 段落 → 视觉职能 → 镜头类型（🟡 H3 专用）

| 歌段 | 视觉职能 | H3 镜头类型 |
|---|---|---|
| Intro | 建立世界与视觉语言 | 广角环境 / 物件母题 |
| Verse | 引入表演者或叙事动作 | 中景表演 + 故事插入镜 |
| Pre-chorus | 提速、制造预期 | 移动镜头、更紧的剪辑、渐亮 |
| Chorus | **最强的可重复画面** | 英雄表演 / 群体动作 / 变身 |
| Bridge | 制造对比 | 新地点 / 慢动作 / 抽象 |
| Outro | 收 | 回到母题 / 淡出 |

### 5.4 "视觉系统一页纸"（写提示词前必须定）

表演者身份+发型+服装+配饰+妆容 ｜ 2-3 个复用地点 ｜ 色彩与灯光规则 ｜ 主歌/副歌各自的镜头规则 ｜ 重复的物件母题 ｜ 画幅与交付分辨率 ｜ **哪些段落有可见演唱** ｜ 哪些声音来自模型、哪些来自母带。

### 5.5 镜数量级（别照搬真人 MV）

| | 4 分钟歌 |
|---|---|
| 传统真人 MV | 80-150 镜 |
| **H3**（一镜 5-15 秒） | **10-30 镜** |

**2:30 的歌，我们这版（9 秒/镜）≈ 17 镜。**

## 模块 7 · 故障手册（症状 → 原因 → 处置）

| 症状 | 原因 | 处置 |
|---|---|---|
| 出片画面崩坏/不听指令 | **素材超限**（不报错只出坏片） | 图≤9 / 视频≤3 / 音频≤3 / 合计≤12 |
| 越往后画风越浓、线条越粗 | 继承了上一镜视频 latent | 每镜独立，不继承 |
| 口型越来越偏 | 音频按偏移切片算错 | 5 帧 preroll + 精确偏移；或走"音频不切"路线（待实测） |
| 出片分辨率不对 | 放大倍率 | `#1317` 倍率 × 一采尺寸 |
| 出片时长不对 | duration 参数 | `duration=9` → 216 帧 → 实际 9.0 秒 |
| 二采阶段崩 `Allocation on device` | 缺 `--disable-cuda-malloc` | 启动参数必须带（已加进 `start_comfyui.bat`） |
| 提交返回 `no_prompt` | POST body 格式错 | 必须 `{"prompt": <工作流>, "client_id": "..."}` 包一层 |
| `safetensors header too large` | 模型文件损坏/不完整 | 重下校验字节 |
| `api_key is required for external LLM calls` | 用了 API 版提示词节点 | 改用本地 `QwenTE` 链（我们已改） |
| 任务卡住/显存不释放 | 残留 | 每次任务前 `POST /free`（`{"unload_models":true,"free_memory":true}`） |

**诊断纪律**：先看**完整日志** + 查社区 issue，再断言。不猜因、不反复试错。
