# 音乐 MV 制作方法论（社区 / 业界现成做法汇总）

> 2026-09-15 采集。用途：**取代我们自摸的 LTX 版分镜流程**（凡哥定：学别人现成的）。
> 证据分级：🟢 实测/官方文档 ｜ 🟡 平台型指南（有真实出片案例） ｜ 🔵 传统工业经验（可对照，非 AI 专用）

## 一、业界标准前置流程（5 步，🟡🔵）

**Treatment 先于 Storyboard**（vibemv.app / storyflow.so）：

| 步 | 产出 | 干什么 | 谁看 |
|---|---|---|---|
| 1. Song Intent | 几句话 | 情绪弧 + 目标听众 | 自己 |
| 2. **Treatment**（1-5 页） | 概念文档 | 概念/视觉语言规则/段落推进/参考意图/约束 | 决策方 |
| 3. Storyboard | 帧序列 | 构图、机位、运动、转场连续性 | 导演/摄影 |
| 4. Shot List | 表格 | 要拍什么、按什么顺序 | 执行 |
| 5. Production | 素材 | 拍/生成 | — |

> 关键判断：**Treatment 修订便宜，Storyboard 修订贵**。先把"这片子是什么"定死，再进"怎么拍"。

## 二、MV 分镜 ≠ 电影分镜（🔵，但 AI 同样适用）

- **跟歌走，不跟剧本走**。歌是锁死的（3 分 40 秒就是 3 分 40 秒），分镜必须**倒推自音轨**。
- 每帧必须带**时间码或小节号**（bar/beat），不是只有构图。传统 MV 板写 `Bar 17, beat 1`。
- **表演层 + 概念层双轨**并行，要标出交汇点（哪里从表演切到叙事）。
- **副歌重复必须"升级"**：同一 hook 第二、三次要更强，否则第二遍就疲了。
- **长镜头是 1 帧，不是 5 帧**（写"hold 4 bars"，不是画 4 张几乎一样的图）。

## 三、段落 → 视觉职能 → 镜头类型（🟡，H3 专用版，来源 minimaxh3.pro）

| 歌段 | 视觉职能 | H3 镜头类型 |
|---|---|---|
| Intro | 建立世界与视觉语言 | 广角环境 / 物件母题 |
| Verse | 引入表演者或叙事动作 | 中景表演 + 故事插入镜 |
| Pre-chorus | 提速、制造预期 | 移动镜头、更紧的剪辑、渐亮 |
| Chorus | **最强的可重复画面** | 英雄表演 / 群体动作 / 变身 |
| Bridge | 制造对比 | 新地点 / 慢动作 / 抽象 |
| Outro | 收 | 回到母题 / 淡出 |

**"视觉系统一页纸"**（写提示词前必须定，🟡）：表演者身份+发型+服装+配饰+妆容 ｜ 2-3 个复用地点 ｜ 色彩与灯光规则 ｜ 主歌与副歌各自的镜头规则 ｜ 重复的物件母题 ｜ 画幅与交付分辨率 ｜ **哪些段落有可见演唱** ｜ 哪些声音来自模型、哪些来自母带。

## 四、镜数与时长预算（🔵 传统 + 🟡 H3）

**传统真人 MV（4 分钟）**：80-150 个镜头。分段配比：
Intro 4-6 镜（每镜 5-8 秒）｜ Verse 15-20 镜 ｜ Pre-chorus 从 8 秒镜过渡到 3-4 秒镜 ｜ Chorus 8-12 镜（更大更有冲击力）｜ Bridge 允许非常规 ｜ 另预留 15-20% 额外覆盖。

**传统分镜帧数**：Intro 4-8 ｜ Verse 每段 6-12 ｜ Chorus 每段 8-16 ｜ Bridge 4-10 ｜ Drop 10-20 ｜ Outro 2-6；3-4 分钟总计 **40-80 帧**。

**⚠️ H3 完全不同量级**：H3 单次生成 4-15 秒 → **一镜承担一整个段落职能**，2.5 分钟的歌大约 **10-30 镜**。所以**"逐句配图"是错的**（传统 MV 可以，H3 不行）。

## 五、H3 硬约束（🟢，来自 Atlas Cloud 实测文章 + 多份官方/平台指南）

| 项 | 限制 |
|---|---|
| 单次生成时长 | **4-15 秒**（整秒）；15 秒是**单次上限，不是项目上限** |
| 素材总量 | 图 ≤9 ｜ 视频 ≤3（各 2-15s）｜ 音频 ≤3（各 2-15s）｜ **合计 ≤12** |
| 音频 | ⚠️ **分两套口径，别混**：<br>**云端 API**：不能单独送，必须配图或视频；单次请求内**音频总长 ≤15 秒**（超了被拒：`total audio duration 24138 ms exceeds 15000 ms`）。<br>**我们本地**：`MiniMaxH3MediaLoaderFantastic` 可直接载入**整首歌**并任意段剪辑（凡哥 2026-09-15 截图实证：`爱的记忆.mp3` 全曲 2:30、`0.00 → 149.98`、**`150.0s kept`**，带 `+Segment / −Segment / Use segment`）→ **本地不受 15 秒限制** |
| 参考音频计费 | 免费（只按输出秒计费） |
| 提示词 | ≤7,000 字符；**无独立负向提示词字段** |
| 分辨率 | 768p 探索 / 2K 交付；**长宽须为 32 倍数** |

**切镜铁律（🟢 实测）**：**别过度切镜**。5 秒 = 1-2 镜；10 秒 = 2-3 镜；15 秒 = 3-4 镜。**切得越多，每次剪切都要重新匹配参考 → 脸越容易漂**。

## 六、参考图必须各司其职（🟢 多份指南一致强调）

- **槽位顺序 = 提示词编号**：上传位从左到右、从上到下 = `参考图1…9`；写"image 1 里的女人"。
- **每个文件一个窄职责**，禁止"五个文件都去描述同一个电影感"：
  - 图 → 锁身份 / 产品几何 / 文字 / 环境 / 关键帧
  - 视频 → 运动 / 镜头语言 / 节奏 / 表演
  - 音频 → 音色 / 语速 / 节拍
- **上传前删冗余参考**：两张冲突角度的角色图、三块不同色板的风格板 → 只会让失败更难诊断。
- 组合描述写**一句话**（谁在哪、和什么互动），不要写清单（清单会让三样东西各干各的）。

## 七、提示词写法（🟡 H3 指南共识）

- **字段顺序固定**：`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`（+ 首行写对齐说明：T2VA 跳过，I2VA/FL2VA 写 `<Picture 1>` 对齐 0.00 秒/末尾秒）。
- **时间轴标签**：`Shot 1` 不带时间戳；后续每镜 `[Shot 2] At 00:03.000, ...`。用切镜引入**真正的新信息**（新主体/新空间/新视角）；只是景别变了就推镜头，别切。
- **运镜写成一句完整话**：运动类型 + 幅度 + 速度（"相机小幅度慢速推近"）。
- **情绪写成可观察行为**：写"固定向下凝视、手指静止、肩膀抬起"，不写"悲伤"。**实测有效且会被字面执行**。
- **明确写"相机不动"**比不写更好（不写会持续漂移重新构图）。
- 时长诚实：`S.SS` 的末帧对齐必须等于实际生成秒数。

## 八、我们的音频路线：已确认 vs 待实测（2026-09-15，读源码 + 凡哥 UI 实证）

### ✅ 已确认（源码级）
| 事实 | 依据 |
|---|---|
| 加载器可放**整首母带**并任意段剪辑，**保留段才进管线** | `h3_media_io.py:312`「`start`/`end` trim the source before sampling; only the trimmed span is decoded」+ 凡哥截图（2:30 全曲载入、`150.0s kept`） |
| 每次生成的时长由 `MiniMaxH3ReferenceSplitter.duration` 决定，**范围 1-15 秒整数** | `h3_context_ir.py:369`（`Float 1..15, step 0.01`）/ `:459`（取整 1-15） |
| **我们这版设 9 秒** → 每次生成 9 秒画面（216 帧 @24fps） | 工作流 `#221` `duration=9`；`h3_unified.py:55 duration_to_length` |
| 生成的音频 latent **长度 = 生成时长**且**零初始化** → **输出音轨是模型自己生成的** | `h3_unified.py:80-81, 116` |
| 参考音频**只作条件**（喂给模型，不等于输出音轨） | `h3_unified.py:147 _encode_reference_audio` |
| `MiniMaxH3AudioLock`（把参考音频锁成输出音轨）**在我们这版是 bypass** | 工作流 `#226` mode=4 |

### ⚠️ 待实测（**这个答案决定整个方案的骨架**）
**把整首 2:30（保留 150s）放进加载器后，模型是"整轨做条件、只生成 9 秒画面"，还是"只取前 9 秒"？**
- 若是**整轨做条件** → **音频全程连续，只切画面** → 口型全程稳、无累积偏移（比切歌派强）
- 若是**只取前 9 秒** → 音频也得按镜切片 → 那我们和切歌派面对同样的偏移坑，得靠"5 帧 preroll + 精确偏移"解决

### ✅ 已解决：**A 路线成立 —— 音频不切，只切画面**（2026-09-15 读源码定论）
`h3_unified.py:531-537`：参考音频**按自身实际长度整段编码**成参考块，**不被 `duration` 截断**；`duration` **只**决定目标帧数（`:652`）。素材上限只管个数不管时长。
→ 口型不会遭遇"切片偏移累积"（切歌派的坑与我们无关）。
⚠️ 保留两点：① **长度外推风险**——模型未在 150 秒参考音频上训练过，结构支持、效果待实测；② **输出音轨是模型生成的**（音频 latent 独立、零初始化、长度=duration），要原曲音轨需**后期替换**或**启用 `MiniMaxH3AudioLock`**（`#226` 现 bypass）。

> ⛔ 本文档 2026-09-15 初稿曾写"配合 `MiniMaxH3SongMaskedAVContext`"——**该节点不在本工作流里，此说法作废**。

## 九、可直接落地的产出物（建议采纳）

1. **Treatment 一页纸**：概念一句 + 视觉语言规则 + 6 段职能表 + 约束
2. **AV 双栏分镜表**（🟡 celtx/studiobinder 标准格式）字段：
   `镜号 ｜ 时间码/小节 ｜ 时长 ｜ 层次(表演/叙事) ｜ 景别 ｜ 机位与运动 ｜ 内容 ｜ 歌词/段落cue ｜ 是否对口型 ｜ sync point标记 ｜ 所需参考图`
3. **Sync Points 清单**：必须命中的时刻（drop、hook 首句、静音切点）
4. **视觉系统一页纸**（见第三节）
