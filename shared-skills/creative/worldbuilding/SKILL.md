# Worldbuilding · IP角色与世界观设计

## 核心原则

1. **真实锚点优先**——角色和反派必须有真实存在的物理/文化锚点（建筑、民俗、传说、历史事件）。不凭空编造。
2. **仇恨是自己的**——反派恨的必须是发生在自己身上的事，不是替别人恨。霍启明恨自己设计的灯塔被拆，阿木恨自己父亲死在伐木道上，老犁恨自己的魂牌被卖。
3. **避开敏感话题**——革命历史、民族起义、战争、宗教冲突等不做反派诱因。优先用传说、民俗、自然现象。
4. **不确定就先反问**——不理解凡哥意思时先反问确认，不瞎猜执行。

## 反派设计模板

每个反派按以下结构记录：

```
## #N · 市县名

| 项目 | 内容 |
|------|------|
| 正派   | 角色A（地标）、角色B（地标） |
| 反派   | **名字** |
| 类型   | 完全黑化者 / 心魔合成体 / 人魔共生体 |
| 心魔   | 心魔A + 心魔B |

### 诱因 · 真实历史
（真实存在的建筑/民俗/传说/历史事件）

### 反派故事
（反派的个人经历，仇恨的根源）

### 共鸣锚点
（反派对应的真实物理/文化锚点）

### 跨界
（心魔如何在两个世界同时绑定）

### 与正派关系
（反派和对应市县正派之间的冲突/连接）
```

## 构建工作流

### Phase 1: 先收集权威源

动笔前必须检查：

1. **凡哥是否已经定稿？** 搜索现有文档、xlsx、记忆日志、另一端Agent笔记。
2. **是否存在"定稿"版？** 有则以此为准，草稿必须对齐定稿，不是反过来。
3. **其他Agent是否做过？** 先通过 git / session_search 拉取他们的内容再起草。

陷阱：权威版本已存在时不要发明新名字、新体系、新关系——必然被纠正且浪费时间。

### Phase 2: 草稿 → 展示 → 修改

1. 先写**精简大纲**（不是完整文档），未知项明确标注。
2. 展示大纲，等待纠正（关系、分类、命名、机制）。
3. 每轮纠正后，先**总结改了什么**再写下一版。
4. 凡哥说"可以开始了/继续"再写完整版。

### Phase 3: 对齐检查

凡哥提供纠正或参考文档（xlsx、其他Agent笔记）后：

1. 逐项对比当前版本与权威版本。
2. 用 ≠ 表显式标出每一处差异。
3. 按权威版本更新所有被标出的项。

### Phase 4: 拆分文件

内容稳定后：

1. 把大文档拆成分类目录（如 `world/`、`characters/`、`tech/`）。
2. 每个文件只讲一个主题（六界.md，不是世界观大全.md）。
3. **拆分前先备份**（整目录复制）。
4. 确认每个文件存在且内容完好，才删除原文件。
5. 拆分后更新所有交叉引用和仪表树链接。

### Phase 5: 构建仪表树

创建交互式 HTML 树（`dashboard-tree.html`）供凡哥导航：

- **DATA 对象**在脚本顶部——易编辑
- **status 字段**：`"done"` | `"progress"` | `"blocked"` | `"pending"`
- **file 字段**：md 文件的相对路径（点击直接打开）
- **info 字段**：灰色副标题附加上下文
- **count 字段**：进度数字如 `"57/57"`

更新流程：编辑 DATA 对象 → 保存 → `git commit` → `git push`。

## 搜索策略

在受限网络环境中搜索中文资料时：
- **首选搜狗（Sogou）**：`curl -sL "https://www.sogou.com/web?query=关键词"`，通过终端curl获取
- Bing Browserbase经常返回空页，不可靠
- 百度百科可能403

## 表格格式

所有Markdown表格原始文本中，竖线必须上下行对齐，用空格填充列宽。凡哥看原始文本而非渲染效果。

## 陷阱

1. **命名冲突**：凡哥可能已命名（六界、六阶）。不要改名。
2. **关系错误**：不要发明婚姻、亲子、师徒关系。先查 xlsx 和现有文档。
3. **过度书写**：大纲未获批准前不要写出3万字完整历史。
4. **拆分丢内容**：拆分前必须整目录备份。
5. **链接失效**：拆分时更新所有交叉引用和仪表树链接到新路径。
