# OPC 写作与主体资产回归经验（2026-08-31）

本文件记录本轮可复用的验证细节；它是 Skill 制作/验证材料，不是 OPC 运行时创意输入。

## 写作入口

- 客户想法是唯一开放的外部创意输入；小说输出后才进入下游封闭链。
- 静态契约应具有：required/optional/locked/human_confirmation、completed/blocked互斥分支、逐项 provenance、字段级 downstream handoff、固定 regression fixtures。
- `provenance_and_decisions` 最少区分 user_fact、inference、default、decision、risk，并绑定 source/body/rule/status。
- 回归夹具应覆盖：多格式、缺项、显式冲突、五类硬门禁故障、来源隔离、跨口味多样性、唯一交付、空输入阻断。
- 三类历史样本必须分开：未完结小说是小说正样例；短剧故事是灰区辅助样本；完整短剧剧本只提供创作过程证据，不能替代小说回归。
- 蒸馏条目字段：method_id、结论、原始证据、证据等级、适用条件、失败模式、排除项、状态。
- 经独立审计，可进入新输入测试的方法包括：灵感到发动机、框架先行、动机—错误—代价、信息线/证据线分离、多线独立后汇合、物件多功能但不一证解全局、多口味出口。
- 仅来自单一未完结奇幻样本的规则死循环、规则最小充分、阶段收束方法继续留作 candidate_not_runtime，不能直接升级。

## 真实写作回归

- 长文本回归按 `初稿 → 独立五门禁 → 定向修订 → 差异与断言终验` 四阶段串行落盘；每阶段一个文件，前一步真实存在并可读后才启动下一步。
- 完整小说正文不等于来源可追溯。回归产物必须内嵌 `source_registry`，保存本次客户输入原文及稳定 `SRC-*`；正文必须设置真实可定位的 `BODY-*` 锚点，不能只在 provenance 中悬空引用。
- 客户事实中的全称量词（如“每位”“所有”“从不”）属于锁定事实。正文必须证明适用集合和覆盖范围，不能静默缩窄成几个示例人物。
- 核心解局机制必须先有可观察的小试验、证据或失败偏差，再允许主角据此行动；“象征数字相关”不能直接跳成“逆向行动必然恢复”的规则。新增机制必须登记为 inference/decision 并绑定正文锚点。
- 门禁失败后的返工只改被指出的事实、因果和引用缺口，保留初稿原件作为对照；不得用润色替代结构修复，也不得伪造失败或把终稿自报的 `pass_after_revision` 当独立验收。
- 若委派代理在单文件完整小说生成上仍反复超时且零产物，由总负责人直接落地初稿；后续门禁与终验继续交给独立 verifier，保持创作与验收分离。

## GPT Image 主体资产

- 官方能力、项目规则、待测经验必须分级；runtime_model_id 从受控配置获取，不写死。
- 静态覆盖审计应先判定哪些资产有足够可见事实，哪些在 API 前阻断。
- 一个通过的固定静态预检可以证明来源、ID、哈希、未知字段和阻断逻辑一致，但不能证明图片质量或锁版能力。
- 本轮固定预检示例：21个对照项全部命中预期；8项 eligible，13项预期 ASSET_BLOCKED。该结果只属于静态层。
- 最终验收分三层报告：文档结构、静态 fixture/preflight、真实 API 图片/QC/锁版。不得上推结论。

## 委派与验收

- 长文本代理连续超时时，停止重复相同大任务，拆成单文件和单职责任务。
- 子代理摘要不是证据；必须回读文件、哈希/字节/行数、关键字段和测试输出。
- verifier 报告若早于依赖产物落地，其“缺失”结论属于时间点事实；依赖补齐后重新复审，不沿用旧 FAIL。
- 同一 SKILL.md 保持单写者，research、test-engineer、asset-auditor、verifier 分别写独立产物。
