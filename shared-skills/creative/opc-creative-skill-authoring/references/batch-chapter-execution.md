# 整卷批量章节改编执行模式（2026-09-08《十二时辰》17 章实战）

场景：用户把整卷/整本书的多章小说一次性改为剧本（每章=一个独立剧本包，不合并）。

## 组织方式

- **每章 = 一次独立节点调用**：源文是单章 md（如 `十二时辰_第一卷_01.md`），产物单章剧本包。
- **产物目录**：源文旁的 `<书名>_剧本/` 文件夹，命名 `第X卷_XX_剧本包.md`（与源文卷章号一致）。
- **并行**：delegate_task 并行上限 10；17 章实测分 9+6+1（两批全并行，断档单章单独补）。
- **style_id 必须逐任务下发**（同一画风批量时每个子任务 context 都写死 style_id=3d_animated_film + 锁风描述），剧本包头写入供下游继承。
- 每任务 output_schema：`{gates, score_44, output_path, screenplay_text}`，要求正文返回（不是只给路径）——子代理总结被截断时正文已在返回流里，便于核对。

## 单章成本基线（flash 子代理实测）

| 指标 | 数值 |
|------|------|
| 源文大小 | 3–8 KB/章 |
| 剧本包大小 | 18–28 KB（1.8万–2.8万字） |
| 单章耗时 | 10–20 分钟（api_calls 6–23） |
| 自评 | 41–43/44（首章对照回归验收表可达 43/44，其余 41/42） |

## 断点恢复（402/429/iteration cap 实战）

1. **先 `ls` 产物目录对比目标清单，不整体重跑**——API 余额断（HTTP 402 Insufficient Balance / 429 并发限额）时**多数产物已落盘**：子代理先写文件、后写总结，被打断的只是总结/自评段。09-08 实测 9 章批次 402 中断后 8 章文件已完整，只有 1 章没写。
2. 只补**缺失章**（单章重派，任务描述同前）。
3. 清理残留：子代理可能把中间文件留在产物目录（实测 `_03_json_check.json`、`第二卷_15_剧本包_自评.json`）——产物目录只允许正式剧本包，临时文件须删。
4. 用户充值/恢复后直接重派，无需向用户解释流程细节。

## 批量验收（文本检查）

- 文件级：每章字数 ≥1.8万、标题/卷次对、style_id 标记存在——注意 style_id 在剧本包内是**表格格式** `**style_id** | **`3d_animated_film`**`，别用 `style_id = 3d_animated_film`（带等号）去搜，会误报缺失（09-08 实测误报一次）。
- 断言级（抽查首尾章+关键事实章）：grep 关键剧情词在正文出现。首章《慢下来的时间》类回归断言：不是慢，是停/老槐树/窑子/木簪/寿数/神位/打火机/火柴；跨章连续性查前情锚点（王二半脸老承接、猫神线索、金纹、辰时龙线），卷终章查收束（去原点找逆鳞）。
- 首章有官方回归验收表时严格对照（38/44 释放线），后续章用同一标准抽查，不逐章全文精读。
