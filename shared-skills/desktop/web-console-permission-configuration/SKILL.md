# Web Console Permission Configuration

## 触发条件

用户明确授权直接操作已打开的网页控制台，并需要配置权限、机器人能力、事件订阅或应用发布前准备时使用。用户希望助手主动完成普通点击，不反复要求其切换窗口；但登录、扫码、密码、密钥、2FA 和最终不可逆发布/授权确认仍由用户本人完成。

## 核心流程

1. **定位真实窗口**：先 `list_apps`，再使用真实可识别的进程名（Windows Chrome 常见为 `chrome.exe`）进行 `capture(mode="som")`。不要因为别名不匹配就断言没有窗口。
2. **确认对象**：核对网页标题、应用名称、域名和当前页面，避免误操作用户的个人、银行、邮件或其他敏感标签页。
3. **先取证再点击**：读取页面显示的权限名称、scope ID、访问令牌类型、是否需要审核和当前已选数量。大型目录绝不点击“全部”。
4. **最小权限**：根据实际适配器调用和官方文档建立精确清单，优先用权限 ID 搜索。消息机器人场景应分别核对收消息、发消息、以机器人身份发消息、资源/聊天读取等必要项；不要把通讯录写入、云文档、日历等无关权限混入。
5. **逐项验证**：每次点击后重新 capture；SOM 索引只对最近一次 capture 有效，列表重排后必须重新取索引。比较勾选状态与计数，不能只相信按钮变色。
6. **导入模式谨慎**：若使用批量导入，先查看默认 JSON。删除示例中的无关 scope，检查导入说明和预览列表，再进入下一步。导入通常是“新增申请”，不等于已经生效。
7. **处理焦点问题**：后台输入若被系统拒绝，不要重复发送快捷键或声称成功。优先请用户做一个最小动作（只点击编辑器获得焦点），或在用户明确授权时使用前台投递；绝不代填秘密。
8. **错误回退**：一旦出现已选计数异常、误触权限或页面状态不确定，取消未提交批次，回到干净状态重新开始；不要凭记忆反向猜哪些复选框已选。
9. **区分四个状态**：权限已申请/已开通、机器人能力已启用、事件订阅已配置、应用版本已发布分别记录。任何一个状态都不能替代另外三个。
10. **不可逆动作刹车**：在提交权限、发布版本、管理员审批、授权确认前，先展示即将执行的动作和范围；若页面要求用户确认身份或管理员审批，停下来交给用户。

## 验收清单

- 应用名称与域名核对无误。
- 没有选择“全部”或无关业务权限。
- 关键 scope 的勾选状态和计数已通过新 capture 验证。
- 导入/新增预览只包含预期权限。
- 机器人能力、事件订阅、连接方式和发布状态分别有证据。
- 没有读取、显示或输入 App Secret、密码、令牌、验证码。
- 最终报告明确哪些已完成、哪些仍需用户操作，不能把“配置已保存”说成“端到端已接通”。

## 常见教训

- 页面可能显示“待上线”，这表示还需创建版本并发布，手机端通常不会自动出现未发布的自建应用。
- 飞书权限弹窗的视觉位置和 SOM 索引可能在筛选后改变；每次交互后都必须重新 capture。
- 若默认批量导入内容含 `docx` 等示例权限，必须移除，不可直接恢复默认值。
