## 三、Qwen Image 模型问题排查

### UNET Loader 找不到模型
- `z-image-turbo-fp8-e4m3fn.safetensors` 之前在 `checkpoints/` 而非 `diffusion_models/`
- UNET Loader 只扫描 `diffusion_models/` 和 `unet/`
- 已移到 `D:\SDkecheng\models\diffusion_models\` ✅

### 8-step Lightning LoRA 问题
- Z-Image Turbo 自带 8 步加速，Lightning LoRA 是给非 Turbo 原版用的
- 两个一起用 = 加速套加速 = 可能相互干扰
- **结论：用 Turbo 底模时不要加 Lightning LoRA**

### VAE 加载报错（重要发现）
- `qwen_image_vae.safetensors`（243MB）是 **3D 视频 VAE**，标准 Load VAE 节点加载失败
- `z_image_vae.safetensors`（160MB）是 **标准 2D VAE**，与 Qwen Image 2511 完全兼容
- **Qwen Image 2511 图片工作流必须用 `z_image_vae`，不是 `qwen_image_vae`！**
- 两者 latent channels 都是 16，架构通用

## 八、今日教训

1. **WSL soft link ≠ Windows Junction**：跨文件系统时必须用 Windows 原生的 Junction/mklink
2. **Electron 版 ComfyUI 不暴露 API**：必须用独立 Python 版
3. **Qwen Image Edit 的 img2img 跟 SD 不同**：需要高 denoise（≥0.90）才能实现显著编辑，因为它的 conditioning 机制不同
4. **不要遇到困难就换底模**：凡哥强调核心是 Qwen 2511 Edit，应该深挖它的正确用法而不是换方案
5. **--lowvram 导致极端慢**：RTX 5080 16GB 跑 Z-Image fp8 不需要 --lowvram
