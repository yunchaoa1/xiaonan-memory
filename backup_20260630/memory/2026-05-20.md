## 二、LTX-2.3 工作流深度诊断

### 参数分析（凡哥发了工作流 JSON）
| 参数 | 值 | 评估 |
|------|------|------|
| 底模 | LTX-2.3 22B distilled FP8 | ✅ |
| 采样步数 | 4步 | 🔴 极其激进 |
| 分辨率 | 896×1664 | 🟡 对4步蒸馏压力大 |
| CFG | 1.0 | 🟡 偏低 |
| 蒸馏LoRA | 0.6 | ✅ |
| image_strength | 0.7 | ✅ |

### 🎯 核心发现：4步蒸馏是根因
- 4步蒸馏把100帧跳跃动作压成"起跳→定格最高点→落地"
- 蒸馏模型每步倾向"选一个最佳姿势"然后锁住
- **推荐：6步 sigmas，蒸馏LoRA 降到 0.4，CFG 提高到 1.2**

### 提示词问题（自己写的5段提示词被凡哥指出是前一天写的 😅）
- 第3段6个动作塞进4秒/100帧 → 4步蒸馏处理不了
- 手部密集段太多
- 过渡缺失

### 新分镜方案（6段代替5段）
| 段 | 时长 | 帧数 | 内容 |
|------|------|------|------|
| 1 | 2.5s | 60帧 | 俯拍全景·沉睡 |
| 2 | 3.3s | 80帧 | 苏醒·发现匕首·困惑 |
| 3 | 3.3s | 80帧 | 恍然大悟·坐在床上开始笑 |
| 4 | 4.2s | 100帧 | 跳下床·空中高举匕首大笑【纯动作·无台词】|
| 5 | 4.2s | 100帧 | 落地站稳·喘口气·说台词 |
| 6 | 2.5s | 61帧 | 全息屏浮现·凑近看·震惊定格 |

### 设计原则（凡哥认可）
- **动作先行，台词后置**：跳完站稳再说台词
- **一段一个核心动作**：不给模型压力
- **帧间留白**：相邻关键帧只差1动作+1情绪
- **参考图放段中偏前**：模型知道往哪走但不锁死

### 6张关键帧画面描述
小南给了详细描述（帧1-6），包含画面构图、人物姿态、情绪表情、场景元素、道具位置。凡哥拿去用于 Qwen 2511 编辑模型合成。

## 四、技术踩坑

### OpenClaw 配置
- `config.patch` 不能改受保护路径（models.providers、auth.profiles），需用 CLI `openclaw` 命令
- `openclaw secrets` 用于刷新 API Key
- 杀网关进程会把自己踢下线
- Gateway 重启后自动恢复

### Gemini API
- AI Studio Key 和 Cloud Console API 是两个通道
- 即使 API 已启用、Key 能列模型，也可能不能生成内容
- `openai-gemini` 项目只解决格式转换，不解决 Key 被拒

### 视频分析
- OpenCV 提取关键帧：`cv2.VideoCapture + frame skipping`
- Qwen VL 通过百炼 API 分析视频（base64 编码帧）
