### 4. 🎬 首帧图设计新原则（今天凡哥确立·极其重要）
> **首帧图 ≠ 动作发生中的画面。首帧图 = 每段视频的静态起点，动作交给 LTX prompt 去驱动。**

- ❌ 不要在首帧图提示词里写「嘴唇微张正在说话」「抬起手势」「微微点头」等正在发生的动作
- ✅ 首帧图写「双唇闭合」「双手放在扶手上」「面带微笑注视对方」的静态状态
- 💡 动作描述全部留给 LTX prompt
- ❌ 不要在提示词里写「还没开始说话」「带着刚说完话的余韵微笑」「处于即将开口的前一刻」等内心预想的词——Qwen 2511 理解不了，反而可能出怪东西
- ✅ 提示词就是此时此刻这一帧的样子，不多不少。额外解释放在提示词下方单独写

### 6. 段间衔接逻辑（凡哥今天深讲）
- 三个段落之间存在无缝衔接
- 段1的尾帧 ≈ 段2的首帧图，段2的尾帧 ≈ 段3的首帧图
- 两个说话人切换时太快 → LTX没时间做过渡动作
- **解决方案：TTS音频每段之间加 1 秒静音**（约24帧留给LTX做过渡）
- 首帧图之间的差异只做最小必要的微调（身体微转、表情微变），不跳跃

### 8. 音频合并注意事项（今天踩坑）
- ffmpeg 在 Windows 侧（`D:\tools\ffmpeg\ffmpeg.exe`），WSL 没有
- WSL→Windows路径不互通：ffmpeg 不认识 `/home/...` 路径，Windows 不认识 `/mnt/...`
- **正确流程**：文件先 cp 到 Windows 侧的 `D:\SDkecheng\input\`，再用 Windows ffmpeg 处理
- 合并用 `-c copy` 会导致 FLAC→WAV 容器码流不匹配，播放器卡死 → **必须用 `-c:a pcm_s16le` 重编码**
